モジュールとパッケージの全体像

モジュールパスは github.com/teslamotors/vehicle-command で、go.mod は Go 1.23 を要求します。v0.x リリースは API の安定性を保証しないため、go.mod でバージョンを固定してください。

go get github.com/teslamotors/vehicle-command@v0.4.1
パッケージ役割主要シンボル
pkg/protocol鍵の読み込み、ドメイン定数、エラー型。サブディレクトリ protobuf/* に生成された protobuf バインディング。LoadPrivateKey, LoadPublicKey, ECDHPrivateKey, DomainVCSEC, DomainInfotainment, Error, MayHaveSucceeded, ShouldRetry
pkg/connectorトランスポート層のインターフェース定義。Connector, FleetAPIConnector, AuthMethodNone/GCM/HMAC, BufferSize, MaxResponseLength
pkg/connector/bleBLE トランスポートの実装 (go-ble ベース)。macOS、Linux に対応。Windows はビルドはできるが実行時エラー。InitAdapterWithID, ScanVehicleBeacon, NewConnection, NewConnectionFromScanResult, VehicleLocalName, CloseAdapter
pkg/connector/inetFleet API(HTTPS) トランスポートの実装。NewConnection, SendFleetAPICommand, HTTPError, ErrVehicleNotAwake, MaxLatency
pkg/vehicle車両コマンド API。ドメインのルーティング、セッション、リトライを包んだ高水準メソッド。Vehicle, NewVehicle, StateCategory*, SeatPosition, Level, ChargingPolicy
pkg/cacheセッション状態のキャッシュ(JSON シリアライズ)。SessionCache, New, ImportFromFile, ExportToFile
pkg/cli共通のフラグ/環境変数/キーリング処理。CLI ツールを作るときに使用。Config, NewConfig, Flag*, DomainList, Env* 定数
pkg/accountTesla アカウント(OAuth トークン)のラッパー。Fleet API ドメインの決定、GetVehicle。Account, New, GetVehicle, Get, Post, UpdateKey
pkg/proxyREST → エンドツーエンド認証コマンドへの変換サーバー。http.Handler を実装。Proxy, New, ExtractCommandAction, ErrCommandUseRESTAPI
pkg/signFleet Telemetry の設定などに使う JWS(Schnorr/P256) 署名。SignMessageForVehicle, SignMessageForFleet
internal/ パッケージはインポートできません

internal/authentication(ECDH、署名、検証)、internal/dispatcher(セッション/ルーティング)、internal/log、internal/schnorr は Go の internal ルールにより外部モジュールからインポートできません。必要な機能は pkg/protocol(鍵の型の再公開)、pkg/vehicle(セッション管理)、pkg/cache(キャッシュエントリ)を通じて使います。

基本フロー: BLE でアンロック

リポジトリの examples/ble/main.go を要約した最小限のプログラムです。呼び出し順序と defer の順序が重要です。

package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/teslamotors/vehicle-command/pkg/connector/ble"
    "github.com/teslamotors/vehicle-command/pkg/protocol"
    "github.com/teslamotors/vehicle-command/pkg/vehicle"
)

func main() {
    vin := "5YJ30123456789ABC"

    // 1. BLE アダプターの初期化。空文字列ならデフォルトアダプター。"hci0" のような ID 指定は Linux のみ可能。
    if err := ble.InitAdapterWithID(""); err != nil {
        if ble.IsAdapterError(err) {
            log.Fatal(ble.AdapterErrorHelpMessage(err)) // Linux: setcap の案内を出力
        }
        log.Fatalf("BLE アダプターの初期化に失敗: %s", err)
    }

    // 2. 秘密鍵の読み込み (PEM, NIST P-256)。nil でもよいが、認証が必要なコマンドは失敗する。
    privateKey, err := protocol.LoadPrivateKey("private.pem")
    if err != nil {
        log.Fatalf("秘密鍵の読み込みに失敗: %s", err)
    }

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    // 3. アドバタイズのスキャン。VIN から計算した Local Name("S...C")と一致するビーコンを探す。
    scan, err := ble.ScanVehicleBeacon(ctx, vin)
    if err != nil {
        log.Fatalf("スキャンに失敗: %s", err)
    }
    fmt.Printf("検出: %s (%s) %ddBm\n", scan.LocalName, scan.Address, scan.RSSI)

    // 4. GATT 接続。target が nil なら内部で再度スキャンする。
    conn, err := ble.NewConnectionFromScanResult(ctx, vin, scan)
    if err != nil {
        log.Fatalf("接続に失敗: %s", err)
    }
    defer conn.Close() // (b) 2 番目に実行

    // 5. Vehicle オブジェクトの生成。3 番目の引数はセッションキャッシュ(なければ nil)。
    car, err := vehicle.NewVehicle(conn, privateKey, nil)
    if err != nil {
        log.Fatal(err)
    }

    // 6. 受信ゴルーチンの開始。
    if err := car.Connect(ctx); err != nil {
        log.Fatalf("Connect に失敗: %s", err)
    }
    defer car.Disconnect() // (a) 最初に実行。必ず conn.Close() より先に。

    // 7. ドメインごとのハンドシェイク。nil なら VCSEC と INFOTAINMENT の両方。
    if err := car.StartSession(ctx, nil); err != nil {
        log.Fatalf("ハンドシェイクに失敗: %s", err)
    }

    // 8. コマンドの送信。各コマンドはコンテキストの期限まで自動でリトライする。
    if err := car.Unlock(ctx); err != nil {
        log.Fatalf("アンロックに失敗: %s", err)
    }
    if err := car.ClimateOn(ctx); err != nil {
        log.Fatalf("空調のオンに失敗: %s", err)
    }
    fmt.Println("完了")
}
  1. アダプターの初期化はプロセスごとに 1 回。 ble.InitAdapterWithID はグローバルな ble.Device を作成し、以降は ScanVehicleBeacon/NewConnection がそれを再利用します。明示的に呼ばない場合は、最初のスキャン/接続時にデフォルトアダプターで自動的に初期化されます。Linux では newDevice() を複数回呼ぶと失敗するため、内部のミューテックスで保護されています。アダプターを切り替えるには ble.CloseAdapter() のあとで再初期化します。
  2. defer の順序。 Vehicle.Disconnect() はディスパッチャーのゴルーチンを停止したあと、内部で conn.Close() を呼び出します。Connector.Close() は冪等でなければならないので両方を defer しても構いませんが、Disconnect が先に実行される必要があります(defer は逆順に実行されるため、defer conn.Close() を先に、defer car.Disconnect() を後に書きます)。
  3. コンテキストはコマンドごとに新しく作るのが望ましいです。 例では簡略化のため 30 秒のものを 1 つ共有していますが、tesla-control は接続に 20 秒、コマンドごとに 5 秒を個別に与えます。セッションにおけるコマンドの有効期限(expires_at)もコンテキストのデッドラインから計算されます(デッドラインがなければ 5 秒)。
  4. リトライは SDK が行います。 Vehicle.Send、StartSession、VCSEC コマンドのループは、protocol.ShouldRetry(err) が真となるエラー(一時的で、かつ成功した可能性がないエラー)を、RetryInterval()(BLE 1 秒)の間隔でコンテキストが終了するまでリトライします。

秘密鍵と公開鍵の扱い

関数説明
protocol.LoadPrivateKey(filename) (ECDHPrivateKey, error)P-256 EC 秘密鍵ファイルを読み込みます。PEM 形式(EC PRIVATE KEY、PKCS#8 PRIVATE KEY)に対応しています。他の曲線や RSA 鍵は拒否されます。
protocol.SavePrivateKey(skey, filename) errorネイティブ鍵を SEC1 PEM(EC PRIVATE KEY)として 0600 の権限で保存します。HSM ベースの鍵のようにエクスポートできない実装の場合は key is not exportable エラー。
protocol.LoadPublicKey(filename) (*ecdh.PublicKey, error)公開鍵を柔軟に読み込みます。対応形式: PKIX PEM(PUBLIC KEY)、暗号化されていない PKCS#8 PEM(PRIVATE KEY、秘密鍵ファイルから公開鍵を抽出)、SEC1 PEM(EC PRIVATE KEY)、バイナリの非圧縮曲線点(65 バイト、0x04 で始まる)、16 進文字列の非圧縮曲線点(130 文字、末尾の改行を許容)。曲線が P-256 でなければ ErrInvalidPublicKey。
protocol.PublicKeyBytesFromHex(h) (*ecdh.PublicKey, error)16 進文字列を検証して ecdh.PublicKey に変換します。
protocol.UnmarshalECDHPrivateKey(keyBytes) ECDHPrivateKey32 バイトのスカラー(ビッグエンディアン)から秘密鍵を復元します。キーリングに保存される形式はこれです。失敗すると nil。
ECDHPrivateKey.PublicBytes() []byte非圧縮エンコードの公開鍵(65 バイト)。ハンドシェイクと signer_identity.public_key にそのまま入ります。

OpenSSL で鍵ペアを作る方法(tesla-keygen の代わりにファイルベースの鍵を使いたい場合):

openssl ecparam -genkey -name prime256v1 -noout > private.pem
openssl ec -in private.pem -pubout > public.pem
protocol.md のテスト鍵を実際の車両に登録しないでください

pkg/protocol/protocol.md にある client.key/vehicle.key はテストベクター検証用に公開されている鍵です。車両に登録すると、誰でもコマンドを送れるようになります。

Vehicle 型の主要メソッド

メソッド説明
vehicle.NewVehicle(conn connector.Connector, privateKey ECDHPrivateKey, sessionCache *cache.SessionCache) (*Vehicle, error)Vehicle を作成します。privateKey と sessionCache は nil でも可。キャッシュにこの VIN のエントリがあれば即座に読み込みます。認証方式は conn.PreferredAuthMethod() で決まります(BLE: AES-GCM、inet: HMAC)。Flags は DefaultFlags(FLAG_ENCRYPT_RESPONSE ビット)で初期化されます。
Connect(ctx) errorディスパッチャーの受信ゴルーチンを開始します。準備が整う前に ctx が期限切れになるとエラー。
StartSession(ctx, domains []universal.Domain) error指定したドメインとハンドシェイクします。nil なら VCSEC と INFOTAINMENT の両方を並列に実行。鍵がペアリングされていなければ protocol.ErrKeyNotPaired。一時的なエラーは自動でリトライ。キャッシュからすでに読み込まれたドメインはハンドシェイクを省略します。
Disconnect()ディスパッチャーを停止し、conn.Close() を呼び出します。
Wakeup(ctx) errorコネクターが FleetAPIConnector であれば、Fleet API の wake_up エンドポイントを state == "online" になるまで 10 秒間隔でポーリングします。BLE であれば VCSEC に RKE_ACTION_WAKE_VEHICLE を送ります(認証が必要)。
Send(ctx, domain, payload []byte, auth connector.AuthMethod) ([]byte, error)低水準: 任意のペイロードをドメインに送り、レスポンスのペイロードを返します。リトライ込み。新しいコマンドを試すときに使用。
SendMessage(ctx, message *universal.RoutableMessage) (protocol.Receiver, error)さらに低水準: 構築済みの RoutableMessage を認証なしで送信します。別の主体が署名したメッセージを中継するとき(カードなしの鍵ペアリングなど)に使用。返された Receiver は使用後に Close()。
SessionInfo(ctx, publicKey *ecdh.PublicKey, domain) (*signatures.SessionInfo, error)任意の公開鍵でハンドシェイクリクエストを送り、SessionInfo を受け取ります。認証不要。鍵が登録されているかを確認する用途(tesla-control session-info)。
SetMaxLatency(d time.Duration)セッション情報のレスポンスがリクエスト後この時間より遅れて届いた場合、時計の同期に使わずに破棄します。デフォルトはコネクターの AllowedLatency()(BLE 4 秒、inet 10 秒)。
Flags uint32 (フィールド)すべてのリクエストの RoutableMessage.flags。デフォルトは 1 << FLAG_ENCRYPT_RESPONSE。2024.38+ のファームウェアはレスポンスを暗号化し、古いファームウェアは無視します。
PrivateKeyAvailable() bool, VIN() string状態の照会。
UpdateCachedSessions(c *cache.SessionCache) error / LoadCachedSessions(c) error現在のセッション状態をキャッシュに書き込む、またはキャッシュから読み込みます。

ドメインの選択と Infotainment を起こさない方法

VCSEC のコマンド(ロック、トランク、ウェイク、鍵管理、BodyControllerState)だけを使う場合は、INFOTAINMENT とハンドシェイクする必要はありません。INFOTAINMENT とのハンドシェイクはスリープ中のインフォテインメントを起こし、時間がかかります。

import universal "github.com/teslamotors/vehicle-command/pkg/protocol/protobuf/universalmessage"

// VCSEC のみハンドシェイク
if err := car.StartSession(ctx, []universal.Domain{protocol.DomainVCSEC}); err != nil { ... }
if err := car.Lock(ctx); err != nil { ... }

tesla-control は、-domain vcsec フラグ(繰り返し指定可)、body-controller-state コマンドでの domain: protocol.DomainVCSEC の指定、そして -ble wake のときに VCSEC だけとハンドシェイクする特別な処理によって、同じことを行います。

INFOTAINMENT セッションなしで Infotainment コマンドを送ると

protocol.ErrNoSession(cannot send authenticated command before establishing a vehicle session)が即座に返されます。tesla-control はこのエラーを「You must provide a private key…」として案内します。

セッションキャッシュ

ハンドシェイクは往復を 1 回追加し、Fleet API ではリクエスト数を増やします。pkg/cache でセッション状態(ドメインごとの SessionInfo と生成時刻)をディスクに保存すると、次回の実行時に最初のコマンドをすぐに送れます。キャッシュが古い場合は、最初のコマンドが失敗すると同時に車両が最新のセッション情報を送ってくるため、SDK が自動で更新してリトライします。つまり、古いキャッシュを使っても損はありません。

const cacheFile = "/var/lib/myapp/tesla-cache.json"

myCache, err := cache.ImportFromFile(cacheFile)
if err != nil {
    myCache = cache.New(5) // 最大 5 台分。0 なら無制限。LRU で追い出し。
}

car, err := vehicle.NewVehicle(conn, privateKey, myCache) // 生成時にキャッシュから読み込む
...
defer func() {
    if err := car.UpdateCachedSessions(myCache); err != nil { log.Println(err) }
    if err := myCache.ExportToFile(cacheFile); err != nil { log.Println(err) }
}()
  • キャッシュはクライアントの秘密鍵に紐づきます。 別の鍵でキャッシュを使うと最初の認証が失敗し、車両が新しいセッション情報を送ってくることで正常に復旧します。
  • 複数の VIN を 1 つのキャッシュに入れても構いません。 SessionCache.Vehicles は VIN → ドメインごとのエントリのマップです。
  • ファイルのアクセス制御を行ってください。 キャッシュには車両の公開鍵、epoch、カウンター、時計のオフセットが入っています。秘密鍵は含まれませんが、第三者に読まれたり改ざんされたりしないようにする必要があります。ExportToFile は 0644 で作成するので、必要に応じて権限を絞ってください。
  • tesla-control とプロキシは、それぞれ TESLA_CACHE_FILE(デフォルト ~/.tesla-cache.json)とメモリ内キャッシュ(最大 10000 台)を使用します。
  • SessionCache.Update/GetEntry は内部のディスパッチャー用なので、Vehicle.UpdateCachedSessions を使う方がよいでしょう。

pkg/cli で CLI アプリケーションを作る

pkg/cli.Config は、5 つの CLI ツールが共有するフラグ/環境変数/キーリングのロジックを提供します。独自の CLI を作るときにそのまま再利用できます。

import (
    "flag"
    "github.com/teslamotors/vehicle-command/pkg/cli"
)

config, err := cli.NewConfig(cli.FlagAll) // FlagVIN | FlagOAuth | FlagPrivateKey | FlagBLE
if err != nil { panic(err) }
config.RegisterCommandLineFlags()   // -vin, -key-name, -key-file, -token-name, -token-file, -session-cache, -domain, -keyring-type ...
flag.Parse()
config.ReadFromEnvironment()        // 空の値だけを TESLA_* 環境変数で埋める
if err := config.LoadCredentials(); err != nil { ... } // キーリングのパスワードプロンプトをタイムアウト前に処理

ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()
acct, car, err := config.Connect(ctx) // OAuth があればインターネット、なければ BLE。Connect + StartSession(config.Domains) まで実行
if err != nil { ... }
if car != nil {
    defer car.Disconnect()
    defer config.UpdateCachedSessions(car) // キャッシュファイルを更新
}
Flag マスク登録されるオプション
FlagVIN-vin / TESLA_VIN
FlagPrivateKey-key-name, -key-file, -session-cache, -disable-session-cache, -domain / TESLA_KEY_NAME, TESLA_KEY_FILE, TESLA_CACHE_FILE
FlagOAuth-token-name, -token-file / TESLA_TOKEN_NAME, TESLA_TOKEN_FILE
FlagOAuth または FlagPrivateKey-keyring-type, -keyring-file-dir, -keyring-debug / TESLA_KEYRING_TYPE, TESLA_KEYRING_PASSWORD, TESLA_KEYRING_PATH, TESLA_KEYRING_DEBUG
FlagBLE (Linux)-bt-adapter
  • config.Connect のトランスポート選択: FlagOAuth が有効でトークン名/ファイルがあれば ConnectRemote、そうでなく FlagBLE|FlagVIN であれば ConnectLocal、どちらでもなければ ErrNoAvailableTransports。
  • ConnectLocal(ctx, skey) は ble.InitAdapterWithID(c.BtAdapterID) → ble.NewConnection → vehicle.NewVehicle(conn, skey, c.sessions) だけを行い、Connect/StartSession は呼び出しません。Connect はその 2 つまで行います。
  • config.Domains(cli.DomainList)を設定すると、Connect はそのドメインだけとハンドシェイクします。
  • config.PrivateKey() はファイルが優先で、なければキーリング。最初の読み込み時にキャッシュファイルも一緒に読みます。

インターネット経路: pkg/account

acct, err := account.New(oauthToken, "myapp/1.0.0") // userAgent が "" ならビルド情報から生成
if err != nil { ... }
car, err := acct.GetVehicle(ctx, vin, privateKey, sessionCache) // inet.Connection を生成
if err != nil { ... }
if err := car.Connect(ctx); err != nil { ... }
defer car.Disconnect()
if err := car.Wakeup(ctx); err != nil { ... }          // Fleet API wake_up のポーリング (任意)
if err := car.StartSession(ctx, nil); err != nil { ... }
if err := car.Unlock(ctx); err != nil { ... }
  • account.New は JWT を署名検証なしでデコードし、aud と ou_code から Fleet API のホストを選びます。デフォルトは fleet-api.prd.na.vn.cloud.tesla.com。サーバーが 421 と use base URL: https://… という本文を返すと、inet.Connection がホストを更新します。
  • インターネット経路は HMAC-SHA256 認証(平文)を使います。Fleet API が OAuth スコープを検査する必要があるためです。AES-GCM で暗号化されたコマンドは Fleet API が拒否します。
  • Account.Get(ctx, "api/1/products")、Post、SendVehicleFleetAPICommand(ctx, vin, "vehicle_data", nil) で一般的な Fleet API 呼び出しもできます。
  • Account.UpdateKey(ctx, publicKey, name) は api/1/users/keys に鍵のメタデータ(表示名)を登録します。車両の Locks 画面に表示されます。
  • BLE 専用コマンド(SendAddKeyRequest)はインターネット経路では protocol.ErrRequiresBLE。逆に SetPINToDrive はインターネット経路でのみ許可されます(protocol.ErrRequiresEncryption。BLE では認証されていない公開鍵に PIN が露出するおそれがあるためブロックしている)。

エラー処理のパターン

SDK のエラーは可能な限り protocol.Error インターフェースを実装しています。2 つのメソッドがリトライとユーザーへの案内を決定します。

err := car.Unlock(ctx)
switch {
case err == nil:
    // 成功
case protocol.MayHaveSucceeded(err):
    // コマンドは届いた可能性があるが確認が取れていない (例: タイムアウト)。再送すると 2 回実行される可能性があるので、状態を照会して判断。
case errors.Is(err, protocol.ErrKeyNotPaired):
    // 公開鍵が車両に登録されていない。ペアリングを案内。
case errors.Is(err, protocol.ErrNoSession):
    // StartSession を行っていないか、該当ドメインを除いて行った。
case protocol.IsNominalError(err):
    // 車両はコマンドを認証したが実行できない (例: パーキング状態でない、すでにオン)。ユーザーに理由を表示。
case protocol.Temporary(err):
    // 一時的なエラー。SDK がすでにコンテキストの期限までリトライしたので、コンテキストを延ばして再試行。
default:
    // その他
}
ヘルパー意味
protocol.MayHaveSucceeded(err)車両がコマンドを実行した可能性がある。コンテキストのタイムアウト、レスポンスのパース失敗、HTTP 5xx(503 を除く)など。
protocol.Temporary(err)ユーザーの介入なしにリトライで解決できる可能性がある。ErrBusy、MESSAGEFAULT_ERROR_BUSY/TIMEOUT/INVALID_SIGNATURE/INVALID_TOKEN_OR_COUNTER/INTERNAL/INCORRECT_EPOCH/TIME_EXPIRED/TIME_TO_LIVE_TOO_LONG、HTTP 503/504/408/421。
protocol.ShouldRetry(err)Temporary であり、かつ MayHaveSucceeded でない場合のみ真。SDK 内部のリトライループの基準。
protocol.IsNominalError(err)アプリケーション層での拒否(NominalError)。プロキシはこれを HTTP 200 + reason として返します。
errors.As(err, &*protocol.RoutableMessageError)プロトコル層のエラー。.Code で MessageFault_E を確認。
errors.As(err, &*protocol.KeychainError)鍵の追加/削除の失敗。.Code は WhitelistOperation_information_E。

エラーコードの一覧とシナリオ別の対処は 9. エラーとトラブルシューティング を参照してください。

カスタム Connector の実装

別の BLE スタック(例: TinyGo、モバイルブリッジ、シリアルゲートウェイ)やテスト用のモックトランスポートをつなぐには、connector.Connector を実装して vehicle.NewVehicle に渡せば済みます。ディスパッチャーはコネクターを純粋なデータグラムの通り道としてのみ扱います。

type Connector interface {
    Receive() <-chan []byte                     // 車両が送った RoutableMessage のバイト列。スレッドセーフ。
    Send(ctx context.Context, buffer []byte) error // RoutableMessage のバイト列を送信。スレッドセーフ。
    VIN() string
    Close()                                     // 複数回呼んでも安全でなければならない
    PreferredAuthMethod() AuthMethod            // BLE: AuthMethodGCM, HTTP: AuthMethodHMAC
    RetryInterval() time.Duration               // 再送間隔 (BLE/inet とも 1 秒)
    AllowedLatency() time.Duration              // セッション情報レスポンスの最大許容遅延 (BLE 4 秒, inet 10 秒)
}

type FleetAPIConnector interface {             // インターネットコネクターのみ追加で実装
    Connector
    SendFleetAPICommand(ctx context.Context, endpoint string, command interface{}) ([]byte, error)
    Wakeup(ctx context.Context) error
}
  • Receive() チャネルのバッファは connector.BufferSize(5) 程度を推奨します。BLE 実装は 5、inet も 5 を使います。満杯になると、BLE はチャンクを捨て、inet は dropped response because inbox is full エラーを出します。
  • Send が返すエラーが protocol.Error を実装していれば、ディスパッチャーは ShouldRetry で再送を判断します。一般的なエラーは終端エラーとして扱われます。
  • レスポンスは connector.MaxResponseLength(100000 バイト)までサポートする必要があります。BLE 実装はメッセージあたり 1024 バイト(maxBLEMessageSize)に制限しています。
  • BLE の場合、2 バイトのビッグエンディアン長プレフィックスによるフレーミングと MTU 分割をコネクター内で処理する必要があります。ディスパッチャーはフレーミングを知りません。
  • セッション情報のレスポンスが AllowedLatency より遅れて届くと時計同期用としては破棄されるため、遅延の大きいトランスポートでは値を増やすか、Vehicle.SetMaxLatency で調整してください。
  • FleetAPIConnector を実装すると、Vehicle.Wakeup がそれを使い、SetPINToDrive が許可され、SendAddKeyRequest は拒否されます。

HSM/TEE 統合時の注意

protocol.ECDHPrivateKey はインターフェースであり、protocol.Session が再公開されているため、外部モジュールからも実装できます(pkg/protocol/external_impl_test.go が例)。秘密鍵を Nitro Enclave、KMS、ハードウェア HSM に置くには、Exchange(remotePublicBytes) (Session, error)、PublicBytes()、SchnorrSignature(message) を TEE 呼び出しにプロキシする型を作ります。pkg/protocol/key.go のコメントが求める条件:

  • TEE は ECDH の共有秘密をエクスポートする API を公開してはなりません。
  • TEE は ECDH 由来の鍵で動作する汎用 AES インターフェースを公開してはなりません(ホストが完全性鍵を計算できてしまう)。
  • TEE はホストが nonce を指定する AES-GCM 暗号化インターフェースを公開してはなりません。
  • Session オブジェクトには導出された秘密を入れず、TEE のハンドルだけを入れます。

これらの条件を満たせなくても、ホストが侵害されたときに漏洩するのは既知の車両公開鍵に対する長期共有秘密だけである、という点で依然として価値がある場合があります。ファイルベースの保存を使う場合は、SavePrivateKey が 0600 で保存する点と、キーリングのオプション(キーリング)を活用してください。

ロギング、ビルド、テスト

  • ロギング。 SDK は internal/log で stderr に [debug]/[info ]/[warn ]/[error] を出力します。外部モジュールはレベルを直接変更できないため、CLI ツールの -debug/-verbose または環境変数 TESLA_VERBOSE(tesla-control、tesla-http-proxy)を使います。独自アプリケーションでデバッグログが必要な場合は、リポジトリをフォークするか、examples/ble のようにリポジトリ内のプログラムとしてビルドする必要があります(examples/ble/main.go は internal/log をインポートできるリポジトリ内部のコードです)。
  • デバッグ出力の読み方。 TX: 32020802…/RX: … は RoutableMessage の 16 進表記です。protoc --decode=UniversalMessage.RoutableMessage -I pkg/protocol/protobuf pkg/protocol/protobuf/*.proto でデコードします(手順)。
  • ビルド。 go build ./...、go install ./cmd/...(= make install)。BLE パッケージは macOS では cbgo(CoreBluetooth)、Linux では HCI ソケットを使うため、cgo/権限の要件が異なります。Docker イメージは distroless ランタイムに 5 つのツールをすべて含み、デフォルトのエントリーポイントは tesla-http-proxy です。
  • テスト/リント。 ./check-all.sh は go build、go test ./...、go vet、go fmt による変更の有無、shellcheck を順に実行します。make test は go test -cover ./... と go vet。CI は make format 後に diff がないこと、golangci-lint v1.61.0(.golangci.yml: errcheck, gofmt, gosimple, govet, misspell, revive, unused)、make test を Go 1.23.0 で実行します。
  • protobuf の再生成。 make proto-gen は protoc --go_out で pkg/protocol/protobuf/*.pb.go を再生成します。.proto を変更したら必ず再生成してコミットします。
  • モックテスト。 pkg/vehicle/vehicle_mock_test.go と pkg/proxy/proxy_test.go がコネクター/車両をモックする方法を参考にしてください。プロキシは httpDoer、vehicleSession インターフェースと fetchVehicle フィールドによって、テストで差し替えられるようになっています。
