15. Commands

A Vehicle can start and end sessions, send the twelve security-controller commands (locks, trunks, wake-up) and send the 31 infotainment commands for climate and charging. The rest of the infotainment commands (windows, horn, media and more) arrive later in M5. This page lists all of them. Reading infotainment state with getState() is available too: see 14. Reading Vehicle State.

Available today

CallWhat it does
startSession(domains, timeout)Runs the handshake for VCSEC and Infotainment (both by default) in parallel. A domain already restored from the session cache succeeds without asking the car. Needs a key that is enrolled. If the phone lock blocks the key (an iOS Secure Enclave key that only works unlocked), it fails as soon as the car answers with KeyStoreError.Locked and is not retried (13). Default timeout 20 seconds
disconnect()Saves the session cache, erases session keys and closes the link. Safe to call more than once

While startSession runs, vehicle.sessions shows Handshaking; afterwards Ready, or None again if it failed or was cancelled.

How every command behaves

  • Commands are encrypted and authenticated with AES-GCM over the domain's session and expire after 5 seconds.
  • No command starts a session or wakes the car. Without a session for its part of the car, a command returns Failure(NoSession) and sends nothing.
  • Temporary failures are retried every second automatically. A command that may already have run is never sent again.
  • When a Bluetooth write fails and the library writes the same bytes again, the command is never signed again: an error that would mean a retry, or a refusal of the message itself (for example KeyNotPaired), is not taken as the result, and the call returns Uncertain(Timeout) unless an answer that settles it arrives in time (the late answer to the first copy, or the repeated copy's success when the first never arrived). See 16. Error Handling.
  • Security-controller commands run one at a time per connection; infotainment commands may run side by side.
  • An Uncertain result means: read the state, do not resend. See 16. Error Handling.

Security controller (M4)

All twelve methods are authenticated and need a VCSEC session; without one they return Failure(NoSession), so run startSession(setOf(VehicleDomain.VCSEC)) first. Each takes an optional timeout (default 5 seconds) and returns VehicleResult<Unit>.

  • Likely failures: NoSession, NotConnected, InsufficientPrivileges (for example a Vehicle Monitor key, or the car state forbids it), VcsecRejected, UnknownVcsecError.
  • Uncertain means the car may have acted, also when a write failed and the library wrote the same bytes again. Do not resend; read vehicleStatus() for the lock state and closures. This matters most for the toggles openTrunk() and actuateTrunk(). See 16. Error Handling.
  • sessions follows the real session state. When a command ends with NoSession, or a session event arrives, the library re-checks that domain. A cached session the car no longer accepts (for example the cache belonged to another key) shows None after the first command fails; startSession recovers it.

Climate and charging (M5)

All 31 methods are authenticated over the infotainment session, take an optional timeout (default 5 seconds) and return VehicleResult<Unit>. The car's answer to a success carries nothing the app needs, as in the Go original. The commands are checked with automated tests against a simulated car; none has been checked on a real car yet (#118).

Before you send

  1. Start an infotainment session: startSession(setOf(VehicleDomain.INFOTAINMENT)), or both domains. Without it, a command returns Failure(NoSession) and sends nothing.
  2. Make sure the car is awake. The library does not wake it: if infotainment is asleep, the command goes out, nothing comes back, and the result is Uncertain(Timeout). Read vehicleStatus() first (no session needed, it never wakes the car). If it says ASLEEP, wake the car as in 14, A8.2 (VCSEC session, wakeUp(), wait for AWAKE) and start the infotainment session.
  3. Send the command and look at the result:
ResultMeaningWhat your app does
SuccessThe car accepted the commandTo show the new state, read it with getState (After Uncertain)
UncertainThe car may have done it: no answer in time (infotainment asleep, answer lost), a failed write the library repeated, or an unreadable answerNever send it again. Read the state with getState and decide from what it shows. Low power mode and accessory power cannot be read back
Failure(InvalidArgument)A check before sending failed, and nothing was sentFix the argument (next section)
Failure(InfotainmentRejected)The car refusedShow a generic message. reason is the car's own text; do not log it
NoSession, NotConnected, other errorsCalled in the wrong order, or the link is goneSee 16. Error Handling

Checks before sending

The library checks only what the Go original checks. The checks run before the session check, so a bad argument is reported as InvalidArgument even without a session, and nothing is sent.

MethodRuleMessage (detail)
setSeatCoolerFront seats only: FRONT_LEFT or FRONT_RIGHTinvalid seat position for seat cooler: <SEAT>
scheduleDepartureThe departure time is 0 to 1440 minutes after midnight, both ends includedinvalid departure time: <n> minutes after midnight (expected 0..1440)

Everything else goes to the car as given, and the car decides: temperatures, charge limit, current, the other times and the schedule fields. autoSeatAndClimate quietly leaves out the seats the Go original does not handle.

After Uncertain

Never resend: read the state the command changes. The field names come from the official protocol definitions; which field a command changes on a real car is not confirmed yet (#118). The read itself can come back Uncertain (infotainment asleep, answer too large); then the command's result stays unknown until a later read succeeds.

Kotlin example

import com.tesla.generated.carserver.common.ChargeSchedule
import dev.mirolab.teslable.Vehicle
import dev.mirolab.teslable.model.ChargingPolicy
import dev.mirolab.teslable.model.SeatClimateLevel
import dev.mirolab.teslable.model.SeatPosition
import dev.mirolab.teslable.model.StateCategory
import dev.mirolab.teslable.model.VehicleError
import dev.mirolab.teslable.model.VehicleResult

// Before: an INFOTAINMENT session (startSession) and an awake vehicle (14-lib-reading-state.md A8.2).
suspend fun warmUp(vehicle: Vehicle): String {
    when (val result = vehicle.climateOn()) {
        is VehicleResult.Success -> Unit
        is VehicleResult.Uncertain -> {
            // The vehicle may have turned climate on. Never resend: read the state.
            val state = vehicle.getState(StateCategory.CLIMATE)
            val on = (state as? VehicleResult.Success)?.value?.climate_state?.is_climate_on
            return if (on == true) "climate on" else "unknown, read again later"
        }
        is VehicleResult.Failure -> return "not sent or refused: ${result.error.message}"
    }
    // Handle these results the same way.
    vehicle.setClimateTemp(driverCelsius = 22.0f, passengerCelsius = 21.5f)
    vehicle.setSeatHeater(mapOf(SeatPosition.FRONT_LEFT to SeatClimateLevel.HIGH, SeatPosition.FRONT_RIGHT to SeatClimateLevel.LOW))
    return "climate on"
}

suspend fun planCharging(vehicle: Vehicle, scheduleId: Long, latitude: Float, longitude: Float) {
    vehicle.setChargeLimit(80)
    // Leave at 08:00, off-peak charging ends at 06:00 (minutes after the vehicle's local midnight).
    val departure = vehicle.scheduleDeparture(480, 360, ChargingPolicy.ALL_DAYS, ChargingPolicy.WEEKDAYS)
    if (departure is VehicleResult.Failure && departure.error is VehicleError.InvalidArgument) {
        return // departAtMinutes outside 0..1440; nothing was sent
    }
    val schedule =
        ChargeSchedule(
            id = scheduleId, // the Go CLI uses the current Unix time
            name = "Home",
            days_of_week = 127, // every day
            start_enabled = true,
            start_time = 120, // 02:00
            enabled = true,
            latitude = latitude,
            longitude = longitude,
        )
    vehicle.addChargeSchedule(schedule)
}

Swift example

Swift passes every argument, including timeout:. Schedules are built with every field plus unknownFields; the details are in 17. Platform Notes. This form passes a Swift typecheck against the framework; it has not run in a Swift program.

func warmUp(vehicle: Vehicle) async throws -> String {
    let result = try await vehicle.climateOn(timeout: nil)
    switch onEnum(of: result) {
    case .success:
        break
    case .uncertain:
        // The vehicle may have turned climate on. Never resend: read the state.
        let state = try await vehicle.getState(category: .climate, timeout: nil)
        if case .success(let s) = onEnum(of: state), let data = s.value as? VehicleData,
           data.climate_state?.is_climate_on?.boolValue == true {
            return "climate on"
        }
        return "unknown, read again later"
    case .failure(let f):
        return "not sent or refused: \(f.error.message)"
    }
    _ = try await vehicle.setClimateTemp(driverCelsius: 22.0, passengerCelsius: 21.5, timeout: nil)
    _ = try await vehicle.setSeatHeater(levels: [.frontLeft: .high, .frontRight: .low], timeout: nil)
    return "climate on"
}

func planCharging(vehicle: Vehicle, scheduleId: Int64, latitude: Float, longitude: Float) async throws {
    _ = try await vehicle.setChargeLimit(percent: 80, timeout: nil)
    let departure = try await vehicle.scheduleDeparture(
        departAtMinutes: 480, offPeakEndMinutes: 360, preconditioning: .allDays, offPeak: .weekdays, timeout: nil)
    if case .failure(let f) = onEnum(of: departure), case .invalidArgument = onEnum(of: f.error) {
        return // departAtMinutes outside 0..1440; nothing was sent
    }
    let schedule = ChargeSchedule(
        id: scheduleId, name: "Home", days_of_week: 127, start_enabled: true, start_time: 120,
        end_enabled: false, end_time: 0, one_time: false, enabled: true,
        latitude: latitude, longitude: longitude, unknownFields: OkioByteString.companion.EMPTY)
    _ = try await vehicle.addChargeSchedule(schedule: schedule, timeout: nil)
}
