# M5 getState와 응답 크기 초과 처리 (#115, #116) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `vehicle.getState(category)` 로 12개 Infotainment 상태를 BLE로 조회하고, 응답 크기 초과를 차량 끊김과 구분해 돌려준다.

**Architecture:** 이미 있는 `InfotainmentCommands.execute`(GCM, Infotainment 라우팅, `SendWithRetry`, `InfotainmentResponses`) 위에 카테고리 선택만 얹는다. 공개 파사드는 VCSEC 명령과 같은 시간 제한·`reconciling` 패턴을 쓴다. 새 재시도, 자동 세션 시작, 자동 깨우기는 없다.

**Tech Stack:** Kotlin Multiplatform, Wire 생성 타입, SKIE, `FakeVehicle`.

**Spec:** `{{PRD_FILE}}` FR-033, `{{SDD_FILE}}` §공개 API(298행), 318행, 521행, #115, #116. 참고 매뉴얼: `{{MANUAL_DIR}}03-protocol.md` §10~12, `05-command-catalog.md` §B·I, `08-errors.md` §3.1·§3.6. Go 원본: `{{REF_REPO_DIR}}pkg/vehicle/state.go`, `pkg/vehicle/infotainment.go`.

## Global Constraints

- 카테고리 하나당 요청 하나. 합쳐서 요청하는 API를 만들지 않는다(FR-033).
- 값이 없는 필드를 0으로 바꾸지 않는다. 생성 타입을 그대로 돌려준다.
- `getState` 는 세션을 시작하거나 차를 깨우지 않는다. 세션이 없으면 `Failure(NoSession)`.
- `RESPONSE_MTU_EXCEEDED` 는 `Uncertain(ProtocolFault(...))`. 재전송·세션 초기화·재연결·깨우기를 하지 않는다.
- 조회 결과(`VehicleData`, `toString()` 포함)를 로그에 남기지 않는다(FR-112, 위치·목적지 포함).
- `TESLEMETRY-EXT` 필드를 요청하거나 해석하지 않는다.

## Review Focus

1. 경로가 있는 `Drive` 에서 MTU 초과가 수십 초 이어질 때: 재전송 없이 매번 요청 하나로 끝나고 세션이 유지되어야 한다. Task 2 `mtuFaultIsUncertainWithoutResendOrSessionLoss`.
2. MTU 응답에 세션정보가 동봉될 때: 일반 세션 갱신은 그대로 일어나고 결과는 여전히 MTU여야 한다. Task 2 `mtuFaultWithAttachedSessionInfoStillRefreshesTheSession`.
3. Infotainment가 잠든 차: 자동으로 깨우지 않고 `Uncertain(Timeout(afterSend = true))` 로 끝나야 한다. Task 2 `sleepingInfotainmentTimesOutWithoutWakeOrResend`.
4. 값이 0인 필드와 없는 필드: `speed = 0` 은 0, 없는 `speed` 는 null로 남아야 한다. Task 1 `explicitZeroAndAbsentFieldsStayDistinct`.
5. 호출자가 조회를 취소할 때: `CancellationException` 이 전파되고 대기 요청이 남지 않아 다음 조회가 성공해야 한다. Task 2 `cancelledQueryLeavesNoPendingRequest`.
