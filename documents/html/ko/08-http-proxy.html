8. HTTP 프록시

tesla-http-proxy는 Fleet API 형식의 REST 요청을 받아 개인 키로 서명한 종단 간 인증 명령으로 바꿔 Tesla 서버를 거쳐 차량에 전달하는 HTTPS 서버입니다. 기존 Owner API 클라이언트를 최소 수정으로 이전할 때 사용합니다.

동작 흐름

프록시는 두 가지 자격 증명을 다룹니다. 클라이언트가 보내는 OAuth 토큰(Tesla 서버 인증)과 프록시가 기동 시 로드하는 개인 키(차량 인증)입니다. 개인 키의 공개 키는 사용자의 차량에 미리 등록되어 있어야 합니다.

OAuth 토큰을 얻는 절차(파트너 토큰 → 사용자 인가 → 코드 교환)는 doc/authorization.puml과 Fleet API 문서를 따르세요. 프록시는 토큰을 발급하거나 갱신하지 않습니다.

실행

tesla-http-proxy -tls-key config/tls-key.pem -cert config/tls-cert.pem -key-file config/fleet-key.pem -port 4443

-host hostnameTESLA_HTTP_PROXY_HOSTlocalhost바인드 주소. localhost가 아니면 기동 시 경고를 stderr에 출력

플래그가 환경 변수보다 우선합니다. 환경 변수는 플래그가 기본값일 때만 읽습니다. 잘못된 포트/타임아웃 형식은 invalid port/invalid timeout 오류로 종료합니다.

TLS 인증서

프록시는 TLS를 끌 수 없습니다. 개발용 자체 서명 인증서는 OpenSSL로 만듭니다.

mkdir config
openssl req -x509 -nodes -newkey ec \
    -pkeyopt ec_paramgen_curve:secp384r1 \
    -pkeyopt ec_param_enc:named_curve  \
    -subj '/CN=localhost' \
    -keyout config/tls-key.pem -out config/tls-cert.pem -sha256 -days 3650 \
    -addext "extendedKeyUsage = serverAuth" \
    -addext "keyUsage = digitalSignature, keyCertSign, keyAgreement"

클라이언트는 --cacert config/tls-cert.pem으로 이 인증서를 신뢰하게 합니다. 운영 환경에서는 공인 CA 인증서를 쓰고 -cert에 전체 체인을 넣으세요.

TLS 키와 명령 인증 키를 같은 키로 쓰면 기동이 거부됩니다

main.go는 -tls-key 파일을 protocol.LoadPublicKey로 읽어 명령 키의 공개 키와 비교합니다. 같으면 It is unsafe to use the same private key for TLS and command authentication.을 출력하고 종료합니다. 위 예시가 secp384r1(P-384)을 쓰는 이유 중 하나입니다(명령 키는 P-256).

Docker 배포

이미지 tesla/vehicle-command는 distroless 런타임 위에 다섯 도구를 담고 있고 기본 엔트리포인트가 tesla-http-proxy입니다. 개인 키는 파일로 마운트합니다(컨테이너에는 시스템 키링이 없습니다).

# docker run
docker pull tesla/vehicle-command:latest
docker run --security-opt=no-new-privileges:true -v ./config:/config -p 127.0.0.1:4443:4443 \
    tesla/vehicle-command:latest \
    -tls-key /config/tls-key.pem -cert /config/tls-cert.pem -key-file /config/fleet-key.pem -host 0.0.0.0 -port 4443

# docker compose (저장소의 docker-compose.yml)
docker compose up

저장소의 docker-compose.yml은 환경 변수로 같은 설정을 합니다.

services:
  tesla_http_proxy:
    image: tesla/vehicle-command:latest
    ports:
      - "4443:4443"
    environment:
      - TESLA_HTTP_PROXY_TLS_CERT=/config/tls-cert.pem
      - TESLA_HTTP_PROXY_TLS_KEY=/config/tls-key.pem
      - TESLA_HTTP_PROXY_HOST=0.0.0.0
      - TESLA_HTTP_PROXY_PORT=4443
      - TESLA_HTTP_PROXY_TIMEOUT=10s
      - TESLA_KEY_FILE=/config/fleet-key.pem
      - TESLA_VERBOSE=true
    security_opt:
      - no-new-privileges:true
    volumes:
      - ./config:/config

컨테이너 안에서 -host 0.0.0.0은 불가피하지만, 호스트 포트 매핑을 127.0.0.1:4443:4443처럼 루프백에 묶거나 앞단에 인증 프록시를 두어 외부 노출을 막으세요.

라우팅 규칙

(*proxy.Proxy).ServeHTTP는 요청 경로에 따라 다음 순서로 처리합니다.

순서경로처리
0모든 요청본문 크기를 1 MiB(maxRequestBodyBytes)로 제한. 초과 시 413
1GET /health인증 없이 200 OK. 다른 메서드는 405
2그 외 모든 경로Authorization: Bearer <token>이 없으면 403. 토큰의 aud/ou_code로 Fleet API 호스트를 결정(account.New). 이전에 421로 갱신된 호스트가 있으면 그것을 사용
3POST /api/1/vehicles/{VIN}/command/{name}VIN이 17자가 아니면 404(expected 17-character VIN in path (do not user Fleet API ID)). 프로토콜 미지원으로 표시된 VIN이면 포워딩. 아니면 handleVehicleCommand로 종단 간 인증 명령 실행. ErrCommandUseRESTAPI면 포워딩
4/api/1/vehicles/fleet_telemetry_config본문의 config를 JWS로 서명해 /api/1/vehicles/fleet_telemetry_config_jws로 포워딩
5나머지 /api/1/* 등 모든 경로forwardRequest: 헤더를 복사하고 hop-by-hop 헤더 제거, X-Forwarded-For 추가, HTTPS로 Fleet API에 전달. GET/POST 모두
Owner API ID가 아니라 VIN을 쓰세요

레거시 Owner API 클라이언트는 URL에 숫자 차량 ID를 넣습니다. 프록시는 command/ 경로에서 반드시 17자 VIN을 요구합니다. 다른 경로(예: vehicle_data)는 그대로 포워딩되므로 Fleet API가 허용하는 형식이면 됩니다.

응답 형식과 상태 코드

명령 성공

{"response":{"result":true,"reason":""}}

차량이 명령을 거부 (NominalError)

차량이 명령을 인증했지만 실행할 수 없는 경우(예: 이미 켜져 있음, 주차 상태 아님)는 Fleet API 관례대로 HTTP 200이고 result가 false, reason에 사유가 들어갑니다.

{"response":{"result":false,"reason":"car could not execute command: already_on"},"error":"","error_description":""}

그 외 오류

{"response":null,"error":"vehicle unavailable: vehicle is offline or asleep","error_description":""}
HTTP상황출처
200성공, 또는 차량의 애플리케이션 계층 거부(reason 확인)handleVehicleCommand
400JSON 파싱 실패, 파라미터 누락/형식 오류(missing X param, invalid X param), 알 수 없는 명령({"response":null,"error":"invalid_command","error_description":""}), remote_boombox 미구현, 잘못된 window_control 값extractCommandAction
403Authorization 헤더에 Bearer 토큰이 없음(client did not provide an OAuth token)ServeHTTP
404command/ 경로의 VIN이 17자가 아님ServeHTTP
405command/에 POST가 아닌 메서드, /health에 GET이 아닌 메서드
408차량이 오프라인/수면(inet.ErrVehicleNotAwake). Fleet API가 503 또는 "vehicle is offline" 408을 돌려준 경우. 먼저 wake_up을 호출httpStatusCode
412공개 키가 차량에 등록되지 않음(protocol.ErrKeyNotPaired). OAuth는 유효하므로 401이 아님httpStatusCode
413요청 본문 1 MiB 초과
422 (Fleet API)차량이 이 프로토콜을 지원하지 않음(protocol.ErrProtocolNotSupported). 프록시는 VIN을 미지원으로 기억하고 원래 요청을 REST로 포워딩. 이후 그 VIN의 명령은 항상 포워딩handleVehicleCommand
500분류되지 않은 오류, 차량 객체 생성 실패, JWS 서명 실패
502Fleet API 연결 실패, 응답 10 MB 초과, 421 재시도 소진(max retry exhausted)forwardRequest
503같은 VIN의 다른 명령이 진행 중이고 타임아웃 내에 락을 얻지 못함lockVIN
504Fleet API 응답 타임아웃forwardRequest
(그대로)포워딩된 요청은 Fleet API의 상태 코드, 헤더, 본문을 그대로 전달. inet.HTTPError로 분류된 오류도 원래 코드와 본문을 유지

Fleet Telemetry 설정 서명

POST /api/1/vehicles/fleet_telemetry_config에 서명되지 않은 설정을 보내면 프록시가 sign.SignMessageForFleet(key, "TelemetryClient", config)로 JWS를 만들어 /api/1/vehicles/fleet_telemetry_config_jws에 {"vins": [...], "token": "<jws>"}로 포워딩합니다. 설정에 aud나 iss가 있으면 덮어쓰고 경고를 로그에 남깁니다. tesla-jws -fleet sign TelemetryClient와 같은 결과입니다.

curl --cacert config/tls-cert.pem \
    --header 'Content-Type: application/json' \
    --header "Authorization: Bearer $TESLA_AUTH_TOKEN" \
    -X POST --data-binary "@telemetry.json" \
    "https://localhost:4443/api/1/vehicles/fleet_telemetry_config"

내부 동작

VIN별 직렬화
lockVIN이 VIN마다 뮤텍스를 잡아 같은 차량에 대한 명령을 순차 실행합니다. VCSEC는 카운터 순서가 어긋나면 거부하므로 필수입니다. 다른 VIN은 병렬로 처리됩니다.
세션 캐시
cmd/tesla-http-proxy는 proxy.New(ctx, key, 10000)으로 최대 10000대분의 세션을 메모리에 유지합니다(LRU). 명령마다 acct.GetVehicle → Connect → StartSession → 실행 → Disconnect를 반복하지만 캐시 덕분에 핸드셰이크는 첫 명령이나 세션 만료 시에만 발생합니다. 프로세스를 재시작하면 캐시가 사라집니다.
User-Agent
tesla-http-proxy/1.1.0(proxyProtocolVersion)을 앱 이름으로 account.New에 넘깁니다.
지역 호스트 결정
account.New가 토큰의 aud 중 fleet-api.로 시작하고 Tesla 도메인 접미사를 가진 것을 고르고, ou_code(지역)가 포함된 것을 우선합니다. 기본은 fleet-api.prd.na.vn.cloud.tesla.com.
421 리다이렉트
포워딩 응답이 421이고 Alt-Svc: h2="https://…" 헤더가 있으면 호스트를 바꿔 최대 2회(MaxAttempts) 재시도하고, 토큰 sub별로 새 호스트를 기억합니다. 종단 간 명령 경로에서는 inet.Connection이 본문의 use base URL: https://…를 파싱해 갱신합니다.
타임아웃
-timeout(기본 10초)이 명령 하나의 전체 컨텍스트입니다. 이 안에서 SDK가 핸드셰이크 재시도와 명령 재시도를 수행합니다.
테스트 훅
Proxy.client(httpDoer)와 Proxy.fetchVehicle(vehicleSession 반환)은 패키지 내부 테스트에서 교체됩니다(pkg/proxy/proxy_test.go).

보안 주의사항

  • localhost 외 바인드 금지(인증 없이). 프록시에는 클라이언트 인증이 없습니다. 아무나 접근할 수 있으면 당신의 IP에서 Tesla 서버로 과도한 트래픽이 발생해 rate limit이나 차단을 당할 수 있습니다. 기동 시 nonLocalhostWarning이 이를 경고합니다.
  • TLS 비활성 옵션은 없습니다. 과거 DIY 배포에서 차량이 인터넷에 노출된 사례 때문에 의도적으로 --insecure 류 플래그를 제공하지 않습니다. TLS 종단을 다른 곳에 두려면 pkg/proxy를 직접 사용하세요.
  • 개인 키 파일 권한. -key-file은 명령 인증 키입니다. 유출되면 등록된 모든 차량에 명령을 보낼 수 있습니다. 0600 권한과 최소 접근 원칙을 지키세요.
  • OAuth 토큰은 저장하지 않습니다. 프록시는 요청마다 헤더의 토큰을 그대로 사용합니다. 토큰 관리는 호출 측 책임입니다.

export TESLA_AUTH_TOKEN=<access-token>
export VIN=<17자 VIN>

    --header 'Content-Type: application/json' \
    --header "Authorization: Bearer $TESLA_AUTH_TOKEN" \

    --header 'Content-Type: application/json' \

pkg/proxy 임베드와 인증 미들웨어

cmd/tesla-http-proxy/main.go는 pkg/proxy를 감싼 얇은 래퍼입니다. 클라이언트 인증, 별도 TLS 종단, 요청 로깅 등을 추가하려면 proxy.Proxy(http.Handler)를 자체 핸들러로 감싸면 됩니다.

package main

import (
    "context"
    "crypto/subtle"
    "net/http"
    "time"

    "github.com/teslamotors/vehicle-command/pkg/protocol"
    "github.com/teslamotors/vehicle-command/pkg/proxy"
)

type authenticated struct {
    next   http.Handler
    apiKey string
}

func (a *authenticated) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    if r.URL.Path == "/health" {
        a.next.ServeHTTP(w, r)
        return
    }
    if subtle.ConstantTimeCompare([]byte(r.Header.Get("X-Api-Key")), []byte(a.apiKey)) != 1 {
        http.Error(w, "unauthorized", http.StatusUnauthorized)
        return
    }
    a.next.ServeHTTP(w, r) // Authorization: Bearer 헤더는 그대로 프록시로 전달
}

func main() {
    skey, err := protocol.LoadPrivateKey("config/fleet-key.pem")
    if err != nil { panic(err) }

    p, err := proxy.New(context.Background(), skey, 10000)
    if err != nil { panic(err) }
    p.Timeout = 10 * time.Second

    handler := &authenticated{next: p, apiKey: "..."}
    // TLS는 여기서 종단하거나, 앞단 리버스 프록시에 맡길 수 있다 (pkg/proxy는 TLS에 무관).
    panic(http.ListenAndServeTLS("localhost:4443", "config/tls-cert.pem", "config/tls-key.pem", handler))
}

proxy.ExtractCommandAction(ctx, command, params)를 직접 호출하면 HTTP 없이도 Fleet API 명령 이름 + JSON 파라미터를 func(*vehicle.Vehicle) error로 변환할 수 있어, 다른 RPC 프레임워크에 같은 명령 매핑을 재사용할 수 있습니다.
