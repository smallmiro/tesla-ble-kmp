16. 에러 처리

모든 호출은 세 가지 결과 중 하나를 반환하고, 모든 오류는 차량이 동작했을 수 있는지와 다시 시도하면 도움이 되는지를 알려 줍니다. 라이브러리가 안전하게 재시도할 수 있는 것은 이미 재시도하므로, 대부분의 앱은 결과에 따라 분기하기만 하면 됩니다.

오류 타입

모든 VehicleError는 message(영어), mayHaveSucceeded, temporary를 가집니다. shouldRetry()는 오류가 일시적이고 차량이 동작했을 리 없을 때 true입니다. 라이브러리가 이미 이런 경우를 재시도하므로 재시도 루프를 만들 필요가 없습니다.

타입발생 상황일시적성공했을 수 있음
ProtocolFault차량이 프로토콜 fault 코드를 보냄busy, timeout, signature, counter, internal, epoch, expiry fault만NONE과 RESPONSE_MTU_EXCEEDED만
KeyNotPaired차량이 이 키를 모름아니요아니요
InsufficientPrivileges키 역할이나 차량 상태(주행 중, 발레)가 명령을 허용하지 않음아니요아니요
Busy차량이 대기를 요청함예아니요
UnknownFault, UnknownKeychainCode, UnknownVcsecError, UnknownResponse새 펌웨어가 이 라이브러리의 프로토콜 정의에 없는 코드를 보냄. 업데이트를 확인하세요아니요아니요
NotConnected, NoSession, RequiresKey잘못된 순서로 또는 키 없이 호출함아니요아니요
BadResponse응답을 읽을 수 없음아니요VCSEC와 Infotainment 응답이면 예
KeychainRejected, VcsecRejected, InfotainmentRejected차량이 이해했지만 거부함아니요아니요
TransportError블루투스 스캔, 연결, 쓰기스캔 시간 초과, 연결 실패, 쓰기 실패만아니요
KeyStoreError플랫폼 키 보관소아니요아니요
Timeout명령의 시간 제한이 지남예이미 전송된 경우
InvalidArgument잘못된 인자아니요아니요

모든 프로토콜 fault 코드의 의미는 9. 오류와 문제 해결에 있습니다.

확장된 프로토콜 정의에서 온 코드

2026-10-18부터 라이브러리의 프로토콜 정의는 Teslemetry/tesla-protocol의 고정된 스냅샷에서 가져옵니다. 이 스냅샷은 공식 정의에 코드를 더한 것입니다(19. 아키텍처 참고). 스냅샷에 있는 코드는 이제 숫자를 담은 Unknown… 타입 대신 이름이 있는 오류 타입으로 알립니다. 라이브러리의 재시도 여부는 바뀌지 않습니다. 코드 이름은 스냅샷에서 온 것이며 실차에서 확인되지 않았습니다.

코드이전현재
프로토콜 fault 29 MESSAGEFAULT_ERROR_COMMAND_REQUIRES_PHYSICAL_PROXIMITYUnknownFault(29)ProtocolFault, 재시도하지 않음
키 목록 코드 29~32(rider·predelivery 키)UnknownKeychainCodeKeychainRejected
VCSEC 오류 8 GENERICERROR_KEY_NOT_FOUND, 9 GENERICERROR_NOT_SUPPORTEDUnknownVcsecErrorVcsecRejected
세션 정보 상태 2 SESSION_INFO_STATUS_INVALID_HANDLEUnknownResponseUnknownResponse(공식 Go 코드도 이 값을 모릅니다)

message가 아니라 오류 타입으로 판단하세요. 이제 메시지에는 숫자 대신 코드 이름이 들어갑니다.

블루투스와 키 보관소 오류

연결은 연결 시간 제한까지 1초마다 이미 재시도됩니다. 마지막 열은 앱이 할 일입니다.

오류의미대처
ScanTimeout시간 안에 차량을 찾지 못함차량이 범위 안에 있는지 확인하고 다시 시도
MaxConnectionsExceeded차량에 이미 블루투스 연결이 세 개 있음다른 휴대폰이나 앱의 연결을 끊고 다시 시도
ConnectFailed연결, 서비스 탐색, 구독 중 하나가 실패함잠시 후 다시 시도
Disconnected링크가 끊김disconnect()를 호출한 뒤 다시 연결
BluetoothOff블루투스가 꺼져 있음사용자에게 켜 달라고 요청
PermissionDenied블루투스 권한 없음권한을 요청하거나 설정 열기
WriteFailed전송 실패자동으로 재시도됨, 계속 발생하면 다시 연결
HardwareUnavailable하드웨어가 필요했지만 사용할 수 없음PREFER_HARDWARE 사용
KeyNotFound해당 별칭의 키가 없음getOrCreate로 생성
PlatformFailure플랫폼 키 보관소가 실패함. stored key is corrupted는 저장된 키가 손상되었다는 뜻손상된 키는 자동으로 교체되지 않음. 삭제하고, 생성하고, 새 키를 다시 등록

브로드캐스트 이벤트

vehicle.events에는 오류 값이 없고 예외도 던지지 않습니다. 링크가 끊기거나 disconnect()를 호출하면 정상적으로 끝납니다(14. 차량 상태 조회, B2). 링크가 끊긴 이유는 connection에 있습니다.

상황일어나는 일할 일
수집자가 프레임 64개보다 더 뒤처짐그 연결의 모든 수집자에게서 새 프레임이 빠지고 버린 수를 셉니다. 첫 번째와 100번째마다 WARN 줄(태그 Dispatcher): Dropping plain broadcast because the broadcast buffer is full (dropped N since connect). 오류가 아닙니다. VehicleError가 없고 흐름은 계속됩니다수집 코드는 가볍게 하고 느린 작업은 다른 코루틴에 넘기세요. 차량은 몇 초마다 상태를 다시 보내므로 최신 상태는 다시 옵니다. 또는 vehicleStatus()로 읽으세요
라이브러리가 디코딩하지 못한 브로드캐스트unknownFields가 빈 Unrecognized 이벤트. 바이트는 raw에 있습니다분석용으로 raw를 VIN을 가린 채 보관하세요

재시도와 시간 제한

라이브러리는 Go 원본과 같은 규칙으로 재시도합니다.

상황라이브러리 동작
차량이 동작했을 리 없는 일시적 오류(busy, wait, 만료, 잘못된 카운터…)1초 기다린 뒤 새 카운터와 만료 시각으로 명령에 다시 서명하고 재전송합니다. 오류와 함께 온 세션 정보를 먼저 적용합니다
차량이 동작했을 수 있는 오류(응답 없음, 읽을 수 없는 응답)토글 명령이 두 번 실행되지 않도록 절대 재전송하지 않습니다. Uncertain을 반환합니다
전송 전에 시간 제한이 지남Failure(Timeout)
응답을 기다리는 중에 시간 제한이 지남Uncertain(Timeout)
핸드셰이크의 시간 제한이 지남Failure(Timeout). 세션이 만들어지지 않았고 바뀐 것은 없습니다
TeslaBleConfig기본값용도
commandTimeout5초각 조회 또는 명령
commandLifetime5초차량이 서명된 명령을 받아들이는 시간
handshakeTimeout20초startSession()
connectTimeout30초스캔과 연결
pairingTimeout60 saddKeyRequest()

Uncertain 뒤에 읽을 것

Uncertain 뒤에는 절대 다시 보내지 마세요. 명령이 바꾸는 상태를 읽으세요.

명령읽는 방법확인할 것
lock, unlock, wakeUp, remoteDrive, autoSecureVehicle, openTrunk, actuateTrunk, closeTrunk, openFrunk, openTonneau, closeTonneau, stopTonneauvehicleStatus()잠금 상태, 개폐부, 수면 상태. openTrunk과 actuateTrunk는 토글이므로 다시 보내기 전에 개폐 상태를 비교하세요
addKey, removeKeylistKeys()공개키가 차량의 키 목록에 있는지
addKeyRequest (TimedOut이거나 마지막 응답 없이 플로우가 끝난 경우)sessionInfo(publicKey, VehicleDomain.INFOTAINMENT)Success = 등록됨, Failure(KeyNotPaired) = 아직 아님

인포테인먼트 명령은 M5에서 이 표에 추가됩니다.
