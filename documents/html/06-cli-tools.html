6. CLI 도구

cmd/ 아래 다섯 개 도구(tesla-keygen, tesla-control, tesla-auth-token, tesla-jws, tesla-http-proxy)의 사용법, 옵션, 환경 변수, 키링 동작을 정리합니다.

설치

cd vehicle-command
go get ./...
go build ./...
go install ./...          # $GOBIN (기본 ~/go/bin)에 다섯 도구 설치. make install 과 동일(./cmd/... 만 설치)

Docker 이미지 tesla/vehicle-command에도 다섯 도구가 모두 들어 있으며 기본 엔트리포인트는 tesla-http-proxy입니다. 다른 도구는 --entrypoint로 지정합니다. 단, 컨테이너 안에서는 호스트 BLE 어댑터에 접근할 수 없으므로 BLE 명령은 로컬 빌드로 실행하세요.

docker run --entrypoint tesla-keygen tesla/vehicle-command:latest -h
플랫폼

macOS와 Linux를 지원합니다. Windows에서는 BLE를 제외한 기능이 빌드되지만 pkg/connector/ble의 newAdapter가 not supported on Windows를 반환하므로 tesla-control -ble는 동작하지 않습니다. Linux에서는 BLE 어댑터 초기화에 CAP_NET_ADMIN이 필요합니다(문제 해결).

공통 환경 변수

pkg/cli.Config.ReadFromEnvironment()는 명령줄 플래그로 채워지지 않은 값만 환경 변수로 채웁니다. 즉 플래그가 항상 우선합니다.

환경 변수대응 플래그의미사용 도구
TESLA_KEY_NAME-key-name시스템 키링에 저장된 명령 인증 개인 키의 이름keygen, control, jws, http-proxy
TESLA_KEY_FILE-key-file개인 키 PEM 파일 경로. 이름과 파일이 둘 다 있으면 파일이 우선 로드됨keygen, control, jws, http-proxy
TESLA_TOKEN_NAME-token-name키링에 저장된 OAuth 토큰 이름control, auth-token, keygen(등록만)
TESLA_TOKEN_FILE-token-fileOAuth 토큰 파일 경로. 파일이 없으면 키링으로 폴백control
TESLA_VIN-vin17자 VINcontrol, jws
TESLA_CACHE_FILE-session-cache세션 캐시 JSON 파일. 미지정 시 $HOME/.tesla-cache.json. -disable-session-cache로 끔control, keygen, jws, http-proxy(로드만)
TESLA_KEYRING_TYPE-keyring-type키링 백엔드 종류. 지원 목록은 tesla-keygen -h의 -keyring-type 설명에 OS별로 표시keygen, control, jws, http-proxy, auth-token(환경 변수만)
TESLA_KEYRING_PASSWORD(없음)파일/키체인 백엔드 비밀번호. 설정하면 프롬프트를 띄우지 않음키링을 쓰는 모든 도구
TESLA_KEYRING_PATH-keyring-file-dir파일 백엔드 디렉터리. 기본 ~/.tesla_keys키링을 쓰는 모든 도구
TESLA_KEYRING_DEBUG-keyring-debug존재하면 키링 디버그 로그 활성화(값 무관)키링을 쓰는 모든 도구
TESLA_VERBOSE-debug / -verbosefalse, 0 이외의 값이면 디버그 로그(TX/RX 16진수 포함)control, http-proxy
TESLA_HTTP_PROXY_TLS_CERT-cert프록시 TLS 인증서 체인 파일http-proxy
TESLA_HTTP_PROXY_TLS_KEY-tls-key프록시 TLS 개인 키 파일http-proxy
TESLA_HTTP_PROXY_HOST-host바인드 호스트. 기본 localhosthttp-proxy
TESLA_HTTP_PROXY_PORT-port바인드 포트. 기본 443http-proxy
TESLA_HTTP_PROXY_TIMEOUT-timeout명령 타임아웃(예: 10s). 기본 10초http-proxy

일반적인 초기 설정:

export TESLA_KEY_NAME=$(whoami)
export TESLA_TOKEN_NAME=$(whoami)
export TESLA_VIN=5YJ30123456789ABC
export TESLA_CACHE_FILE=~/.tesla-cache.json

키링 동작

개인 키와 OAuth 토큰은 99designs/keyring을 통해 OS 자격 증명 저장소에 보관됩니다.

서비스 이름
com.tesla.auth (macOS 키체인에서는 이 이름으로 항목이 보입니다)
개인 키 항목
vehicleCommandKey.<TESLA_KEY_NAME>. 데이터는 32바이트 P-256 스칼라(빅엔디언)
OAuth 토큰 항목
oauthtoken.<TESLA_TOKEN_NAME>. 데이터는 토큰 문자열 그대로
기본 백엔드
OS 기본. macOS는 로그인 키체인(KeychainTrustApplication: true), Linux는 secret-service/kwallet/keyctl 등 가용한 것, 파일 백엔드는 ~/.tesla_keys
비밀번호
파일 백엔드나 키체인 잠금 해제에 비밀번호가 필요하면 터미널에 프롬프트를 띄웁니다. stdout/stderr가 모두 터미널이 아니면 no terminal output available for password prompt 오류. 무인 실행에서는 TESLA_KEYRING_PASSWORD를 설정하세요.
KeyCtl 범위
Linux keyctl 백엔드는 user 범위를 씁니다.

tesla-control은 연결 타임아웃이 시작되기 전에 config.LoadCredentials()를 호출해 비밀번호 프롬프트가 타임아웃을 소모하지 않도록 합니다. 자체 도구를 만들 때도 같은 순서를 지키세요.

tesla-keygen

명령 인증용 P-256 개인 키를 생성·삭제·내보내기·이전하고 공개 키를 PEM으로 출력합니다.

usage: tesla-keygen [OPTION...] create|delete|export|migrate
서브커맨드동작
create키가 이미 있으면(키링 이름 또는 파일) 생성하지 않고 기존 키의 공개 키만 출력합니다. -f를 주면 새 키로 덮어씁니다. 저장 위치는 -key-name이 있으면 키링, 없으면 -key-file(SEC1 PEM, 0600). 둘 다 없으면 private key location not provided.
delete키링에서 vehicleCommandKey.<name>을 삭제합니다. 파일 키는 삭제하지 않습니다.
export개인 키를 EC PRIVATE KEY PEM으로 stdout에 출력합니다. 내보낼 수 없는 키 구현이면 오류.
migrate-key-file의 PEM 개인 키를 읽어 -key-name 이름으로 키링에 저장합니다. 둘 다 필수. 원본 파일은 그대로 둡니다.
옵션설명
-f기존 키가 있어도 덮어쓰기 (create)
-output file공개 키를 stdout 대신 파일에 저장
-key-name name, -key-file file키 위치. 기본 $TESLA_KEY_NAME, $TESLA_KEY_FILE
-keyring-type type, -keyring-file-dir directory, -keyring-debug키링 설정
-token-name, -token-file, -session-cache, -disable-session-cache, -domaincli.FlagOAuth | cli.FlagPrivateKey로 등록되어 있어 플래그는 존재하지만 keygen 동작에는 영향이 없습니다
 
# 키링에 생성하고 공개 키 저장
export TESLA_KEY_NAME=$(whoami)
tesla-keygen create > public_key.pem

# 파일 기반 키 생성 (키링 없이)
tesla-keygen -key-file ~/.tesla/private.pem create > public_key.pem

# OpenSSL로 만든 키를 키링으로 이전
tesla-keygen -key-file private.pem -key-name $(whoami) migrate

# 백업용 내보내기 (출력은 비밀. 안전하게 보관)
tesla-keygen export > private_backup.pem

# 파일 백엔드 강제 + 무인 실행
TESLA_KEYRING_TYPE=file TESLA_KEYRING_PASSWORD=... tesla-keygen create

출력되는 공개 키는 PKIX PEM(-----BEGIN PUBLIC KEY-----)입니다. Fleet API 파트너 등록(/.well-known/appspecific/com.tesla.3p.public-key.pem)과 tesla-control add-key-request 양쪽에 그대로 쓸 수 있습니다.

tesla-control

BLE 또는 인터넷으로 차량 명령을 보내는 범용 CLI입니다. Windows에서는 동작하지 않습니다.

Usage: tesla-control [OPTION...] COMMAND [ARG...]
       tesla-control help            # 전체 명령 목록
       tesla-control help COMMAND    # 명령별 인자 설명
       tesla-control                 # COMMAND 없이 실행하면 대화형 셸

옵션

옵션기본값설명
-blefalseOAuth 환경 변수가 있어도 BLE 연결을 강제. Fleet API 전용 명령과 함께 쓰면 command requires a FleetAPI OAuth token
-debugfalse디버그 로그. TX/RX 16진수 덤프 포함. TESLA_VERBOSE로도 켤 수 있음
-command-timeout duration5s명령 하나의 타임아웃. 이 안에서 SDK가 재시도를 반복
-connect-timeout duration20s스캔 + 연결 + 핸드셰이크 타임아웃
-vin VIN$TESLA_VIN대상 차량
-key-name name / -key-file file$TESLA_KEY_NAME / $TESLA_KEY_FILE명령 인증 개인 키
-token-name name / -token-file file$TESLA_TOKEN_NAME / $TESLA_TOKEN_FILEOAuth 토큰(인터넷 경로)
-session-cache file$TESLA_CACHE_FILE → ~/.tesla-cache.json세션 캐시 파일. 종료 시 자동 갱신
-disable-session-cachefalse캐시 사용 안 함
-domain vcsec|infotainment(모두)핸드셰이크할 도메인. 반복 지정 가능. 예: -domain vcsec으로 인포테인먼트를 깨우지 않음
-keyring-type, -keyring-file-dir, -keyring-debugOS 기본 / ~/.tesla_keys / false키링 설정
-bt-adapter id (Linux만)hci0사용할 블루투스 어댑터(hci0~hci15)

자격 증명 선택 규칙

각 명령은 cmd/tesla-control/commands.go에서 requiresAuth(개인 키 필요)와 requiresFleetAPI(OAuth 토큰 필요)로 분류됩니다. 실행 전 configureFlags와 checkReadiness가 다음 규칙을 적용합니다.

명령 유형필요한 것전송예
차량 명령, 인증 필요 (requiresAuth)VIN + 개인 키OAuth가 있으면 인터넷, -ble이거나 OAuth가 없으면 BLElock, climate-on, state charge
차량 명령, 인증 불필요VIN위와 같음list-keys, session-info, body-controller-state, add-key-request, wake(인터넷)
계정 명령 (requiresFleetAPI)OAuth 토큰인터넷만. -ble과 함께 쓰면 오류product-info, rename-key, get, post
-ble wakeVIN + 개인 키BLE. VCSEC와만 핸드셰이크(인포테인먼트가 잠들어 있으므로)tesla-control -ble wake

body-controller-state는 domain: protocol.DomainVCSEC가 지정되어 있어 VCSEC와만 핸드셰이크합니다. 다른 명령은 -domain 플래그로 제한할 수 있습니다.

대화형 셸

COMMAND 없이 실행하면 연결을 한 번 맺고 > 프롬프트에서 여러 명령을 연속으로 보낼 수 있습니다. 핸드셰이크를 매번 반복하지 않으므로 여러 명령을 시험할 때 유용합니다. 인자는 shlex로 파싱하므로 따옴표를 쓸 수 있고, exit로 종료합니다. 각 명령에는 -command-timeout이 적용됩니다.

$ tesla-control -ble
> body-controller-state
{ "vehicleLockState": "VEHICLELOCKSTATE_LOCKED", ... }
> unlock
> climate-set-temp 21C
> exit

출력과 종료 코드

  • 성공: 종료 코드 0. 대부분의 명령은 아무것도 출력하지 않습니다. state, body-controller-state, session-info, list-keys, product-info, get/post, charging-schedule-add(생성된 ID) 등은 stdout에 결과를 출력합니다.
  • Couldn't verify success: …: 명령이 도착했을 수 있으나 확인을 못 받음(protocol.MayHaveSucceeded). 종료 코드 1.
  • You must provide a private key with -key-name or -key-file to execute this command: protocol.ErrNoSession. 종료 코드 1.
  • Failed to execute command: …: 그 외 오류. 종료 코드 1.
  • Linux에서 어댑터 권한 오류면 setcap 안내문을 출력합니다.

예시

# 키 페어링 (차 안에서, NFC 카드 준비)
tesla-control -ble add-key-request public_key.pem owner cloud_key

# 등록 확인
tesla-control -ble list-keys
tesla-control -ble session-info public_key.pem infotainment

# 기본 명령
tesla-control -ble lock
tesla-control -ble -domain vcsec unlock           # 인포테인먼트를 깨우지 않음
tesla-control -ble climate-set-temp 72F
tesla-control -ble seat-heater front-left high
tesla-control -ble charging-set-limit 80
tesla-control -ble state climate
tesla-control -ble -debug ping                    # TX/RX 덤프 확인

# 인터넷 경로 (OAuth 토큰이 키링에 있을 때)
tesla-control wake
tesla-control lock
tesla-control product-info
tesla-control get "api/1/vehicles/$TESLA_VIN/vehicle_data"

# 충전 스케줄
tesla-control -ble charging-schedule-add weekdays 22:00-06:00 37.4 -122.1
tesla-control -ble charging-schedule-remove home

전체 명령과 인자는 7. 명령 레퍼런스를 보세요.

tesla-auth-token

OAuth 토큰을 stdin 또는 파일에서 읽어 키링의 oauthtoken.<name> 항목으로 저장합니다. 토큰을 발급하지는 않습니다. 발급 절차는 Fleet API 문서를 따르세요.

usage: tesla-auth-token [-token-name token_name] [file]
옵션설명
-token-name name키링 항목 이름. 기본 $TESLA_TOKEN_NAME. 이것이 유일한 플래그입니다. 키링 종류/경로/비밀번호는 TESLA_KEYRING_TYPE, TESLA_KEYRING_PATH, TESLA_KEYRING_PASSWORD 환경 변수로만 지정합니다.
file (위치 인자)토큰이 든 파일. 생략하면 stdin에서 EOF까지 읽습니다. 두 개 이상 주면 오류.
 
export TESLA_TOKEN_NAME=$(whoami)
echo -n "$ACCESS_TOKEN" | tesla-auth-token
tesla-auth-token token.txt
# 저장 후 tesla-control은 OAuth가 있으므로 기본적으로 인터넷 경로를 사용한다. BLE를 쓰려면 -ble.
토큰 문자열은 그대로 저장됩니다

읽은 바이트를 가공 없이 저장하므로 끝의 개행이 포함될 수 있습니다. account.New가 strings.TrimSpace로 정리하므로 동작에는 문제가 없습니다. 만료된 토큰은 갱신 후 다시 저장해야 합니다.

tesla-jws

Fleet Telemetry 설정 등에 쓰는 JWS(JSON Web Signature)를 명령 인증 개인 키로 서명하거나 검증합니다. 서명 알고리즘은 JWS 표준에 없는 Tesla.SS256(Schnorr/P-256 + SHA-256)으로, 기존 ECDH/P-256 키를 서명 키로 안전하게 재사용하기 위한 것입니다.

usage: tesla-jws [OPTION...] sign APP [JSON_FILE]
       tesla-jws verify [JWS_FILE]
서브커맨드 / 옵션설명
sign APP [JSON_FILE]JSON_FILE(없으면 stdin)의 JSON 객체를 클레임으로 서명합니다. iss는 base64 공개 키, aud는 컨텍스트 문자열로 덮어씁니다. 결과 JWS를 stdout에 출력.
-fleet플릿 전체용 서명. aud = com.tesla.fleet.<APP>. 없으면 -vin이 필수이고 aud = com.tesla.vehicle.<VIN>.<APP>가 되어 해당 차량만 수락.
verify [JWS_FILE]서명이 iss의 공개 키로 유효한지만 검사하고 클레임을 JSON으로 출력합니다. 발급자가 신뢰할 만한지, aud가 맞는지는 검사하지 않습니다.
-vin, -key-name, -key-file, -keyring-*, -session-cache, -domaincli.FlagPrivateKey | cli.FlagVIN 공통 플래그
 
# Fleet Telemetry 설정 서명 → Fleet API /api/1/vehicles/fleet_telemetry_config_jws 에 POST
tesla-jws -fleet sign TelemetryClient telemetry_config.json > signed-config.jws
tesla-jws verify signed-config.jws

# 특정 차량 전용 서명
tesla-jws -vin $TESLA_VIN sign TelemetryClient telemetry_config.json

생성된 .jws 파일은 비밀이 아닙니다(JWT와 같은 문법이지만 bearer 토큰이 아닙니다). 프록시의 /api/1/vehicles/fleet_telemetry_config 엔드포인트는 같은 서명을 서버 쪽에서 자동으로 수행합니다(8. HTTP 프록시).

tesla-http-proxy

REST 요청을 종단 간 인증 명령으로 변환하는 HTTPS 서버입니다. 옵션, 라우팅, 응답 형식, 배포는 8. HTTP 프록시에서 자세히 다룹니다. 요약:

tesla-http-proxy -tls-key config/tls-key.pem -cert config/tls-cert.pem -key-file config/fleet-key.pem -port 4443
옵션기본값설명
-cert file(필수)서버 + 중간 CA + 루트 CA를 이어 붙인 TLS 인증서 체인
