11. Library Overview

tesla-ble-kmp is the library built in this repository: a Kotlin Multiplatform port of the BLE path of vehicle-command, so an Android or iOS app can talk to a Tesla directly, with no server. Chapters 11 to 19 describe how to use it. Chapters 1 to 9 describe the Go original.

What works today

The library is built milestone by milestone. These pages describe the code on main, which is at M4, plus the broadcast events and the key accessibility choice from issue #91.

Planned APIs are not available yet

Names of planned methods come from the requirements document (docs/prd/PRD.md) and may change when the milestone lands. Until then an app can scan, connect, read state, receive the car's broadcasts, enroll a key, choose whether the key works while the phone is locked and send the VCSEC control commands, but cannot send infotainment commands. Pairing and the VCSEC commands have not been checked on a real car yet.

Platforms and packages

  • Android 12 (API 31) or later and iOS 16 or later. The app is expected to be in the foreground.
  • A JVM target exists for tests and experiments. Its keys and session cache live in memory only.
  • Package root dev.mirolab.teslable: the facade in dev.mirolab.teslable, values and results in dev.mirolab.teslable.model, the key store, scanning and logging in dev.mirolab.teslable.port.
  • The iOS framework is Teslable. Swift sees Kotlin through SKIE (async functions, AsyncSequence, onEnum(of:)).

Installation

The library is not published yet; M6 adds GitHub Packages and Swift Package Manager. For now, build it from source:

How these pages are kept up to date

Every pull request that changes the library's behaviour, public API or milestone status updates these pages before it is merged: the Markdown page for agents (documents/md/1x-lib-*.md, English) and the HTML page for people in Korean, English and Japanese. The Go reference chapters 1 to 9 are changed only with the maintainer's approval.
