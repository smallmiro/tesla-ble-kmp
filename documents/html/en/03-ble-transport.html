3. BLE Transport Layer

How pkg/connector/ble exchanges bytes with the vehicle over GATT: advertised name, service/characteristic UUIDs, length framing, MTU chunking, scanning and connection retries, and platform differences.

The transport layer knows nothing about cryptography

ble.Connection implements only the connector.Connector interface. In other words, it just sends and receives []byte; protobuf, sessions, and signatures are all the job of the upper layers (internal/dispatcher, internal/authentication). This page covers only how those bytes are carried over the air.

Computing the advertised name

The vehicle does not advertise its VIN directly. It advertises, as its Local Name, the first 8 bytes of the VIN's SHA-1 digest encoded as lowercase hex, prefixed with S and suffixed with C.

// pkg/connector/ble/ble.go
func VehicleLocalName(vin string) string {
	vinBytes := []byte(vin)
	digest := sha1.Sum(vinBytes)
	return fmt.Sprintf("S%02xC", digest[:8])
}
# Check from the shell: VIN 5YJS0000000000000 → S1a87a5a75f3df858C
printf '5YJS0000000000000' | shasum | cut -c1-16 | sed 's/^/S/; s/$/C/'
# S1a87a5a75f3df858C

The scan callback ignores the advertisement if a.LocalName() != localName. If the caller passes a ScanResult whose name differs from the one computed from the VIN, tryToConnect raises the error ble: beacon with unexpected local name and does not retry.

GATT connection procedure

This is the sequence performed by tryToConnect. A failure at each step is classified as retry=true (retryable), except for adapter errors, name mismatches, and non-connectable advertisements.

  1. Adapter initialization initAdapter(nil). Reuses the global device if it already exists.
  2. Scan (when target is nil) obtains the advertised address with scanVehicleBeacon(ctx, localName).
  3. Connectability check If target.Connectable == false, returns ErrMaxConnectionsExceeded with no retry.
  4. Dial device.Dial(ctx, ble.NewAddr(target.Address)).
  5. Service discovery client.DiscoverServices([]ble.UUID{vehicleServiceUUID}). If the result is empty, failed to discover service.
  6. Characteristic discovery client.DiscoverCharacteristics([]ble.UUID{toVehicleUUID, fromVehicleUUID}, services[0]). If both characteristics are not found, failed to find required characteristics.
  7. Descriptor discovery client.DiscoverDescriptors(nil, characteristic) for each characteristic. go-ble must find the CCCD (0x2902) for subscription to work.
  8. Subscribe client.Subscribe(conn.rxChar, true, conn.rx): enables indications on the 0213 characteristic and registers the receive callback rx.
  9. MTU exchange client.ExchangeMTU(ble.MaxMTU). On success, blockLength = min(txMtu, 1024) - 3; on failure, logs a warning and falls back to ble.DefaultMTU - 3 (= 20 bytes). The 3 bytes are the ATT Write Request header (opcode 1 + handle 2).

On success, [info ] Connected to vehicle BLE is logged and a *Connection is returned. Close() calls ClearSubscriptions() and CancelConnection() and is safe to call multiple times.

Message framing and MTU

A single BLE characteristic write is bound by the MTU, but a RoutableMessage can be hundreds of bytes long, so the SDK treats the link as a length-prefixed stream.

Transmit code

func (c *Connection) Send(_ context.Context, buffer []byte) error {
	c.lock.Lock()
	defer c.lock.Unlock()
	var out []byte
	out = append(out, uint8(len(buffer)>>8), uint8(len(buffer)))  // 2-byte big-endian length
	out = append(out, buffer...)
	blockLength := c.blockLength
	for len(out) > 0 {
		if blockLength > len(out) { blockLength = len(out) }
		if err := c.client.WriteCharacteristic(c.txChar, out[:blockLength], false); err != nil {
			return err
		}
		out = out[blockLength:]
	}
	return nil
}

Send ignores ctx (go-ble's write API takes no context). A mutex ensures only one message is written at a time, so chunks never interleave.

Receive code

func (c *Connection) rx(p []byte) {
	if time.Since(c.lastRx) > rxTimeout {
		c.inputBuffer = []byte{}          // discard stale partial message
	}
	c.lastRx = time.Now()
	c.inputBuffer = append(c.inputBuffer, p...)
	for c.flush() {}                       // deliver every complete message in the buffer
}

func (c *Connection) flush() bool {
	if len(c.inputBuffer) >= 2 {
		msgLength := 256*int(c.inputBuffer[0]) + int(c.inputBuffer[1])
		if msgLength > maxBLEMessageSize { c.inputBuffer = []byte{}; return false }
		if len(c.inputBuffer) >= 2+msgLength {
			buffer := c.inputBuffer[2 : 2+msgLength]
			c.inputBuffer = c.inputBuffer[2+msgLength:]
			select {
			case c.inbox <- buffer:
			default:
				return false                 // inbox full: drop message
			}
			return true
		}
	}
	return false
}
The receive path has no locking

rx and flush assume they are called sequentially from go-ble's notification goroutine and have no locks of their own. When porting to another BLE stack where callbacks may arrive in parallel, you need to serialize them.

Scanning

type ScanResult struct {
	Address     string  // advertised address (CoreBluetooth identifier on macOS, MAC on Linux)
	LocalName   string  // "S…C"
	RSSI        int16   // dBm
	Connectable bool    // false means the vehicle has already reached its maximum number of connections
}

func ScanVehicleBeacon(ctx context.Context, vin string) (*ScanResult, error)
  • ScanVehicleBeacon initializes the adapter and returns the first advertisement matching VehicleLocalName(vin). It keeps scanning until ctx expires.
  • The internal scanVehicleBeacon cancels a derived context to stop device.Scan once it finds a matching advertisement. On macOS, device.Scan does not return until the context is cancelled and always returns context.Canceled, so the code treats only errors for which errors.Is(err, context.Canceled) is false as failures.
  • Connectable == false: due to hardware constraints, the vehicle (VCSEC) maintains at most 3 BLE connections at a time, shared by key fobs and phone keys. Attempting to connect in this state immediately returns ErrMaxConnectionsExceeded ("the vehicle is already connected to the maximum number of BLE devices"). Turn off nearby phone keys or move them away from the car.
  • There is no logic to pick the nearest of several vehicles by RSSI. It is unnecessary because there is only one vehicle with a given VIN.
  • To scan only, see the -scan-only flag in examples/ble. The result of ScanVehicleBeacon can be passed to NewConnectionFromScanResult to skip rescanning.

Connection retry loop

func NewConnection(ctx context.Context, vin string) (*Connection, error) {
	return NewConnectionFromScanResult(ctx, vin, nil)
}

func NewConnectionFromScanResult(ctx context.Context, vin string, target *ScanResult) (*Connection, error) {
	var lastError error
	for {
		conn, retry, err := tryToConnect(ctx, vin, target)
		if err == nil { return conn, nil }
		if !retry || IsAdapterError(err) { return nil, err }   // fatal: give up immediately
		log.Warning("BLE connection attempt failed: %s", err)
		if err := ctx.Err(); err != nil {                        // ctx expired: return the last real error
			if lastError != nil { return nil, lastError }
			return nil, err
		}
		lastError = err
	}
}

Because there is no wait between retries, the effective upper bound is the deadline of ctx. tesla-control creates this ctx with -connect-timeout (default 20 seconds). After connecting, Vehicle.Connect and StartSession share the same ctx, so set it generously in environments where scanning takes a long time.

Adapter management

The package holds a single global device ble.Device and a mutex mu. Calling newDevice() multiple times fails on Linux, so an adapter, once created, is reused.

FunctionDescription
InitAdapterWithID(id string) errorCreates the global device using the specified adapter. You do not need to call it when using the default adapter; ScanVehicleBeacon/NewConnection initialize automatically via initAdapter(nil). To use a non-default adapter, you must call it before any other BLE call. On Linux, "hci0"–"hci15"; any other format yields ErrAdapterInvalidID. On macOS, passing a non-empty ID logs a warning and yields ErrAdapterInvalidID.
CloseAdapter() errorCalls device.Stop() and sets the global variable to nil. It does not close existing connections or stop scans, so you must first call Connection.Close() and cancel the scan ctx. A new adapter is then created on the next call.
IsAdapterError(err) boolLinux: whether the error string contains operation not permitted. macOS/Windows: always false (TODO)
AdapterErrorHelpMessage(err) stringLinux: a message including setcap 'cap_net_admin=eip' guidance. Elsewhere: err.Error()

pkg/cli.Config.ConnectLocal calls ble.InitAdapterWithID(c.BtAdapterID) → ble.NewConnection(ctx, c.VIN) → vehicle.NewVehicle(conn, skey, c.sessions) in that order. For a long-running process that connects to multiple vehicles in sequence, initialize the adapter once and just open and close Connections.

VCSEC response characteristics and concurrency

With a direct BLE connection, VCSEC characteristics that the Fleet API used to hide are exposed as-is. The dispatcher handles them, but you should understand the behavior.

  • There is no request_uuid. Due to memory constraints, VCSEC does not fill in the request UUID in responses. The dispatcher therefore generates a fresh random 16-byte routing_address for every request sent to VCSEC, and finds the waiting receiver by the response's to_destination.routing_address (Infotainment uses a fixed per-connection address + request_uuid).
  • No concurrent requests. VCSEC requires counters to arrive in order and has difficulty distinguishing concurrent requests, so requests are sent one at a time. tesla-control and the proxy (lockVIN) serialize commands.
  • Up to 3 responses per request. OPERATIONSTATUS_WAIT (waiting for an NFC tap, or busy), an intermediate status, and the final result may arrive separately. readUntil in pkg/vehicle/vcsec.go keeps reading the receiver channel until the termination condition (isTerminalTest) is true. For example, Lock treats an empty message without commandStatus as success, and whitelist operations treat a message with whitelistOperationStatus filled in as terminal.
  • OPERATIONSTATUS_ERROR is ignored. It exists for legacy clients; new clients wait for the specific error code in the next message. In this case the dispatcher converts it to a KeychainError if whitelistOperationInformation is not NONE, or to ErrUnknown if there is no signedMessageStatus.
  • Infotainment sleep. To establish only a VCSEC session, use StartSession(ctx, []Domain{DomainVCSEC}). Handshaking with both domains either fails because Infotainment is asleep, or is delayed until the vehicle wakes up.

These are the conditions you must meet when reimplementing this transport layer in Python (bleak), Swift (CoreBluetooth), Kotlin (Android BluetoothGatt), Rust (btleplug), and so on. For the detailed checklist, see ../md/10-porting-guide.md.
