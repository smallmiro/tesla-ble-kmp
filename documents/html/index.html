Tesla vehicle-command BLE 개발 매뉴얼

Tesla 차량과 Bluetooth Low Energy(BLE) 또는 인터넷으로 연결해 종단 간 인증(end-to-end authenticated) 명령을 보내는 vehicle-command SDK의 개발자 매뉴얼입니다.

이 문서의 기준 버전

저장소 vehicle-command/의 태그 v0.4.1 이후 커밋 a4b43c1(Fix wrapped protocol error classification)을 기준으로 작성했습니다. Go 모듈 경로는 github.com/teslamotors/vehicle-command, 요구 Go 버전은 1.23입니다. 코드가 갱신되면 이 매뉴얼의 API 시그니처와 명령 목록도 다시 확인하세요.

누가 어떤 문서를 읽어야 하나

이 매뉴얼은 두 벌로 제공됩니다. 같은 내용을 다루지만 독자가 다릅니다.

위치독자형식특징
documents/html/사람 (개발자, 리뷰어, 운영자)HTML (지금 보고 있는 문서)개념 설명, 다이어그램, 단계별 절차, 표 중심

문서 구성

01

시스템 개요

두 단계 인증 모델, VCSEC/Infotainment 도메인, 저장소 구조와 계층 아키텍처.
02

시작하기

설치, 키 생성, NFC 카드로 키 페어링, 첫 BLE 명령까지 10분 안에.
03

BLE 전송 계층

GATT 서비스/특성 UUID, 광고 이름 계산, 2바이트 길이 프레이밍, MTU, 스캔과 연결 재시도.
04

프로토콜 사양

RoutableMessage, 핸드셰이크, ECDH 키 합의, 메타데이터 TLV, HMAC/AES-GCM 인증, 응답 복호화, 세션 복구.
05

Go SDK

pkg/vehicle, pkg/connector, pkg/cache, pkg/cli, pkg/account로 애플리케이션을 만드는 방법.
06

CLI 도구

tesla-keygen, tesla-control, tesla-auth-token, tesla-jws, tesla-http-proxy의 옵션과 환경 변수.
07

명령 레퍼런스

모든 차량 명령을 CLI 이름, Go 메서드, 프록시 엔드포인트, 도메인, 인증 요구 사항으로 정리한 표.
08

HTTP 프록시

REST API를 종단 간 인증 명령으로 변환하는 프록시의 설정, TLS, Docker 배포, 응답 규약.
09

오류와 문제 해결

MessageFault 코드 전체, 재시도 정책, BLE 연결 실패, 키 페어링 실패, 세션 desync 대처법.

30초 요약

  1. 키를 만든다. tesla-keygen create > public_key.pem. NIST P-256 개인 키가 OS 키링에 저장되고 공개 키가 출력됩니다.
  2. 차량에 키를 등록한다. 차 안에서 tesla-control -ble add-key-request public_key.pem owner cloud_key를 실행하고 NFC 카드를 센터 콘솔에 대어 승인합니다.
  3. 명령을 보낸다. tesla-control -ble lock. SDK가 광고 스캔 → GATT 연결 → 도메인별 핸드셰이크 → AES-GCM 암호화 명령 전송을 처리합니다.
export TESLA_KEY_NAME=$(whoami)
export TESLA_VIN=5YJ30123456789ABC
export TESLA_CACHE_FILE=~/.tesla-cache.json

tesla-keygen create > public_key.pem
tesla-control -ble add-key-request public_key.pem owner cloud_key   # 차 안에서, NFC 카드 준비
tesla-control -ble lock
tesla-control -ble -debug body-controller-state                     # 잠금/도어/수면 상태 (Infotainment가 자고 있어도 동작)

핵심 개념 한눈에

도메인(Domain)
VCSEC 잠금, 트렁크, 키 관리, 웨이크업을 담당하는 보안 컨트롤러. Infotainment가 잠들어 있어도 BLE로 응답합니다. INFOTAINMENT 공조, 충전, 미디어, 상태 조회 등 나머지 명령을 담당합니다. 도메인마다 별도의 키 쌍과 세션이 있습니다.
세션(Session)
클라이언트 공개 키로 SessionInfoRequest를 보내면 도메인이 자신의 공개 키, epoch, 카운터, 시계를 담은 SessionInfo를 돌려줍니다. ECDH로 128비트 AES-GCM 키 K를 합의합니다.
인증 방식
BLE에서는 AES-GCM(암호화 + 인증), Fleet API에서는 HMAC-SHA256(평문 + 인증)을 사용합니다. 두 방식 모두 VIN, epoch, 만료 시각, 카운터가 담긴 메타데이터를 인증에 결합합니다.
역할(Role)
Owner, Driver, Fleet Manager, Vehicle Monitor, Charging Manager, Guest, Service. 역할에 따라 허용되는 명령이 달라집니다.
세션 캐시
세션 상태를 디스크에 저장하면 다음 실행 때 핸드셰이크 없이 바로 명령을 보낼 수 있습니다. 캐시가 낡았으면 차량이 새 세션 정보를 오류와 함께 돌려주므로 자동 복구됩니다.
