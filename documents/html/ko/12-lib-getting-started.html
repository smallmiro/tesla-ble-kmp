12. 라이브러리 시작하기

M3의 전체 흐름을 따라갑니다. 라이브러리를 만들고, 키를 얻고, 차량을 찾고, 연결하고, 상태를 읽고, 연결을 끊습니다. 키 등록은 M4에서 추가되므로, 지금 예제는 등록된 키가 필요 없는 조회만 사용합니다.

이 페이지의 내용
  1. 흐름
  2. 다섯 가지 규칙
  3. Kotlin (Android)
  4. Swift (iOS)
  5. 다음 단계

흐름

  1. 라이브러리를 만듭니다. TeslaBle.create(platform, config)를 앱마다 한 번 호출합니다.
  2. 키를 얻습니다. ble.keys.getOrCreate()는 휴대폰의 P-256 키를 반환하며, 처음 호출할 때 보안 하드웨어에 키를 만듭니다.
  3. 차량을 찾습니다. ble.scan(vin)이 차량의 광고를 내보내면 첫 번째 것을 사용합니다.
  4. 연결합니다. ble.connect(vin, key, advertisement)는 Vehicle을 반환합니다.
  5. 읽습니다. vehicleStatus(), keySummary(), listKeys().
  6. 정리합니다. vehicle.disconnect()를 호출하고, 앱이 끝나면 ble.close()를 호출합니다.

다섯 가지 규칙

  • 결과는 값입니다. 차량이나 키 보관소에 대한 모든 호출은 VehicleResult(Success, Uncertain, Failure)를 반환합니다. 호출한 쪽의 코루틴이 취소된 경우를 빼고는 예외를 던지지 않습니다.
  • 앱마다 TeslaBle 하나. 다 쓰면 close()를 호출하세요. 아직 연결된 차량이 있으면 함께 연결을 끊습니다.
  • 항상 연결을 끊으세요. 링크가 이미 끊겼더라도 vehicle.disconnect()를 호출하세요. 세션 캐시를 저장하고, 세션 키를 지우고, 차량의 BLE 슬롯을 비웁니다. 두 번 호출해도 괜찮습니다.
  • 읽기에는 키가 없어도 됩니다. 세 가지 조회에는 connect(vin, key = null)로 충분합니다. 세션을 시작하려면 키가 필요합니다.
  • 디버그 로깅은 개발 중에만. DebugLogger()는 플랫폼 로그에 기록합니다. 릴리스 빌드에서는 빼세요.

Kotlin (Android)

import dev.mirolab.teslable.*
import dev.mirolab.teslable.model.*
import dev.mirolab.teslable.port.*
import kotlinx.coroutines.flow.first

suspend fun demo(context: android.content.Context, vinText: String) {
    val vin = Vin.parseOrNull(vinText) ?: return              // 17자 형식 검사
    val ble = TeslaBle.create(
        PlatformContext(context),
        TeslaBleConfig.default(logger = DebugLogger()),         // 개발용 로거, 릴리스 빌드에서는 사용하지 않음
    )
    try {
        val key = when (val r = ble.keys.getOrCreate()) {       // 기본 별칭, 하드웨어 우선
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: KeyStoreError
        }

        // 첫 번째 광고를 사용합니다. 시간 제한은 호출자가 정합니다(예: withTimeoutOrNull).
        val event = ble.scan(vin).first()
        val target = (event as? ScanEvent.Found)?.advertisement ?: return   // Failed이면 event.error 확인

        val vehicle = when (val r = ble.connect(vin, key, target)) {
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: TransportError 등
        }
        try {
            println(vehicle.vehicleStatus())                    // println 대신 UI에 표시
            println(vehicle.listKeys())
        } finally {
            vehicle.disconnect()                                // 슬롯을 비움, 링크가 끊긴 뒤에도 호출
        }
    } finally {
        ble.close()                                             // suspend, 아직 연결된 차량이 있으면 연결을 끊음
    }
}

이 호출들 전에 BLUETOOTH_SCAN과 BLUETOOTH_CONNECT를 런타임에 요청하세요. 플랫폼 노트를 참고하세요.

Swift (iOS)

SKIE는 suspend 함수를 async throws로, Flow를 AsyncSequence로 바꾸고, switch onEnum(of:)로 결과의 모든 경우를 다룰 수 있게 합니다. 코드 구조는 samples/ios/Sources/SampleModel.swift와 같습니다.

import Teslable

let ble = TeslaBle.companion.create(
    platform: PlatformContext(),
    config: TeslaBleConfig.companion.default(logger: DebugLogger())
)

func run(vinText: String) async {
    guard let vin = Vin.companion.parseOrNull(value: vinText) else { return }   // 잘못된 형식

    // 1) 키
    var key: VehicleKey?
    do {
        let result = try await ble.keys.getOrCreate(alias: VehicleKeyStoreCompanion.shared.DEFAULT_ALIAS, policy: .preferHardware)
        switch onEnum(of: result) {
        case .success(let s): key = s.value as? VehicleKey
        case .uncertain(let u): print("불확실: \(u.error.message)")
        case .failure(let f): print("실패: \(f.error.message)")
        }
    } catch { print("오류: \(error)") }

    // 2) 스캔(첫 번째 광고에서 멈춤, 시간 제한은 Task를 취소해서 설정)
    for await event in ble.scan(vin: vin) {
        switch onEnum(of: event) {
        case .found(let f): print("\(f.advertisement.localName.value) rssi=\(f.advertisement.rssi)")
        case .failed(let e): print("스캔 실패: \(e.error.message)")
        }
        break
    }

    // 3) 연결과 조회
    do {
        let connected = try await ble.connect(vin: vin, key: key, target: nil, options: ConnectOptions(timeout: nil))
        switch onEnum(of: connected) {
        case .success(let s):
            guard let vehicle = s.value as? Vehicle else { return }
            let status = try await vehicle.vehicleStatus(timeout: nil)
            switch onEnum(of: status) {
            case .success(let v): print("상태: \(String(describing: v.value))")
            case .uncertain(let u): print("불확실: \(u.error.message)")   // 다시 조회, 재전송하지 않음
            case .failure(let f): print("실패: \(f.error.message)")
            }
            try await vehicle.disconnect()
        case .uncertain(let u): print("불확실: \(u.error.message)")
        case .failure(let f): print("실패: \(f.error.message)")
        }
    } catch { print("오류: \(error)") }
}

target: nil이면 connect가 직접 스캔합니다. Info.plist에 NSBluetoothAlwaysUsageDescription을 추가하세요. 플랫폼 노트를 참고하세요.

다음 단계

  • 차량에 키를 등록하는 기능은 M4에서 추가됩니다(13. 키와 페어링). 그때까지는 vehicleStatus(), keySummary(), listKeys()에 connect(vin, key = null)로 충분합니다.
  • 링크는 vehicle.connection으로, 세션은 vehicle.sessions로 관찰하세요. 둘 다 StateFlow입니다. 링크가 Disconnected를 알려도 disconnect()는 직접 호출하세요.
