2. 시작하기

준비물

  • Go 1.23 이상 (go.mod의 go 1.23, CI는 1.23.0으로 테스트). Docker 이미지도 golang:1.23.0으로 빌드됩니다.
  • macOS 또는 Linux. BLE는 이 두 플랫폼만 지원합니다. Windows에서는 BLE 외 기능만 빌드됩니다.
  • Bluetooth 어댑터가 있는 컴퓨터, 그리고 차량의 VIN(차량 화면 Controls > Software에서 확인. 17자, 영문+숫자).
  • 키 페어링을 위해 차량 NFC 카드(또는 키포브)와 차량 안에서 화면을 조작할 수 있는 상황.
  • 인터넷 경로를 쓰려면 Tesla 개발자 계정과 OAuth 액세스 토큰. BLE만 쓸 때는 불필요합니다.

설치

소스에서 빌드

cd vehicle-command
go get ./...        # 의존성 다운로드
go build ./...      # 전체 컴파일 (도구 + 예제)
go install ./...    # $GOBIN (기본 ~/go/bin)에 도구 설치

go install 후 다음 실행 파일이 PATH에 놓입니다.

tesla-controlBLE 또는 인터넷으로 차량에 명령 전송. 인자 없이 실행하면 대화형 셸
tesla-auth-tokenOAuth 토큰을 키링에 저장 (토큰을 발급받지는 않음)

저장소의 Makefile도 사용할 수 있습니다: make install(go install ./cmd/...), make test, make build, make linters(golangci-lint), make proto-gen(protoc 필요). ./check-all.sh는 build/test/vet/fmt를 한 번에 검사합니다.

Docker

BLE는 컨테이너에서 쓰기 어렵기 때문에 Docker 이미지는 주로 HTTP 프록시용입니다. 기본 엔트리포인트는 tesla-http-proxy이고 --entrypoint로 바꿀 수 있습니다.

docker pull tesla/vehicle-command:latest
docker run tesla/vehicle-command:latest --help
docker run --entrypoint tesla-keygen tesla/vehicle-command:latest --help

환경 변수 설정

모든 CLI 도구는 pkg/cli를 공유하며 명령줄 플래그 대신 환경 변수를 읽습니다. 플래그가 우선하고, 비어 있는 값만 환경 변수로 채워집니다.

export TESLA_KEY_NAME=$(whoami)            # 키링에서 개인 키를 찾는 이름
export TESLA_VIN=5YJ30123456789ABC          # 대상 차량 VIN
export TESLA_CACHE_FILE=~/.tesla-cache.json # 세션 캐시 (생략 시 ~/.tesla-cache.json)
# 인터넷 경로를 쓸 때만:
export TESLA_TOKEN_NAME=$(whoami)           # 키링에서 OAuth 토큰을 찾는 이름
변수대응 플래그의미
TESLA_KEY_NAME-key-name시스템 키링 안의 개인 키 항목 이름 (실제 항목 키는 vehicleCommandKey.<이름>)
TESLA_KEY_FILE-key-filePEM 파일에서 개인 키 로드. 키링 대신 사용

TESLA_KEYRING_TYPE-keyring-type키링 백엔드 강제 지정. tesla-keygen -h에 OS별 지원 값 표시
TESLA_KEYRING_PATH-keyring-file-dir파일 기반 키링 디렉터리 (기본 ~/.tesla_keys)
TESLA_KEYRING_PASSWORD-파일 키링/키체인 비밀번호. 비어 있으면 터미널에서 프롬프트
TESLA_KEYRING_DEBUG-keyring-debug키링 디버그 로그
TESLA_VERBOSE-debug / -verbosetesla-control, tesla-http-proxy의 상세 로그. false/0 이외의 값이면 켜짐

개인 키 생성

방법 A: tesla-keygen (권장)

export TESLA_KEY_NAME=$(whoami)
tesla-keygen create > public_key.pem
cat public_key.pem
# -----BEGIN PUBLIC KEY-----
# MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
# -----END PUBLIC KEY-----
  • NIST P-256 개인 키를 생성해 OS 키링(macOS는 로그인 키체인)에 저장하고, PKIX PEM 형식의 공개 키를 stdout에 출력합니다. -output 파일로 파일에 쓸 수도 있습니다.
  • 이미 같은 이름의 키가 있으면 덮어쓰지 않고 기존 공개 키만 다시 출력합니다. 강제로 새로 만들려면 -f.
  • -key-file private.pem을 주면 키링 대신 파일에 저장합니다(EC PRIVATE KEY PEM, 0600).
하위 명령동작
create키 생성 후 저장, 공개 키 출력. 기존 키가 있으면 재사용(-f로 덮어쓰기)
export키링의 개인 키를 EC PRIVATE KEY PEM으로 stdout에 출력
migrate-key-file의 PEM 개인 키를 -key-name의 키링 항목으로 옮김
delete키링에서 키 삭제

방법 B: OpenSSL

키링을 쓰지 않고 파일로만 관리하려면 examples/ble/doc.go에 있는 방법대로 만듭니다.

openssl ecparam -genkey -name prime256v1 -noout > private.pem
openssl ec -in private.pem -pubout > public.pem
export TESLA_KEY_FILE=$PWD/private.pem   # 또는 매번 -key-file private.pem
개인 키 보호

개인 키가 유출되면 차량을 잠금 해제하고 운전할 수 있습니다. 파일로 보관한다면 권한을 0600으로 유지하고 저장소에 커밋하지 마세요. protocol.LoadPrivateKey는 암호화되지 않은 PKCS#8/SEC1 PEM만 읽습니다. TLS 서버 키와 명령 인증 키를 같은 키로 쓰면 tesla-http-proxy가 시작을 거부합니다.

차량에 키 페어링

공개 키를 차량 키체인(whitelist)에 등록해야 차량이 명령을 받아들입니다. BLE에서는 NFC 카드로 승인하는 add-key-request를 사용합니다. 이 요청 자체는 인증이 필요 없으므로 아직 페어링되지 않은 키로도 보낼 수 있습니다.

  1. 차 안에 앉는다. 노트북의 Bluetooth를 켜고 NFC 카드(또는 키포브)를 준비합니다. 차량은 동시에 최대 3개의 BLE 연결만 유지하므로 다른 폰 키가 많이 연결되어 있으면 스캔 결과가 Connectable=false일 수 있습니다.
  2. 요청을 보낸다. 
    export TESLA_VIN=<VIN>
tesla-control -ble add-key-request public_key.pem owner cloud_key
# Sent add-key request to <VIN>. Confirm by tapping NFC card on center console.
    프로그램은 요청을 전송하자마자 종료합니다. 종료했다고 승인이 끝난 것은 아닙니다.
  3. NFC 카드를 센터 콘솔(카드 리더 위치)에 댄다. 차량 화면에 새 키 승인 확인 창이 뜹니다.
  4. 화면에서 Confirm을 누른다. Locks 화면에 새 키가 표시됩니다.
  5. 확인한다. tesla-control -ble list-keys로 등록된 공개 키, 역할, 폼팩터를 확인하거나 tesla-control -ble session-info public_key.pem infotainment가 성공하는지 봅니다(Infotainment까지 동기화되면 성공).

add-key-request PUBLIC_KEY ROLE FORM_FACTOR 인자:

인자허용 값설명
PUBLIC_KEY파일 경로공개 키 PEM. 대응 개인 키 PEM, 65바이트 바이너리, 130자 hex 포인트도 허용(protocol.LoadPublicKey)
ROLEowner, driver, fm, vehicle_monitor, charging_managerkeys.Role의 ROLE_ 접두사를 뺀 소문자. 자기 컴퓨터용이면 보통 owner
FORM_FACTORnfc_card, ios_device, android_device, cloud_key차량 UI에 표시될 종류. 서드파티 앱/서버 키는 cloud_key
이미 Owner 키가 있다면

페어링된 Owner 키로 다른 키를 NFC 없이 추가할 수 있습니다: tesla-control -ble -key-file owner.pem add-key new_public.pem driver cloud_key. 삭제는 remove-key new_public.pem. 인터넷 경로에서는 rename-key로 차량 화면에 보이는 이름을 바꿀 수 있습니다(OAuth 필요).

페어링이 실패하는 흔한 이유
  • 카드 탭 시간 초과: WHITELISTOPERATION_INFORMATION_LOCAL_ENTITY_AUTH_FAILED_TIMED_OUT_WAITING_FOR_TAP. 요청 후 바로 카드를 대세요.
  • 화면에서 거부/취소: …UI_DENIED, …CANCELLED.
  • 발렛 모드 중: …LOCAL_ENTITY_AUTH_FAILED_VALET_MODE.
  • 키체인 가득 참: MESSAGEFAULT_ERROR_KEYCHAIN_IS_FULL 또는 WHITELISTOPERATION_INFORMATION_WHITELIST_FULL. 기존 키를 지워야 합니다.
  • 이미 등록된 키: …ATTEMPTING_TO_ADD_KEY_THAT_IS_ALREADY_ON_THE_WHITELIST. 정상입니다.

첫 BLE 명령

tesla-control -ble lock
tesla-control -ble unlock
tesla-control -ble body-controller-state   # 잠금/도어/트렁크/수면 상태 JSON. Infotainment가 자고 있어도 동작
tesla-control -ble list-keys               # 등록된 키 목록
tesla-control -ble climate-on              # Infotainment 명령. 차량이 잠들어 있으면 먼저 wake
tesla-control -ble wake                    # VCSEC에 웨이크업 요청
tesla-control -ble state charge            # 충전 상태 JSON (Infotainment 필요)
  • -ble는 OAuth 환경 변수가 설정되어 있어도 BLE 연결을 강제합니다. OAuth 변수가 없으면 VIN만으로 자동으로 BLE를 선택하므로 생략해도 됩니다.
  • 연결 제한 시간은 -connect-timeout(기본 20s), 명령 제한 시간은 -command-timeout(기본 5s)입니다. 스캔이 느린 환경에서는 -connect-timeout 60s처럼 늘리세요.
  • 인자 없이 tesla-control -ble을 실행하면 > 프롬프트의 대화형 셸이 뜹니다. 연결과 핸드셰이크를 한 번만 하고 여러 명령을 보낼 수 있습니다. exit로 종료.
  • tesla-control help <명령>으로 인자 설명을 볼 수 있습니다. 전체 목록은 7. 명령 레퍼런스.
도메인 제한으로 지연 줄이기

기본적으로 StartSession은 VCSEC와 Infotainment 두 도메인과 병렬로 핸드셰이크합니다. VCSEC 명령만 쓸 때는 -domain vcsec를 주면 Infotainment를 깨우지 않아 빠르고, 차량이 잠들어 있어도 실패하지 않습니다. wake와 body-controller-state는 CLI가 자동으로 VCSEC만 사용합니다.

디버그 출력과 세션 캐시

-debug로 송수신 바이트 보기

tesla-control -ble -debug list-keys
# 2023-12-13T14:41:13-08:00 [debug] Creating new BLE adapter
# 2023-12-13T14:41:13-08:00 [debug] Dialing to xx:xx:xx:xx:xx:xx (S1a87a5a75f3df858C)...
# 2023-12-13T14:41:13-08:00 [debug] MTU size: 517
# 2023-12-13T14:41:13-08:00 [info ] Connected to vehicle BLE
# 2023-12-13T14:41:13-08:00 [debug] TX: 320208023a1212100a7962c1...
# 2023-12-13T14:41:13-08:00 [debug] RX: ...

TX:/RX: 뒤의 hex는 길이 프리픽스를 뺀 RoutableMessage입니다. protoc로 디코딩할 수 있습니다. 로그는 stderr로 나가며 TESLA_VERBOSE=1로도 켤 수 있습니다.

세션 캐시

tesla-control은 매 실행마다 새 프로세스라서 캐시가 없으면 매번 핸드셰이크를 합니다. TESLA_CACHE_FILE(기본 ~/.tesla-cache.json)에 도메인별 세션 정보가 저장되고 다음 실행에서 Session for DOMAIN_VEHICLE_SECURITY loaded from cache 로그와 함께 바로 명령을 보냅니다. 캐시가 낡았으면(차량 재부팅 등) 첫 명령이 실패하면서 차량이 새 세션 정보를 보내 주고 자동으로 재시도합니다. 캐시 파일은 개인 키에 종속되며 다른 키로 쓰면 그냥 실패 후 갱신됩니다. 파일에는 공유 비밀이 직접 들어 있지는 않지만 접근 권한을 제한하세요.

Linux 추가 설정

Linux 구현은 HCI 소켓을 직접 열고 초기화 과정에서 HCIDEVDOWN을 호출하므로 CAP_NET_ADMIN 권한이 필요합니다. 권한이 없으면 operation not permitted가 발생하고 CLI가 다음 안내를 출력합니다.

Failed to initialize BLE adapter:
        ...operation not permitted
Try again after granting this application CAP_NET_ADMIN or running with root:

        sudo setcap 'cap_net_admin=eip' "$(which tesla-control)"
  • setcap은 실행 파일 단위로 적용되므로 go install로 바이너리를 다시 빌드하면 다시 설정해야 합니다.
  • 어댑터가 여럿이면 -bt-adapter hci1처럼 지정합니다(hci0~hci15). 기본은 hci0. 잘못된 형식은 ErrAdapterInvalidID.
  • bluetoothd가 같은 어댑터를 잡고 있어 스캔이 안 되면 sudo hciconfig hci0 down 후 재시도하거나 전용 어댑터를 쓰세요. 이 SDK는 BlueZ D-Bus가 아니라 raw HCI를 사용합니다.

인터넷 경로로 보내기

같은 개인 키로 인터넷 경로도 사용할 수 있습니다. 차이는 OAuth 토큰이 필요하고, 공개 키가 Tesla 개발자 포털에 등록된 도메인과 연결되어 있어야 하며, 인증 방식이 HMAC-SHA256이라는 점입니다.

  1. OAuth 토큰을 발급받는다. Fleet API 문서의 서드파티 토큰 절차를 따릅니다. 이 저장소에는 토큰을 발급하는 도구가 없습니다.
  2. 토큰을 키링에 저장한다. 
    export TESLA_TOKEN_NAME=$(whoami)
tesla-auth-token < token.txt          # 또는 tesla-auth-token token.txt
  3. 공개 키를 도메인에 등록하고 차량 소유자가 승인한다. 소유자는 Tesla 앱(4.27.3+)에서 https://tesla.com/_ak/<your_domain> 링크를 열어 승인합니다. 개인 차량이라면 위의 BLE 페어링으로 등록한 키를 그대로 써도 됩니다.
  4. 명령을 보낸다. -ble를 빼면 OAuth 설정이 있을 때 자동으로 인터넷 경로를 선택합니다. 
    tesla-control lock
tesla-control product-info          # 계정 명령 (VIN 불필요)
tesla-control get api/1/vehicles/$TESLA_VIN/vehicle_data

차량이 잠들어 있으면 Fleet API가 408/503을 돌려주고 SDK는 ErrVehicleNotAwake를 반환합니다. tesla-control wake가 api/1/vehicles/<vin>/wake_up을 호출해 state == "online"이 될 때까지 10초 간격으로 폴링합니다.
