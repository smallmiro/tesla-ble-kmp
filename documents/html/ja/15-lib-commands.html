15. コマンド

Vehicle はセッションの開始と終了、12 個のセキュリティコントローラーコマンド (ロック、トランク、ウェイクアップ)、そして 51 個のインフォテインメントコマンドを送れます: 空調、充電と電源、ウィンドウとサンルーフ、ホーンとライト、セントリーとバレーモード、メディア、ソフトウェアアップデート、ping()。このページではすべてを一覧にします。getState() によるインフォテインメント状態の読み取りも使えます。14. 車両状態の取得 を参照してください。

現在使えるもの

呼び出し動作
startSession(domains, timeout)VCSEC と Infotainment (デフォルトでは両方) のハンドシェイクを並行して実行します。セッションキャッシュからすでに復元されたドメインは、車両に問い合わせずに成功します。登録済みのキーが必要です。電話のロックがキーを妨げると (ロック解除中にだけ使える iOS の Secure Enclave のキー)、車両が応答するとすぐに KeyStoreError.Locked で失敗し、再試行しません (13)。デフォルトのタイムアウトは 20 秒です
disconnect()セッションキャッシュを保存し、セッションキーを消去してリンクを閉じます。複数回呼んでも安全です

startSession の実行中、vehicle.sessions は Handshaking を示します。終了後は Ready に、失敗またはキャンセルされた場合は再び None になります。

すべてのコマンドに共通する動作

  • コマンドはドメインのセッション上で AES-GCM により暗号化と認証が行われ、5 秒で失効します。
  • どのコマンドもセッションを開始したり車両を起こしたりしません。対応する領域のセッションがないと、コマンドは Failure(NoSession) を返し、何も送りません。
  • 一時的な失敗は 1 秒ごとに自動でリトライされます。すでに実行された可能性のあるコマンドが再送されることは 決して ありません。
  • Bluetooth 書き込みが失敗し、ライブラリが同じバイト列をもう一度書き込んだ場合、コマンドは再び署名されません。リトライを意味するエラーやメッセージ自体の拒否 (例: KeyNotPaired) は結果として扱われず、結果を決める応答 (最初のコピーへの遅れた応答、または最初のコピーが届かなかった場合の再度書き込んだコピーの成功) が時間内に届かなければ、呼び出しは Uncertain(Timeout) を返します。16. エラー処理 を参照してください。
  • セキュリティコントローラーのコマンドは接続ごとに 1 つずつ実行されます。インフォテインメントのコマンドは並行して実行できます。
  • Uncertain の結果は「状態を読み取り、再送しない」という意味です。16. エラー処理 を参照してください。

セキュリティコントローラー (M4)

12 個のメソッドはすべて認証付きで VCSEC セッションが必要です。セッションがないと Failure(NoSession) を返すので、先に startSession(setOf(VehicleDomain.VCSEC)) を実行してください。各メソッドは任意の timeout (デフォルト 5 秒) を受け取り、VehicleResult<Unit> を返します。

インフォテインメント (M5)

51 個のメソッド (空調 12、充電と電源 19、ボディ 5、セキュリティ 4、メディア 8、ソフトウェアアップデート 2、ping()) はすべてインフォテインメントのセッション上で認証され、任意の timeout (デフォルト 5 秒) を受け取り、VehicleResult<Unit> を返します。Go 原本と同じく、成功の応答にアプリが必要とする内容はありません。コマンドはシミュレートした車両に対する自動テストで確認しており、実車ではまだ 1 つも確認していません (#118)。

送信する前に

  1. インフォテインメントのセッションを開始します: startSession(setOf(VehicleDomain.INFOTAINMENT))、または両方のドメイン。セッションがないと、コマンドは Failure(NoSession) を返し、何も送りません。
  2. 車両が起きていることを確認します。ライブラリは車両を起こしません。インフォテインメントがスリープしていると、コマンドは送られても何も返らず、結果は Uncertain(Timeout) になります。先に vehicleStatus() を読みます (セッションは不要で、車両を起こすこともありません)。ASLEEP なら 14、A8.2 のように車両を起こし (VCSEC セッション、wakeUp()、AWAKE になるまで待つ)、インフォテインメントのセッションを開始します。
  3. コマンドを送り、結果を確認します:
結果意味アプリの対応
Success車両がコマンドを受け付けた新しい状態を表示するには getState で読みます (Uncertain の後)
Uncertain車両が実行した可能性がある: 時間内に応答がない (インフォテインメントがスリープ、応答の喪失)、ライブラリが再度書き込んだ失敗した書き込み、または読み取れない応答再送しないでください。 getState で状態を読み、その内容で判断します。低消費電力モード、アクセサリー電源、ホーン、ライトは読み戻せません
Failure(InvalidArgument)送信前のチェックに失敗し、何も送られていない引数を直します (次の節)
Failure(InfotainmentRejected)車両が拒否した一般的なメッセージを表示します。reason は車両自身の文言なので、ログに残さないでください
NoSession, NotConnected, other errors呼び出し順が誤っているか、リンクが切れた16. エラー処理 を参照してください

送信前のチェック

ライブラリは Go 原本が検査するものだけを検査します。検査はセッションの確認より前に行われるため、不正な引数はセッションがなくても InvalidArgument として報告され、何も送られません。

メソッドルールメッセージ (detail)
setSeatCooler前席のみ: FRONT_LEFT または FRONT_RIGHTinvalid seat position for seat cooler: <SEAT>
scheduleDeparture出発時刻は午前 0 時から 0〜1440 分 (両端を含む)invalid departure time: <n> minutes after midnight (expected 0..1440)
enableValetModePIN は ASCII の数字 0–9 のちょうど 4 桁です。ほかの文字体系の数字や全角数字は拒否されますPIN codes must be four digits (Go 原本のメッセージで、PIN 自体はエラーにもログにも現れません)
setVolume音量は 0〜10 (両端を含む) で、NaN ではないことinvalid volume (should be in [0, 10]) (Go 原本のメッセージで、Go 原本は NaN を通しますが、このライブラリは拒否します)

それ以外はすべて与えられたまま車両に送られ、車両が判断します: 温度、充電上限、電流、その他の時刻、スケジュールのフィールド、サンルーフの位置、ソフトウェアアップデートの遅延時間。autoSeatAndClimate は、Go 原本が扱わないシートを黙って除外します。

Ping

メソッド要件ペイロード例 (hex)備考

ping() は何も変えず、何も読みません。Success は、車両がキーを知っていてインフォテインメントが応答したことを意味し、コマンドを続けて送る前の手軽な確認になります。すべてのコマンドと同じインフォテインメントのセッションと、起きている車両が必要です。Uncertain(Timeout) は応答がないこと (スリープ中または喪失) を意味します。何も変えないので、アプリは Uncertain の後に再度呼んでかまいません。ライブラリが自分で再送することはありません。データを読むには getState を使います。

Uncertain の後

再送せず、コマンドが変える状態を読み取ります。フィールド名は公式のプロトコル定義に基づいており、コマンドが実車でどのフィールドを変えるかはまだ確認していません (#118)。読み取り自体が Uncertain で返ることもあり (インフォテインメントがスリープ、応答が大きすぎる)、その場合は後の読み取りが成功するまでコマンドの結果は不明のままです。

Kotlin の例

import com.tesla.generated.carserver.common.ChargeSchedule
import com.tesla.generated.carserver.common.MediaPlaybackStatus
import dev.mirolab.teslable.Vehicle
import dev.mirolab.teslable.model.ChargingPolicy
import dev.mirolab.teslable.model.SeatClimateLevel
import dev.mirolab.teslable.model.SeatPosition
import dev.mirolab.teslable.model.StateCategory
import dev.mirolab.teslable.model.VehicleError
import dev.mirolab.teslable.model.VehicleResult

// Before: an INFOTAINMENT session (startSession) and an awake vehicle (14-lib-reading-state.md A8.2).
suspend fun warmUp(vehicle: Vehicle): String {
    when (val result = vehicle.climateOn()) {
        is VehicleResult.Success -> Unit
        is VehicleResult.Uncertain -> {
            // The vehicle may have turned climate on. Never resend: read the state.
            val state = vehicle.getState(StateCategory.CLIMATE)
            val on = (state as? VehicleResult.Success)?.value?.climate_state?.is_climate_on
            return if (on == true) "climate on" else "unknown, read again later"
        }
        is VehicleResult.Failure -> return "not sent or refused: ${result.error.message}"
    }
    // Handle these results the same way.
    vehicle.setClimateTemp(driverCelsius = 22.0f, passengerCelsius = 21.5f)

}

            val state = vehicle.getState(StateCategory.CHARGE)
            val departAt = (state as? VehicleResult.Success)?.value?.charge_state?.scheduled_departure_time_minutes

            }
    }

        ChargeSchedule(
            id = scheduleId, // the Go CLI uses the current Unix time
            name = "Home",
            days_of_week = 127, // every day
            start_enabled = true,
            start_time = 120, // 02:00
            enabled = true,
            latitude = latitude,
            longitude = longitude,
        )
    return when (val added = vehicle.addChargeSchedule(schedule)) {
        is VehicleResult.Success -> "departure and schedule set"

            val state = vehicle.getState(StateCategory.CHARGE_SCHEDULE)

Swift の例

Swift では timeout: を含むすべての引数を渡します。スケジュールはすべてのフィールドと unknownFields で組み立てます。詳細は 17. プラットフォームノート にあります。この形はフレームワークに対する Swift の型チェックを通っていますが、Swift のプログラムで実行したものではありません。

func warmUp(vehicle: Vehicle) async throws -> String {
    let result = try await vehicle.climateOn(timeout: nil)
    switch onEnum(of: result) {
    case .success:
        break
    case .uncertain:
        // The vehicle may have turned climate on. Never resend: read the state.
        let state = try await vehicle.getState(category: .climate, timeout: nil)
        if case .success(let s) = onEnum(of: state), let data = s.value as? VehicleData,
           data.climate_state?.is_climate_on?.boolValue == true {
            return "climate on"
        }
        return "unknown, read again later"
    case .failure(let f):
        return "not sent or refused: \(f.error.message)"
    }
    _ = try await vehicle.setClimateTemp(driverCelsius: 22.0, passengerCelsius: 21.5, timeout: nil)
    _ = try await vehicle.setSeatHeater(levels: [.frontLeft: .high, .frontRight: .low], timeout: nil)
    return "climate on"
}

func planCharging(vehicle: Vehicle, scheduleId: Int64, latitude: Float, longitude: Float) async throws -> String {
    // Leave at 08:00, off-peak charging ends at 06:00 (minutes after the vehicle's local midnight).
    let departure = try await vehicle.scheduleDeparture(
        departAtMinutes: 480, offPeakEndMinutes: 360, preconditioning: .allDays, offPeak: .weekdays, timeout: nil)
    switch onEnum(of: departure) {
    case .success:
        break
    case .uncertain:
        // The vehicle may have stored it. Never resend: read the state and stop here.
        let state = try await vehicle.getState(category: .charge, timeout: nil)
        if case .success(let s) = onEnum(of: state), let data = s.value as? VehicleData,
           data.charge_state?.scheduled_departure_time_minutes?.int32Value == 480 {
            return "departure set, schedule not added"
        }
        return "unknown, read again later"
    case .failure(let f):
        if case .invalidArgument = onEnum(of: f.error) {
            return "departure time outside 0..1440 minutes; nothing was sent"
        }
        return "not sent or refused: \(f.error.message)"
    }
    let schedule = ChargeSchedule(
        id: scheduleId, name: "Home", days_of_week: 127, start_enabled: true, start_time: 120,
        end_enabled: false, end_time: 0, one_time: false, enabled: true,
        latitude: latitude, longitude: longitude, unknownFields: OkioByteString.companion.EMPTY)
    let added = try await vehicle.addChargeSchedule(schedule: schedule, timeout: nil)
    switch onEnum(of: added) {
    case .success:
        return "departure and schedule set"
    case .uncertain:
        // Never resend: look for the id in the charge schedules.
        let state = try await vehicle.getState(category: .chargeSchedule, timeout: nil)
        if case .success(let s) = onEnum(of: state), let data = s.value as? VehicleData,
           (data.charge_schedule_state?.charge_schedules ?? []).contains(where: { $0.id == scheduleId }) {
            return "departure and schedule set"
        }
        return "schedule unknown, read again later"
    case .failure(let f):
        return "schedule not sent or refused: \(f.error.message)"
    }
}
