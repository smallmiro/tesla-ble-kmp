13. Keys and Pairing

The phone needs its own key pair, and the car must list the public key before it accepts commands from it. The library creates and stores the key, reads the car's key list, and enrolls the key on the car: the user taps an NFC key card and confirms on the screen.

The key store

TeslaBle.keys is a VehicleKeyStore. Keys are found by an alias; most apps only need the default one.

CallReturnsWhat it does
getOrCreate(alias, policy)VehicleResult<VehicleKey>Returns the stored key, or creates a NIST P-256 key pair under the alias
get(alias)VehicleResult<VehicleKey?>Success(null) when there is no key
delete(alias)VehicleResult<Unit>Also succeeds when there is no key
  • The default alias is "teslable-default" (VehicleKeyStore.DEFAULT_ALIAS; in Swift VehicleKeyStoreCompanion.shared.DEFAULT_ALIAS).
  • An alias may use letters, digits, ., _ and -, up to 64 characters, and may not be . or ...
  • A VehicleKey is a handle. It exposes alias, protection and publicKey (65 bytes, 0x04 ‖ X ‖ Y). The private key never leaves the platform key store, and there is no export API.

Where the key lives

The policy argument decides whether software keys are acceptable. VehicleKey.protection tells you where the key actually ended up.

KeyPolicyBehaviour
PREFER_HARDWARE (default)Hardware first, software if hardware fails
REQUIRE_HARDWAREHardware only; otherwise KeyStoreError.HardwareUnavailable
SOFTWARE_ONLYSoftware only, for tests and emulators
KeyProtectionHardwareWhere
SECURE_ENCLAVEyesiOS Secure Enclave
STRONGBOXyesAndroid StrongBox
TEEyesAndroid Trusted Execution Environment
SOFTWAREnoWrapped by Android Keystore or kept in the iOS Keychain; in memory on the JVM

If a real device reports SOFTWARE, consider telling the user: the key is weaker than a hardware key.

Is my key enrolled?

vehicle.listKeys() works without a key and without waking the car. Compare the car's list with your public key:

val mine = key.publicKey.toByteArray()
val enrolled = when (val r = vehicle.listKeys()) {
    is VehicleResult.Success -> r.value.firstOrNull { it.publicKey?.toByteArray()?.contentEquals(mine) == true }
    else -> null                                   // Uncertain or Failure: unknown, ask again later
}
// enrolled?.role is the KeyRole, enrolled?.slot the whitelist slot

A key that is not enrolled can still connect and read. Starting a session with it fails with KeyNotPaired.

Deleting or replacing a key

  • keys.delete(alias) removes the key from the phone only. The car keeps listing the public key until it is removed on the car.
  • Saved sessions belong to one key. After the key changes, the next connection throws away the old sessions and starts a new handshake.
  • A corrupted stored key (KeyStoreError.PlatformFailure, stored key is corrupted) is never replaced on its own. Tell the user, call delete then getOrCreate, and enroll the new key on the car again. See Platform Notes.

Enrolling a key

The Go original sends the add-key request and does not read the reply. Reading the reply as PairingEvent values is new behaviour of this library and has not been checked on a real car yet.

CallReturnsWhat it does
addKeyRequest(publicKey, role, formFactor, timeout)Flow<PairingEvent>Asks the car to add the key (FR-022, FR-023). A cold flow: each collection sends one request. It is not signed, so no session is needed. timeout = null uses pairingTimeout (60 seconds). Requests run one at a time
sessionInfo(publicKey, domain, timeout)VehicleResult<SessionInfoSummary>Checks enrollment per domain (FR-024); the connection needs no key. Failure(KeyNotPaired) means the car does not list the key. Asking with the connection's own key also creates that domain's session, so sessions shows Ready(fromCache = false)
addKey(publicKey, role, formFactor, timeout)VehicleResult<Unit>An enrolled key with enough privileges adds another key without the NFC card (FR-027). Authenticated VCSEC; needs a VCSEC session
removeKey(publicKey, timeout)VehicleResult<Unit>Removes a key from the car (FR-026). Authenticated VCSEC; needs a VCSEC session
  • role defaults to KeyRole.OWNER; formFactor defaults to platformKeyFormFactor(): ANDROID_DEVICE on Android, IOS_DEVICE on iOS, CLOUD_KEY on the JVM (tests).
  • In Swift, Kotlin default arguments are not available: pass every argument (role:, formFactor:, timeout:), for example formFactor: .iosDevice.
  • addKey and removeKey can fail with InsufficientPrivileges (the connection's key may not manage keys, for example a Driver key), KeychainRejected(code) (for example WHITELIST_FULL), NoSession or InvalidArgument (role = UNKNOWN). Uncertain means the car may have changed its key list: check with listKeys() and do not resend.

Pairing events

PairingEventMeaningLast event
SentThe request was written. The user must tap an NFC key card on the center console and confirm on the screenno
WaitingForTapThe car reports that it is waiting (WAIT)no
AcceptedThe car accepted the key. Infotainment can take tens of seconds more to learn ityes
Rejected(error)The car refused: KeychainRejected, UnknownKeychainCode, VcsecRejected or UnknownVcsecErroryes
Unknown(raw)A frame that could not be decoded. raw is a copy of the bytesno
Failed(error)Not sent (NotConnected, write failure, InvalidArgument), or the link dropped while waitingyes
TimedOutNo final answer within timeout. The key may still have been enrolled: check with sessionInfoyes

After a last event the flow ends (isTerminal is true for them). Frames that carry neither a status nor an error, intermediate OK statuses and frames received before the request was sent are ignored.

Not verified on a real car

The reply format of add-key-request has not been observed on a real car yet (ADR-0009). If you receive Unknown(raw), please report raw as hex (no VIN) together with what the car did.

The pairing flow

  1. Create the key (keys.getOrCreate()) and connect with it.
  2. Collect vehicle.addKeyRequest(key.publicKey). Tell the user to tap the key card on the center console and confirm on the screen.
  3. After Accepted (or TimedOut), call sessionInfo(key.publicKey, VehicleDomain.INFOTAINMENT) every 3 seconds for up to 2 minutes. KeyNotPaired means "not yet": keep polling. Success means the key is enrolled and synced.
  4. Run startSession(setOf(VehicleDomain.VCSEC)), then send commands (15. Commands).

Kotlin

val key = (ble.keys.getOrCreate() as VehicleResult.Success).value
val vehicle = (ble.connect(vin, key) as VehicleResult.Success).value

vehicle.addKeyRequest(key.publicKey).collect { event ->
    when (event) {
        PairingEvent.Sent -> show("Tap the key card on the center console, then confirm on the screen")
        PairingEvent.WaitingForTap -> show("Waiting for the card")
        PairingEvent.Accepted -> show("Accepted, waiting for the car to sync")
        is PairingEvent.Rejected -> show("Rejected: ${event.error.message}")
        is PairingEvent.Unknown -> report(event.raw.joinToString("") { it.toUByte().toString(16).padStart(2, '0') })      // see the warning below
        is PairingEvent.Failed -> show("Failed: ${event.error.message}")
        PairingEvent.TimedOut -> show("No answer, checking enrollment")
    }
}

suspend fun waitUntilEnrolled(vehicle: Vehicle, key: VehicleKey): Boolean {
    val deadline = TimeSource.Monotonic.markNow() + 2.minutes
    while (deadline.hasNotPassedNow()) {
        when (val r = vehicle.sessionInfo(key.publicKey, VehicleDomain.INFOTAINMENT)) {
            is VehicleResult.Success -> return true
            is VehicleResult.Failure -> if (r.error != VehicleError.KeyNotPaired) return false
            is VehicleResult.Uncertain -> Unit                  // reply lost: ask again
        }
        delay(3.seconds)
    }
    return false
}

Swift

for await event in vehicle.addKeyRequest(publicKey: key.publicKey, role: .owner, formFactor: .iosDevice, timeout: nil) {
    switch onEnum(of: event) {
    case .sent: print("Tap the key card on the center console, then confirm on the screen")
    case .waitingForTap: print("Waiting for the card")
    case .accepted: print("Accepted, waiting for the car to sync")
    case .rejected(let r): print("Rejected: \(r.error.message)")
    case .unknown(let u): print("Unknown frame, \(u.raw.size) bytes")
    case .failed(let f): print("Failed: \(f.error.message)")
    case .timedOut: print("No answer, checking enrollment")
    }
}

// then, every 3 s for up to 2 minutes:
let r = try await vehicle.sessionInfo(publicKey: key.publicKey, domain: .infotainment, timeout: nil)
switch onEnum(of: r) {
case .success: print("enrolled")
case .failure(let f): print("not yet or failed: \(f.error.message)")   // KeyNotPaired: keep polling
case .uncertain: print("reply lost, ask again")
}

Roles (KeyRole) are OWNER, DRIVER, FLEET_MANAGER, VEHICLE_MONITOR, CHARGING_MANAGER, GUEST and SERVICE. Which commands each role may send is listed in 7. Command Reference.
