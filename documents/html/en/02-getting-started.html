2. Getting Started

Follow the steps in order, from installation to key generation, pairing a key with an NFC card, and sending your first BLE command.

Prerequisites

  • Go 1.23 or later (go 1.23 in go.mod; CI tests with 1.23.0). The Docker image is also built with golang:1.23.0.
  • macOS or Linux. BLE is supported only on these two platforms. On Windows, only the non-BLE features build.
  • A computer with a Bluetooth adapter, and the vehicle's VIN (found on the vehicle screen under Controls > Software; 17 alphanumeric characters).
  • For key pairing, the vehicle's NFC card (or key fob) and the ability to operate the screen from inside the vehicle.
  • For the internet path, a Tesla developer account and an OAuth access token. Not needed if you use BLE only.

Installation

Building from source

cd vehicle-command
go get ./...        # download dependencies
go build ./...      # compile everything (tools + examples)
go install ./...    # install tools into $GOBIN (default ~/go/bin)

After go install, the following executables are placed on your PATH.

ExecutableRole
tesla-keygenGenerates a private key for command authentication, stores it in the system keyring, and prints the public key
tesla-controlSends commands to the vehicle over BLE or the internet. Running it without arguments opens an interactive shell
tesla-auth-tokenStores an OAuth token in the keyring (does not issue tokens)
tesla-http-proxyREST API proxy server
tesla-jwsJWS signing/verification for Fleet Telemetry configuration
ble, unlockExample programs from examples/ (included in go install ./...)

You can also use the repository's Makefile: make install (go install ./cmd/...), make test, make build, make linters (golangci-lint), make proto-gen (requires protoc). ./check-all.sh runs build/test/vet/fmt checks in one go.

Docker

Because BLE is hard to use from a container, the Docker image is mainly for the HTTP proxy. The default entrypoint is tesla-http-proxy, which you can change with --entrypoint.

docker pull tesla/vehicle-command:latest
docker run tesla/vehicle-command:latest --help
docker run --entrypoint tesla-keygen tesla/vehicle-command:latest --help

Environment variables

All CLI tools share pkg/cli and read environment variables in place of command-line flags. Flags take precedence; only empty values are filled from environment variables.

export TESLA_KEY_NAME=$(whoami)            # name used to find the private key in the keyring
export TESLA_VIN=5YJ30123456789ABC          # target vehicle VIN
export TESLA_CACHE_FILE=~/.tesla-cache.json # session cache (defaults to ~/.tesla-cache.json if omitted)
# Only when using the internet path:
export TESLA_TOKEN_NAME=$(whoami)           # name used to find the OAuth token in the keyring
VariableCorresponding flagMeaning
TESLA_KEY_NAME-key-nameName of the private key entry in the system keyring (the actual entry key is vehicleCommandKey.<name>)
TESLA_KEY_FILE-key-fileLoads the private key from a PEM file. Used instead of the keyring
TESLA_TOKEN_NAME-token-nameName of the OAuth token entry in the keyring (oauthtoken.<name>)
TESLA_TOKEN_FILE-token-fileLoads the OAuth token from a file
TESLA_VIN-vinVIN
TESLA_CACHE_FILE-session-cachePath to the session cache JSON. Can be turned off with -disable-session-cache
TESLA_KEYRING_TYPE-keyring-typeForces a specific keyring backend. tesla-keygen -h shows the values supported per OS
TESLA_KEYRING_PATH-keyring-file-dirDirectory for the file-based keyring (default ~/.tesla_keys)
TESLA_KEYRING_PASSWORD-Password for the file keyring/keychain. If empty, you are prompted in the terminal

Generating a private key

Method A: tesla-keygen (recommended)

export TESLA_KEY_NAME=$(whoami)
tesla-keygen create > public_key.pem
cat public_key.pem
# -----BEGIN PUBLIC KEY-----
# MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
# -----END PUBLIC KEY-----
  • Generates a NIST P-256 private key, stores it in the OS keyring (the login keychain on macOS), and prints the public key to stdout in PKIX PEM format. You can also write it to a file with -output file.
  • If a key with the same name already exists, it is not overwritten; the existing public key is printed again. Use -f to force creation of a new one.
  • If you pass -key-file private.pem, the key is saved to a file instead of the keyring (EC PRIVATE KEY PEM, 0600).
SubcommandBehavior
createGenerates and stores a key, prints the public key. Reuses an existing key if present (overwrite with -f)
exportPrints the private key from the keyring to stdout as EC PRIVATE KEY PEM
migrateMoves the PEM private key in -key-file into the keyring entry -key-name
deleteDeletes the key from the keyring

Method B: OpenSSL

To manage keys only as files without a keyring, create them as described in examples/ble/doc.go.

openssl ecparam -genkey -name prime256v1 -noout > private.pem
openssl ec -in private.pem -pubout > public.pem
export TESLA_KEY_FILE=$PWD/private.pem   # or pass -key-file private.pem every time
Protecting the private key

Anyone who obtains the private key can unlock and drive the vehicle. If you keep it in a file, keep its permissions at 0600 and do not commit it to a repository. protocol.LoadPrivateKey reads only unencrypted PKCS#8/SEC1 PEM. If the TLS server key and the command authentication key are the same key, tesla-http-proxy refuses to start.

Pairing a key with the vehicle

The vehicle accepts commands only after the public key is registered in its keychain (whitelist). Over BLE, use add-key-request, which is approved with an NFC card. The request itself requires no authentication, so it can be sent with a key that is not yet paired.

  1. Sit inside the car. Turn on your laptop's Bluetooth and have the NFC card (or key fob) ready. The vehicle maintains at most 3 BLE connections at a time, so if many other phone keys are connected, the scan result may show Connectable=false.
  2. Send the request. 
    export TESLA_VIN=<VIN>
tesla-control -ble add-key-request public_key.pem owner cloud_key
# Sent add-key request to <VIN>. Confirm by tapping NFC card on center console.
    The program exits as soon as the request is sent. Exiting does not mean that approval is complete.
  3. Tap the NFC card on the center console (where the card reader is). A confirmation dialog for approving the new key appears on the vehicle screen.
  4. Press Confirm on the screen. The new key appears on the Locks screen.
  5. Verify. Check the registered public keys, roles, and form factors with tesla-control -ble list-keys, or see whether tesla-control -ble session-info public_key.pem infotainment succeeds (it succeeds once the key has been synchronized to Infotainment).

Arguments of add-key-request PUBLIC_KEY ROLE FORM_FACTOR:

ArgumentAllowed valuesDescription
PUBLIC_KEYFile pathPublic key PEM. The corresponding private key PEM, a 65-byte binary, or a 130-character hex point are also accepted (protocol.LoadPublicKey)
ROLEowner, driver, fm, vehicle_monitor, charging_managerLowercase keys.Role names without the ROLE_ prefix. Usually owner for your own computer
FORM_FACTORnfc_card, ios_device, android_device, cloud_keyThe type shown in the vehicle UI. Use cloud_key for third-party app/server keys
If you already have an Owner key

A paired Owner key can add other keys without NFC: tesla-control -ble -key-file owner.pem add-key new_public.pem driver cloud_key. Remove with remove-key new_public.pem. On the internet path, rename-key changes the name shown on the vehicle screen (requires OAuth).

Common reasons pairing fails
  • Card tap timed out: WHITELISTOPERATION_INFORMATION_LOCAL_ENTITY_AUTH_FAILED_TIMED_OUT_WAITING_FOR_TAP. Tap the card right after sending the request.
  • Rejected/cancelled on the screen: …UI_DENIED, …CANCELLED.
  • Valet mode is active: …LOCAL_ENTITY_AUTH_FAILED_VALET_MODE.
  • Keychain is full: MESSAGEFAULT_ERROR_KEYCHAIN_IS_FULL or WHITELISTOPERATION_INFORMATION_WHITELIST_FULL. You must remove an existing key.
  • Key already registered: …ATTEMPTING_TO_ADD_KEY_THAT_IS_ALREADY_ON_THE_WHITELIST. This is normal.

Your first BLE command

tesla-control -ble lock
tesla-control -ble unlock
tesla-control -ble body-controller-state   # lock/door/trunk/sleep state as JSON. Works even while Infotainment is asleep
tesla-control -ble list-keys               # list of registered keys
tesla-control -ble climate-on              # Infotainment command. If the vehicle is asleep, wake it first
tesla-control -ble wake                    # wake-up request to VCSEC
tesla-control -ble state charge            # charging state as JSON (requires Infotainment)
  • -ble forces a BLE connection even if OAuth environment variables are set. If no OAuth variables are set, BLE is selected automatically from the VIN alone, so you can omit it.
  • The connection timeout is -connect-timeout (default 20s) and the command timeout is -command-timeout (default 5s). In environments where scanning is slow, increase it, e.g. -connect-timeout 60s.
  • Running tesla-control -ble without arguments opens an interactive shell with a > prompt. You can connect and handshake once and then send multiple commands. Exit with exit.
  • tesla-control help <command> shows argument descriptions. For the full list, see 7. Command Reference.
Reducing latency by restricting domains

By default, StartSession handshakes with both domains, VCSEC and Infotainment, in parallel. When you use only VCSEC commands, passing -domain vcsec avoids waking Infotainment, so it is faster and does not fail even if the vehicle is asleep. For wake and body-controller-state, the CLI automatically uses only VCSEC.

Debug output and the session cache

Viewing sent/received bytes with -debug

tesla-control -ble -debug list-keys
# 2023-12-13T14:41:13-08:00 [debug] Creating new BLE adapter
# 2023-12-13T14:41:13-08:00 [debug] Dialing to xx:xx:xx:xx:xx:xx (S1a87a5a75f3df858C)...
# 2023-12-13T14:41:13-08:00 [debug] MTU size: 517
# 2023-12-13T14:41:13-08:00 [info ] Connected to vehicle BLE
# 2023-12-13T14:41:13-08:00 [debug] TX: 320208023a1212100a7962c1...
# 2023-12-13T14:41:13-08:00 [debug] RX: ...

The hex after TX:/RX: is the RoutableMessage without the length prefix. You can decode it with protoc. Logs go to stderr and can also be enabled with TESLA_VERBOSE=1.

Session cache

tesla-control is a new process on every run, so without a cache it performs a handshake every time. Per-domain session information is saved to TESLA_CACHE_FILE (default ~/.tesla-cache.json), and on the next run commands are sent immediately with the log line Session for DOMAIN_VEHICLE_SECURITY loaded from cache. If the cache is stale (for example, after a vehicle reboot), the first command fails, the vehicle sends new session information, and the command is retried automatically. The cache file is tied to the private key; if used with a different key, it simply fails and is then refreshed. The file does not directly contain the shared secret, but restrict access to it.

Additional Linux setup

The Linux implementation opens HCI sockets directly and calls HCIDEVDOWN during initialization, so it requires the CAP_NET_ADMIN capability. Without it, operation not permitted occurs and the CLI prints the following guidance.

Failed to initialize BLE adapter:
        ...operation not permitted
Try again after granting this application CAP_NET_ADMIN or running with root:

        sudo setcap 'cap_net_admin=eip' "$(which tesla-control)"
  • setcap applies per executable, so you must set it again whenever you rebuild the binary with go install.
  • If you have several adapters, specify one, e.g. -bt-adapter hci1 (hci0–hci15). The default is hci0. An invalid format yields ErrAdapterInvalidID.
  • If scanning does not work because bluetoothd holds the same adapter, run sudo hciconfig hci0 down and retry, or use a dedicated adapter. This SDK uses raw HCI, not BlueZ D-Bus.

Sending over the internet path

The same private key can also be used on the internet path. The differences are that an OAuth token is required, the public key must be associated with a domain registered on the Tesla developer portal, and the authentication method is HMAC-SHA256.

  1. Obtain an OAuth token. Follow the third-party token procedure in the Fleet API documentation. This repository has no tool for issuing tokens.
  2. Store the token in the keyring. 
    export TESLA_TOKEN_NAME=$(whoami)
tesla-auth-token < token.txt          # or tesla-auth-token token.txt
  3. Register the public key with your domain and have the vehicle owner approve it. The owner approves by opening the https://tesla.com/_ak/<your_domain> link in the Tesla app (4.27.3+). For a personal vehicle, you can simply use the key registered through BLE pairing above.
  4. Send a command. If you omit -ble and OAuth is configured, the internet path is selected automatically. 
    tesla-control lock
tesla-control product-info          # account command (no VIN needed)
tesla-control get api/1/vehicles/$TESLA_VIN/vehicle_data

If the vehicle is asleep, the Fleet API returns 408/503 and the SDK returns ErrVehicleNotAwake. tesla-control wake calls api/1/vehicles/<vin>/wake_up and polls every 10 seconds until state == "online".
