14. Reading Vehicle State

Three queries read the car's security controller (VCSEC) over BLE. They need no key, no session and no wake-up, because VCSEC answers even while the infotainment computer sleeps.

On this page
  1. The three queries
  2. What vehicleStatus() returns
  3. What the key queries return
  4. Connection and session state
  5. Sleep and wake-up

The three queries

CallReturnsGo original
vehicleStatus()Lock, doors, trunks, charge port, sleep state, presenceBodyControllerState
keySummary()Number of enrolled keys and which slots are usedKeySummary
listKeys()Every enrolled key with its public key, role and form factorKeySummary + KeyInfoBySlot
  • Each takes an optional timeout; without it the default command timeout (5 seconds) applies. For listKeys() the timeout covers all of its requests together.
  • The car handles one VCSEC request at a time per connection. A query that has to wait for another one spends part of its timeout waiting.
  • These are queries, so an Uncertain result can simply be asked again.

What vehicleStatus() returns

FieldValues
lockStateUNLOCKED, LOCKED, INTERNAL_LOCKED, SELECTIVE_UNLOCKED, UNKNOWN
closuresEight openings, each a ClosureState; all CLOSED if the car did not send them (it omits them when everything is closed, like the Go getters)
sleepStatusAWAKE, ASLEEP, UNKNOWN
userPresencePRESENT, NOT_PRESENT, UNKNOWN
tonneauPercentOpenCybertruck only; null otherwise

The eight openings are frontDriverDoor, frontPassengerDoor, rearDriverDoor, rearPassengerDoor, rearTrunk, frontTrunk, chargePort and tonneau. Each is CLOSED, OPEN, AJAR, OPENING, CLOSING, FAILED_UNLATCH or UNKNOWN.

Unknown values do not fail

When newer car firmware sends a value the library does not know yet, the field reads UNKNOWN instead of failing the query.

What the key queries return

TypeFieldMeaning
WhitelistSummarynumberOfEntriesHow many keys are enrolled
slotMask, occupiedSlotsWhich slots are used, as a bit mask and as a sorted list
WhitelistEntryslotSlot number
publicKey65-byte public key, or null if missing or malformed
keyIdSha1HexSHA-1 of the public key in hex, or null
role, formFactorFor example OWNER and IOS_DEVICE; see 13. Keys and Pairing

Connection and session state

These are properties of Vehicle that you observe, not questions sent to the car:

PropertyValues
connectionConnected, or Disconnected with the reason if known
sessionsFor VCSEC and INFOTAINMENT: None, Handshaking or Ready (with fromCache)
hasKeyWhether the connection was made with a key
vinThe VIN. Printing it shows a masked form; vin.value is the raw VIN, which should not go into logs

Sleep and wake-up

  • None of the three queries wakes the car. Use sleepStatus to show whether it is asleep.
  • Coming in M5: getState(category) reads the twelve infotainment categories (charge, climate, drive, location, closures, charge schedule, preconditioning schedule, tire pressure, media, media detail, software update, parental controls). It needs an enrolled key and an awake car.
  • Coming in M4: wakeUp(), which needs only the VCSEC session.
  • When a lock or trunk command (M4) comes back Uncertain, read vehicleStatus() again instead of sending the command a second time.
