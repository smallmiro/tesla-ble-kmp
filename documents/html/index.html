Tesla vehicle-command BLE Developer Manual

The developer manual for the vehicle-command SDK, which connects to Tesla vehicles over Bluetooth Low Energy (BLE) or the internet and sends end-to-end authenticated commands.

Reference version for this document

Written against commit a4b43c1 (Fix wrapped protocol error classification), which follows tag v0.4.1 of the vehicle-command/ repository. The Go module path is github.com/teslamotors/vehicle-command and the required Go version is 1.23. When the code is updated, re-check the API signatures and command lists in this manual.

30-second summary

  1. Create a key. tesla-keygen create > public_key.pem. A NIST P-256 private key is stored in the OS keyring and the public key is printed.
  2. Register the key with the vehicle. Inside the car, run tesla-control -ble add-key-request public_key.pem owner cloud_key, then approve by tapping an NFC card on the center console.
  3. Send a command. tesla-control -ble lock. The SDK handles advertisement scanning → GATT connection → per-domain handshake → sending the AES-GCM encrypted command.
export TESLA_KEY_NAME=$(whoami)
export TESLA_VIN=5YJ30123456789ABC
export TESLA_CACHE_FILE=~/.tesla-cache.json

tesla-keygen create > public_key.pem
tesla-control -ble add-key-request public_key.pem owner cloud_key   # inside the car, with an NFC card ready
tesla-control -ble lock
tesla-control -ble -debug body-controller-state                     # lock/door/sleep state (works even while Infotainment is asleep)

Key concepts at a glance

Domain
VCSEC The security controller responsible for locking, trunks, key management, and wake-up. It responds over BLE even while Infotainment is asleep. INFOTAINMENT Handles the remaining commands, such as climate, charging, media, and state queries. Each domain has its own key pair and session.
Session
When the client sends a SessionInfoRequest with its public key, the domain returns a SessionInfo containing its public key, epoch, counter, and clock. The two sides agree on a 128-bit AES-GCM key K via ECDH.
Authentication method
BLE uses AES-GCM (encryption + authentication), and the Fleet API uses HMAC-SHA256 (plaintext + authentication). Both bind metadata containing the VIN, epoch, expiration time, and counter into the authentication.
Role
Owner, Driver, Fleet Manager, Vehicle Monitor, Charging Manager, Guest, Service. The permitted commands depend on the role.
Session cache
If session state is saved to disk, the next run can send commands immediately without a handshake. If the cache is stale, the vehicle returns new session information along with an error, so it recovers automatically.
