Module and package map

The module path is github.com/teslamotors/vehicle-command, and go.mod requires Go 1.23. v0.x releases do not guarantee API stability, so pin the version in your go.mod.

go get github.com/teslamotors/vehicle-command@v0.4.1

internal/authentication (ECDH, signing, verification), internal/dispatcher (sessions/routing), internal/log and internal/schnorr cannot be imported from external modules because of Go's internal rule. Access the functionality you need through pkg/protocol (re-exported key types), pkg/vehicle (session management) and pkg/cache (cache entries).

Basic flow: unlocking over BLE

A minimal program that summarizes examples/ble/main.go from the repository. The order of calls and the order of defers matter.

package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/teslamotors/vehicle-command/pkg/connector/ble"
    "github.com/teslamotors/vehicle-command/pkg/protocol"
    "github.com/teslamotors/vehicle-command/pkg/vehicle"
)

func main() {
    vin := "5YJ30123456789ABC"

    // 1. Initialize the BLE adapter. An empty string means the default adapter. An ID such as "hci0" can be given on Linux only.
    if err := ble.InitAdapterWithID(""); err != nil {
        if ble.IsAdapterError(err) {
            log.Fatal(ble.AdapterErrorHelpMessage(err)) // Linux: prints setcap guidance
        }
        log.Fatalf("failed to initialize BLE adapter: %s", err)
    }

    // 2. Load the private key (PEM, NIST P-256). nil is allowed, but authenticated commands will fail.
    privateKey, err := protocol.LoadPrivateKey("private.pem")
    if err != nil {
        log.Fatalf("failed to load private key: %s", err)
    }

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    // 3. Scan advertisements. Finds the beacon matching the Local Name ("S...C") computed from the VIN.
    scan, err := ble.ScanVehicleBeacon(ctx, vin)
    if err != nil {
        log.Fatalf("scan failed: %s", err)
    }
    fmt.Printf("found: %s (%s) %ddBm\n", scan.LocalName, scan.Address, scan.RSSI)

    // 4. GATT connection. If target is nil, it scans again internally.
    conn, err := ble.NewConnectionFromScanResult(ctx, vin, scan)
    if err != nil {
        log.Fatalf("connection failed: %s", err)
    }
    defer conn.Close() // (b) runs second

    // 5. Create the Vehicle object. The third argument is the session cache (nil if none).
    car, err := vehicle.NewVehicle(conn, privateKey, nil)
    if err != nil {
        log.Fatal(err)
    }

    // 6. Start the receive goroutine.
    if err := car.Connect(ctx); err != nil {
        log.Fatalf("Connect failed: %s", err)
    }
    defer car.Disconnect() // (a) runs first. Must run before conn.Close().

    // 7. Per-domain handshake. nil means both VCSEC and INFOTAINMENT.
    if err := car.StartSession(ctx, nil); err != nil {
        log.Fatalf("handshake failed: %s", err)
    }

    // 8. Send commands. Each command is retried automatically until the context expires.
    if err := car.Unlock(ctx); err != nil {
        log.Fatalf("unlock failed: %s", err)
    }
    if err := car.ClimateOn(ctx); err != nil {
        log.Fatalf("failed to turn on climate: %s", err)
    }
    fmt.Println("done")
}
  1. Initialize the adapter once per process. ble.InitAdapterWithID creates the global ble.Device, which ScanVehicleBeacon/NewConnection then reuse. If you do not call it explicitly, the default adapter is initialized automatically on the first scan/connection. Calling newDevice() more than once fails on Linux, so it is guarded by an internal mutex. To switch adapters, call ble.CloseAdapter() and then initialize again.
  2. defer order. Vehicle.Disconnect() stops the dispatcher goroutine and then calls conn.Close() internally. Connector.Close() must be idempotent, so deferring both is fine, but Disconnect must run first (defers run in reverse order, so write defer conn.Close() first and defer car.Disconnect() after it).
  3. Prefer a fresh context per command. The example shares a single 30-second context for simplicity, but tesla-control gives 20 seconds to connecting and a separate 5 seconds to each command. The session's command expiration time (expires_at) is also computed from the context deadline (5 seconds if there is no deadline).
  4. The SDK handles retries. Vehicle.Send, StartSession and the VCSEC command loop retry errors for which protocol.ShouldRetry(err) is true (errors that are temporary and cannot have succeeded) at RetryInterval() intervals (1 second for BLE) until the context ends.

Creating a key pair with OpenSSL (when you want file-based keys instead of tesla-keygen):

openssl ecparam -genkey -name prime256v1 -noout > private.pem
openssl ec -in private.pem -pubout > public.pem
Do not enroll the test keys from protocol.md on a real vehicle

The client.key/vehicle.key in pkg/protocol/protocol.md are published keys for verifying test vectors. If you enroll them on a vehicle, anyone can send it commands.

Choosing domains and not waking Infotainment

If you only use VCSEC commands (lock, trunk, wake, key management, BodyControllerState), you do not need a handshake with INFOTAINMENT. An INFOTAINMENT handshake wakes a sleeping infotainment system and takes time.

import universal "github.com/teslamotors/vehicle-command/pkg/protocol/protobuf/universalmessage"

// Handshake with VCSEC only
if err := car.StartSession(ctx, []universal.Domain{protocol.DomainVCSEC}); err != nil { ... }
if err := car.Lock(ctx); err != nil { ... }

tesla-control does the same through the -domain vcsec flag (repeatable), the domain: protocol.DomainVCSEC setting on the body-controller-state command, and special handling that performs a VCSEC-only handshake for -ble wake.

If you send an Infotainment command without an INFOTAINMENT session

protocol.ErrNoSession (cannot send authenticated command before establishing a vehicle session) is returned immediately. tesla-control reports this error as "You must provide a private key…".

Session cache

A handshake adds a round trip and, on the Fleet API, increases the number of requests. Storing session state (per-domain SessionInfo and creation time) on disk with pkg/cache lets you send the first command right away on the next run. If the cache is stale, the first command fails and the vehicle sends up-to-date session info along with the failure, so the SDK updates automatically and retries. In other words, using a stale cache costs nothing.

const cacheFile = "/var/lib/myapp/tesla-cache.json"

myCache, err := cache.ImportFromFile(cacheFile)
if err != nil {
    myCache = cache.New(5) // Up to 5 vehicles. 0 means unlimited. LRU eviction.
}

car, err := vehicle.NewVehicle(conn, privateKey, myCache) // Loads from the cache on creation
...
defer func() {
    if err := car.UpdateCachedSessions(myCache); err != nil { log.Println(err) }
    if err := myCache.ExportToFile(cacheFile); err != nil { log.Println(err) }
}()
  • The cache is tied to the client private key. If you use the cache with a different key, the first authentication fails, the vehicle sends new session info, and it recovers normally.
  • You can put multiple VINs in one cache. SessionCache.Vehicles is a map of VIN → per-domain entries.
  • Control file access. The cache contains the vehicle public key, epoch, counter and clock offset. It contains no private key, but third parties must not be able to read or tamper with it. ExportToFile creates it with 0644, so tighten the permissions if needed.
  • tesla-control uses TESLA_CACHE_FILE (default ~/.tesla-cache.json), and the proxy uses an in-memory cache (up to 10000 vehicles).
  • SessionCache.Update/GetEntry are for the internal dispatcher, so prefer Vehicle.UpdateCachedSessions.

Building CLI applications with pkg/cli

pkg/cli.Config provides the flag, environment variable and keyring logic shared by the five CLI tools. You can reuse it as-is when building your own CLI.

import (
    "flag"
    "github.com/teslamotors/vehicle-command/pkg/cli"
)

config, err := cli.NewConfig(cli.FlagAll) // FlagVIN | FlagOAuth | FlagPrivateKey | FlagBLE
if err != nil { panic(err) }
config.RegisterCommandLineFlags()   // -vin, -key-name, -key-file, -token-name, -token-file, -session-cache, -domain, -keyring-type ...
flag.Parse()
config.ReadFromEnvironment()        // Fills only empty values from TESLA_* environment variables
if err := config.LoadCredentials(); err != nil { ... } // Handles the keyring password prompt before the timeout starts

ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()
acct, car, err := config.Connect(ctx) // Internet if OAuth is available, otherwise BLE. Performs Connect + StartSession(config.Domains)
if err != nil { ... }
if car != nil {
    defer car.Disconnect()
    defer config.UpdateCachedSessions(car) // Updates the cache file
}

FlagBLE (Linux)-bt-adapter
  • Transport selection in config.Connect: ConnectRemote if FlagOAuth is set and a token name/file is present; otherwise ConnectLocal if FlagBLE|FlagVIN; if neither, ErrNoAvailableTransports.
  • ConnectLocal(ctx, skey) only does ble.InitAdapterWithID(c.BtAdapterID) → ble.NewConnection → vehicle.NewVehicle(conn, skey, c.sessions) and does not call Connect/StartSession. Connect does both of those as well.
  • If you set config.Domains (cli.DomainList), Connect handshakes only with those domains.
  • config.PrivateKey() prefers the file and falls back to the keyring. On first load it also reads the cache file.

Internet path: pkg/account

acct, err := account.New(oauthToken, "myapp/1.0.0") // If userAgent is "", it is generated from build info
if err != nil { ... }
car, err := acct.GetVehicle(ctx, vin, privateKey, sessionCache) // Creates an inet.Connection
if err != nil { ... }
if err := car.Connect(ctx); err != nil { ... }
defer car.Disconnect()
if err := car.Wakeup(ctx); err != nil { ... }          // Polls Fleet API wake_up (optional)
if err := car.StartSession(ctx, nil); err != nil { ... }
if err := car.Unlock(ctx); err != nil { ... }
  • account.New decodes the JWT without verifying its signature and picks the Fleet API host from aud and ou_code. The default is fleet-api.prd.na.vn.cloud.tesla.com. If the server returns 421 with a use base URL: https://… body, inet.Connection updates the host.
  • The internet path uses HMAC-SHA256 authentication (plaintext), because the Fleet API must check OAuth scopes. The Fleet API rejects AES-GCM encrypted commands.
  • You can also make general Fleet API calls with Account.Get(ctx, "api/1/products"), Post, and SendVehicleFleetAPICommand(ctx, vin, "vehicle_data", nil).
  • Account.UpdateKey(ctx, publicKey, name) registers key metadata (display name) at api/1/users/keys. It is shown on the vehicle's Locks screen.
  • BLE-only commands (SendAddKeyRequest) return protocol.ErrRequiresBLE on the internet path. Conversely, SetPINToDrive is allowed only on the internet path (protocol.ErrRequiresEncryption; it is blocked over BLE because the PIN could be exposed to an unauthenticated public key).

Error handling patterns

All SDK errors implement the protocol.Error interface where possible. Two methods determine retries and user guidance.

err := car.Unlock(ctx)
switch {
case err == nil:
    // Success
case protocol.MayHaveSucceeded(err):
    // The command may have arrived but was not confirmed (e.g. timeout). Resending could execute it twice, so query state to decide.
case errors.Is(err, protocol.ErrKeyNotPaired):
    // The public key is not enrolled on the vehicle. Guide the user through pairing.
case errors.Is(err, protocol.ErrNoSession):
    // StartSession was not called, or was called without that domain.
case protocol.IsNominalError(err):
    // The vehicle authenticated the command but cannot execute it (e.g. not in park, already on). Show the reason to the user.
case protocol.Temporary(err):
    // Temporary error. The SDK already retried until the context expired, so retry with a longer context.
default:
    // Anything else
}
HelperMeaning
protocol.MayHaveSucceeded(err)The vehicle may have executed the command. Context timeouts, response parsing failures, HTTP 5xx (except 503), etc.
protocol.Temporary(err)May be resolved by retrying without user intervention. ErrBusy, MESSAGEFAULT_ERROR_BUSY/TIMEOUT/INVALID_SIGNATURE/INVALID_TOKEN_OR_COUNTER/INTERNAL/INCORRECT_EPOCH/TIME_EXPIRED/TIME_TO_LIVE_TOO_LONG, HTTP 503/504/408/421.
protocol.ShouldRetry(err)True only when Temporary and not MayHaveSucceeded. The criterion for the SDK's internal retry loops.
protocol.IsNominalError(err)Application-layer rejection (NominalError). The proxy returns this as HTTP 200 + reason.
errors.As(err, &*protocol.RoutableMessageError)Protocol-layer error. Check MessageFault_E via .Code.
errors.As(err, &*protocol.KeychainError)Key add/remove failure. .Code is a WhitelistOperation_information_E.

For the full error code table and scenario-by-scenario remedies, see 9. Errors and Troubleshooting.

Implementing a custom Connector

To plug in a different BLE stack (for example TinyGo, a mobile bridge, or a serial gateway) or a mock transport for testing, implement connector.Connector and pass it to vehicle.NewVehicle. The dispatcher treats the connector purely as a datagram channel.

type Connector interface {
    Receive() <-chan []byte                     // RoutableMessage bytes sent by the vehicle. Thread-safe.
    Send(ctx context.Context, buffer []byte) error // Sends RoutableMessage bytes. Thread-safe.
    VIN() string
    Close()                                     // Must be safe to call multiple times
    PreferredAuthMethod() AuthMethod            // BLE: AuthMethodGCM, HTTP: AuthMethodHMAC
    RetryInterval() time.Duration               // Resend interval (1 second for both BLE and inet)
    AllowedLatency() time.Duration              // Maximum allowed latency for session info responses (4 seconds for BLE, 10 seconds for inet)
}

type FleetAPIConnector interface {             // Implemented additionally by internet connectors only
    Connector
    SendFleetAPICommand(ctx context.Context, endpoint string, command interface{}) ([]byte, error)
    Wakeup(ctx context.Context) error
}
  • A buffer of about connector.BufferSize (5) is recommended for the Receive() channel. The BLE implementation uses 5, and inet also uses 5. When it is full, BLE drops chunks and inet produces a dropped response because inbox is full error.
  • If an error returned by Send implements protocol.Error, the dispatcher uses ShouldRetry to decide whether to resend. Plain errors are treated as terminal.
  • Responses up to connector.MaxResponseLength (100000 bytes) must be supported. The BLE implementation limits messages to 1024 bytes each (maxBLEMessageSize).
  • For BLE, the 2-byte big-endian length framing and MTU splitting must be handled inside the connector. The dispatcher knows nothing about framing.
  • Session info responses that arrive later than AllowedLatency are discarded for clock synchronization, so for high-latency transports increase the value or adjust it with Vehicle.SetMaxLatency.
  • If you implement FleetAPIConnector, Vehicle.Wakeup uses it, SetPINToDrive is allowed, and SendAddKeyRequest is rejected.

Caveats for HSM/TEE integration

protocol.ECDHPrivateKey is an interface and protocol.Session is re-exported, so they can be implemented in external modules too (pkg/protocol/external_impl_test.go is an example). To keep the private key in a Nitro Enclave, KMS or hardware HSM, create a type that proxies Exchange(remotePublicBytes) (Session, error), PublicBytes() and SchnorrSignature(message) to TEE calls. The conditions required by the comments in pkg/protocol/key.go:

  • The TEE must not expose an API that exports the ECDH shared secret.
  • The TEE must not expose a general-purpose AES interface that operates with ECDH-derived keys (the host could compute integrity keys).
  • The TEE must not expose an AES-GCM encryption interface in which the host specifies the nonce.
  • Do not put derived secrets in the Session object; put only TEE handles in it.

Even if these conditions are not met, it can still be valuable in that a compromised host leaks only the long-term shared secrets for already-known vehicle public keys. When using file-based storage, keep in mind that SavePrivateKey saves with 0600, and make use of the keyring options (keyring).

Logging, building, testing

  • Logging. The SDK prints [debug]/[info ]/[warn ]/[error] to stderr via internal/log. External modules cannot change the level directly, so use the CLI tools' -debug/-verbose or the TESLA_VERBOSE environment variable (tesla-control, tesla-http-proxy). If you need debug logs in your own application, you must fork the repository or build it as a program inside the repository like examples/ble (examples/ble/main.go is in-repository code that can import internal/log).
  • Interpreting debug output. TX: 32020802…/RX: … are RoutableMessages in hex. Decode them with protoc --decode=UniversalMessage.RoutableMessage -I pkg/protocol/protobuf pkg/protocol/protobuf/*.proto (procedure).
  • Building. go build ./..., go install ./cmd/... (= make install). The BLE package uses cbgo (CoreBluetooth) on macOS and HCI sockets on Linux, so the cgo/permission requirements differ. The Docker image packs all five tools into a distroless runtime, and its default entrypoint is tesla-http-proxy.
  • Testing/linting. ./check-all.sh runs go build, go test ./..., go vet, a go fmt no-changes check and shellcheck, in that order. make test runs go test -cover ./... and go vet. CI runs, with Go 1.23.0, make format followed by a no-diff check, golangci-lint v1.61.0 (.golangci.yml: errcheck, gofmt, gosimple, govet, misspell, revive, unused) and make test.
  • Regenerating protobuf. make proto-gen regenerates pkg/protocol/protobuf/*.pb.go with protoc --go_out. Whenever you change a .proto, always regenerate and commit.
  • Mock tests. See how pkg/vehicle/vehicle_mock_test.go and pkg/proxy/proxy_test.go mock connectors/vehicles. The proxy is designed so that the httpDoer and vehicleSession interfaces and the fetchVehicle field can be swapped out in tests.
