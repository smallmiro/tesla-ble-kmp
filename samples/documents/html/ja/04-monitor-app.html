4. モニターアプリ

車内または車の近くに置いたスマートフォンが自動で接続し、接続を保ち、車の状態をライブで表示し、ライブラリが読み取れるものをすべてポーリングし、すべてのブロードキャストを生のバイト列とともに記録します。これにより、未知のプロトコルフィールドを後から分析できます。

予定

issue #91 で管理しており、すぐに作り始められます。必要なライブラリ API はすべて使えます: Vehicle.events（ライブラリマニュアル 12 章「ブロードキャストイベント」、14 章 B2）と iOS のキーアクセシビリティの選択（13 章「スマートフォンのロック中にキーを使う」、FR-037）。このページは目標とする姿を説明しています。

要件

IDアプリの動作
SFR-0104 つのタブ：Live、Query、Log、Control。現在の 1 画面は Control に移ります。
SFR-011VIN は 1 回入力すると保存され、消去ボタンがあります。保存済みの VIN がある状態でアプリを起動すると、自動でスキャンして接続します。Connect ボタンは常に即座に接続を試みます。
SFR-012接続が切れると、アプリは古い接続を解放して再接続します。最初は 2 秒待ち、倍々にして最大 30 秒まで延ばします。バックグラウンドでも同様です。Disconnect は、Connect を押すまで自動再接続を止めます。
SFR-013アプリが画面に表示されている間は、画面が消灯しません。
SFR-014Live タブ：最新のステータスブロードキャストから、ロック、ギア、在車状態、スリープ、4 つのドア、フランク、トランク、充電ポートを表示し、それぞれに最後に変化した時刻を付けます（同じ値が再送されても変化とは見なしません）。認証リクエストを含む最近のイベントの一覧。接続バナー。トランクはブロードキャストを送らない場合があるという注記。
SFR-015Query タブ：vehicleStatus()、keySummary()、listKeys() を 30 秒ごと（変更可能）に読み取り、セッション状態を表示します。各結果には、成功、不確定、失敗のいずれかと時刻が表示されます。「今すぐ問い合わせ」ボタン。
SFR-016Log タブとログファイル：すべてのレコードを JSON Lines ファイルに書き込みます。メモ欄と Mark ボタンで、これから行う操作を記録します。タブには、件数、未認識イベントの数、最後の数行、ファイルの場所が表示され、新しいファイルを開始できます。
SFR-017tools/samples/pull-monitor-logs.sh android|ios は、ケーブルで接続したスマートフォンからログを samples/logs/<platform>/<date>/ にコピーします。このフォルダーは git の管理対象外です。

ロック中のスマートフォンでのキー

モニターは専用のキー teslable-monitor を使います。このキーは、スマートフォンがロックされていても使えるように作られます（iOS では KeyAccessibility.AFTER_FIRST_UNLOCK、Android のキーはもともとロック中でも使えると報告します。実機ではまだ確認していません）。この設定はキーを作る時点で固定されます。スマートフォンにすでにそのキーが厳しい設定で存在する場合、アプリは、それを削除して新しく作り、車に登録し直すよう求めます。Control タブには、キーがどの設定になっているかが表示されます。アプリは接続を試みるたびに、まずキーストアからキーを読み込みます。キーストアが KeyStoreError.Locked を返した場合（再起動後にまだロックを解除していない、またはロック解除中にだけ使えるキーの場合）、アプリは待ってからロック解除後に再試行し、この理由でキーを削除することはありません。

ログファイル

1 行に 1 つの JSON オブジェクトです。すべての行に ts（オフセット付きの時刻）と kind があります。各ファイルは、スマートフォンとアプリのビルドを記した session 行から始まります。

{"ts":"2026-10-24T10:00:00.123+09:00","kind":"session","platform":"ios","app":"0.2.0(9)","os":"27.0.1","phone":"iPhone"}
{"ts":"…","kind":"event","type":"Status","summary":"lock=LOCKED gear=PARK presence=NOT_PRESENT","unknownFields":["1.8"],"unrecognized":true,"raw":"<hex>"}
{"ts":"…","kind":"observe","line":"[drop:no-handler] 83B from=domain(DOMAIN_VEHICLE_SECURITY) …"}
{"ts":"…","kind":"query","call":"vehicleStatus","result":"Success","summary":"…"}
{"ts":"…","kind":"link","state":"backoff","reason":"…","attempt":3,"delayMs":8000}
{"ts":"…","kind":"mark","memo":"before: open driver door"}
Kind内容
event車からのブロードキャスト：その種類（Status、AuthenticationRequest、Unrecognized）、要約、ライブラリが認識しなかったフィールド番号、未認識の内容を示すフラグ、16 進数の生のバイト列
observeライブラリの観察行（ライブラリがすでにマスク済み）。生の BLE の TX:/RX: 行は書き込まれません
queryQuery タブの結果
link接続中、接続済み、切断、再試行待ち、停止
markMark ボタンで残したメモ
  • VIN のマスク：書き込む前に、生のバイト列やテキストに含まれる 17 文字の VIN は、先頭 3 文字と末尾 4 文字を残し、残りを * に置き換えます。そのため長さは変わりません。
  • マークのメモは最大 80 文字です。空のメモは無視されます。
  • ファイル名は monitor-<yyyyMMdd-HHmmss>.jsonl です。20 MB で新しいファイルを開始し、フォルダーが 200 MB を超えると最も古いファイルから削除します。
  • 書き込みがイベントの収集を止めることはありません。ライターは小さなインターフェースの背後にあり、将来クラウドへの出力先を追加できます。
  • ファイルの場所：Android は Android/data/dev.mirolab.teslable.sample/files/logs/（adb pull で読み取れます）。iOS は Documents/logs/ で、Finder とファイルアプリからも見えます。

実車チェックリスト

  1. 新規インストール：VIN を入力し、モニターキーを作成して登録します。アプリを再起動すると、自動で接続します。
  2. Live タブ：運転席ドアを開閉し、P、R、N、D とシフトし、外からロックします。それぞれの変化が時刻付きで表示されます。
  3. リンクが切れるまで離れてから戻ります。スマートフォンに触れなくても、画面を点灯したままの場合とロックした場合の両方で再接続します。
  4. ロックしたスマートフォンを車の近くに 30 分置きます。接続したまま、または再接続され、ログが増え続けます。
  5. Disconnect を押します。2 分間、再接続を試みません。
  6. Mac でスクリプトを使ってログを取り出します。最初の行は session 行で、17 文字の VIN を検索しても何も見つかりません。
