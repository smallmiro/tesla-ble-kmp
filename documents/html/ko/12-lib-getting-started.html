12. 라이브러리 시작하기

라이브러리 생성, 키 확보, 차량 찾기, 연결, 상태 읽기, 연결 해제까지 전체 흐름을 따라갑니다. 마지막 두 절에서는 새 키를 페어링하고 첫 명령을 보내는 방법(M4)과 차량 브로드캐스트를 받는 방법을 보여 줍니다.

  2. 다섯 가지 규칙

흐름

  1. 라이브러리를 만듭니다. TeslaBle.create(platform, config)를 앱마다 한 번 호출합니다.
  2. 키를 얻습니다. ble.keys.getOrCreate()는 휴대폰의 P-256 키를 반환하며, 처음 호출할 때 보안 하드웨어에 키를 만듭니다.
  3. 차량을 찾습니다. ble.scan(vin)이 차량의 광고를 내보내면 첫 번째 것을 사용합니다.
  4. 연결합니다. ble.connect(vin, key, advertisement)는 Vehicle을 반환합니다.
  5. 읽습니다. vehicleStatus(), keySummary(), listKeys().
  6. 정리합니다. vehicle.disconnect()를 호출하고, 앱이 끝나면 ble.close()를 호출합니다.

다섯 가지 규칙

  • 결과는 값입니다. 차량이나 키 보관소에 대한 모든 호출은 VehicleResult(Success, Uncertain, Failure)를 반환합니다. 호출한 쪽의 코루틴이 취소된 경우를 빼고는 예외를 던지지 않습니다.
  • 앱마다 TeslaBle 하나. 다 쓰면 close()를 호출하세요. 아직 연결된 차량이 있으면 함께 연결을 끊습니다.
  • 항상 연결을 끊으세요. 링크가 이미 끊겼더라도 vehicle.disconnect()를 호출하세요. 세션 캐시를 저장하고, 세션 키를 지우고, 차량의 BLE 슬롯을 비웁니다. 두 번 호출해도 괜찮습니다.
  • 읽기에는 키가 없어도 됩니다. 세 가지 조회에는 connect(vin, key = null)로 충분합니다. 세션을 시작하려면 키가 필요합니다.
  • 디버그 로깅은 개발 중에만. DebugLogger()는 플랫폼 로그에 기록합니다. 릴리스 빌드에서는 빼세요.

Kotlin (Android)

import dev.mirolab.teslable.*
import dev.mirolab.teslable.model.*
import dev.mirolab.teslable.port.*
import kotlinx.coroutines.flow.first

suspend fun demo(context: android.content.Context, vinText: String) {
    val vin = Vin.parseOrNull(vinText) ?: return              // 17자 형식 검사
    val ble = TeslaBle.create(
        PlatformContext(context),
        TeslaBleConfig.default(logger = DebugLogger()),         // 개발용 로거, 릴리스 빌드에서는 사용하지 않음
    )
    try {
        val key = when (val r = ble.keys.getOrCreate()) {       // 기본 별칭, 하드웨어 우선
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: KeyStoreError
        }

        // 첫 번째 광고를 사용합니다. 시간 제한은 호출자가 정합니다(예: withTimeoutOrNull).
        val event = ble.scan(vin).first()
        val target = (event as? ScanEvent.Found)?.advertisement ?: return   // Failed이면 event.error 확인

        val vehicle = when (val r = ble.connect(vin, key, target)) {
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: TransportError 등
        }
        try {
            println(vehicle.vehicleStatus())                    // println 대신 UI에 표시
            println(vehicle.listKeys())
        } finally {
            vehicle.disconnect()                                // 슬롯을 비움, 링크가 끊긴 뒤에도 호출
        }
    } finally {
        ble.close()                                             // suspend, 아직 연결된 차량이 있으면 연결을 끊음
    }
}

이 호출들 전에 BLUETOOTH_SCAN과 BLUETOOTH_CONNECT를 런타임에 요청하세요. 플랫폼 노트를 참고하세요.

Swift (iOS)

SKIE는 suspend 함수를 async throws로, Flow를 AsyncSequence로 바꾸고, switch onEnum(of:)로 결과의 모든 경우를 다룰 수 있게 합니다. 코드 구조는 samples/ios/Sources/SampleModel.swift와 같습니다.

import Teslable

let ble = TeslaBle.companion.create(
    platform: PlatformContext(),
    config: TeslaBleConfig.companion.default(logger: DebugLogger())
)

func run(vinText: String) async {
    guard let vin = Vin.companion.parseOrNull(value: vinText) else { return }   // 잘못된 형식

    // 1) 키
    var key: VehicleKey?
    do {
        let result = try await ble.keys.getOrCreate(alias: VehicleKeyStoreCompanion.shared.DEFAULT_ALIAS, policy: .preferHardware)
        switch onEnum(of: result) {
        case .success(let s): key = s.value as? VehicleKey
        case .uncertain(let u): print("불확실: \(u.error.message)")
        case .failure(let f): print("실패: \(f.error.message)")
        }
    } catch { print("오류: \(error)") }

    // 2) 스캔(첫 번째 광고에서 멈춤, 시간 제한은 Task를 취소해서 설정)
    for await event in ble.scan(vin: vin) {
        switch onEnum(of: event) {
        case .found(let f): print("\(f.advertisement.localName.value) rssi=\(f.advertisement.rssi)")
        case .failed(let e): print("스캔 실패: \(e.error.message)")
        }
        break
    }

    // 3) 연결과 조회
    do {
        let connected = try await ble.connect(vin: vin, key: key, target: nil, options: ConnectOptions(timeout: nil))
        switch onEnum(of: connected) {
        case .success(let s):
            guard let vehicle = s.value as? Vehicle else { return }
            let status = try await vehicle.vehicleStatus(timeout: nil)
            switch onEnum(of: status) {
            case .success(let v): print("상태: \(String(describing: v.value))")
            case .uncertain(let u): print("불확실: \(u.error.message)")   // 다시 조회, 재전송하지 않음
            case .failure(let f): print("실패: \(f.error.message)")
            }
            try await vehicle.disconnect()
        case .uncertain(let u): print("불확실: \(u.error.message)")
        case .failure(let f): print("실패: \(f.error.message)")
        }
    } catch { print("오류: \(error)") }
}

target: nil이면 connect가 직접 스캔합니다. Info.plist에 NSBluetoothAlwaysUsageDescription을 추가하세요. 플랫폼 노트를 참고하세요.

Swift에서 시간 제한을 넘기려면 박싱된 도우미와 초 단위 설정 팩토리를 쓰세요. Swift에는 기본 인자 오버로드가 없으므로 모든 인자가 필수입니다.

let status = try await vehicle.vehicleStatus(timeout: Timeouts.shared.seconds(seconds: 10))
let config = TeslaBleConfig.companion.withSeconds(logger: DebugLogger(), commandTimeoutSeconds: 10,
    handshakeTimeoutSeconds: 20, connectTimeoutSeconds: 30, pairingTimeoutSeconds: 90)

페어링 후 잠그기

새 휴대폰 키를 처음 쓸 때는 키카드로 등록하고, 차량 목록에 나타날 때까지 기다린 다음, VCSEC 세션을 시작해 명령을 보냅니다. 이벤트 처리는 13. 키와 페어링, 명령은 15. 명령에서 설명합니다.

Kotlin

// vehicle was connected with `key` (see above)
vehicle.addKeyRequest(key.publicKey).collect { event -> render(event) }      // user taps the key card, confirms on screen
if (waitUntilEnrolled(vehicle, key)) {                                       // polls sessionInfo(…, INFOTAINMENT), see chapter 13
    vehicle.startSession(setOf(VehicleDomain.VCSEC))
    val result = vehicle.lock()                                              // VehicleResult<Unit>; Uncertain: vehicleStatus(), do not resend
}

Swift

for await event in vehicle.addKeyRequest(publicKey: key.publicKey, role: .owner, formFactor: .iosDevice, timeout: nil) {
    render(event)                                                            // user taps the key card, confirms on screen
}
// poll vehicle.sessionInfo(publicKey:domain:timeout:) until success (chapter 13), then:
_ = try await vehicle.startSession(domains: [.vcsec], timeout: nil)
let result = try await vehicle.lock(timeout: nil)

Kotlin의 기본 인자는 Swift 오버로드가 되지 않으므로 Swift에서는 모든 인자를 직접 넘깁니다.

브로드캐스트 이벤트

차량은 요청하지 않아도 평문 브로드캐스트를 보냅니다. 차량 상태(잠금, 문과 그 밖의 개폐부, 기어, 탑승, 수면)와 인증 요청입니다. vehicle.events는 이것을 Flow<VehicleEvent>로 전달하며, 키도 세션도 필요 없습니다. 어떤 프레임이 이벤트가 되는지, 이벤트 종류, unknownFields, 버퍼는 14. 차량 상태 조회, B2에서 설명합니다.

  • 따로 수집하세요. 별도의 코루틴(Swift에서는 별도의 Task)을 씁니다. 흐름은 링크가 끊기거나 disconnect()가 불리면 스스로 끝나며, 그 뒤에 시작한 수집은 바로 끝납니다. 그다음 connection을 확인하고 disconnect()를 호출하세요. 새로 연결하면 새 Vehicle과 새 events를 받습니다.
  • 듣고 있는 동안 온 것만 받습니다. 그 전의 브로드캐스트는 다시 보내 주지 않습니다. 반복은 변화가 아닙니다. 차량은 같은 상태를 몇 초마다 다시 보내므로 마지막 값과 비교하세요.
  • 트렁크: 밖에서 손으로 열거나 닫은 트렁크는 브로드캐스트되지만, 실내 버튼으로 조작한 트렁크는 브로드캐스트되지 않습니다. 트렁크 상태가 중요하면 vehicleStatus()로 읽으세요.
  • raw는 프레임 전체입니다. VIN을 가리지 않았고 읽을 때마다 새 복사본을 만듭니다. 한 번만 읽고, 저장하거나 공유하기 전에 VIN을 가리세요.

Kotlin

// vehicle은 위처럼 연결됨(key = null이면 충분)
scope.launch {
    vehicle.events.collect { event ->
        when (event) {
            is VehicleEvent.Status -> render(event.status)                        // 반복은 변화가 아님
            is VehicleEvent.AuthenticationRequest -> note(event.requestedLevel, event.reasons)
            is VehicleEvent.Unrecognized -> keep(event.raw, event.unknownFields)  // 저장하기 전에 raw의 VIN을 가림
        }
    }
    // 끝남: 링크가 끊겼거나 disconnect()가 불림. vehicle.connection을 확인한 뒤 vehicle.disconnect()를 호출
}

Swift

SKIE 흐름은 예외를 던지지 않으므로 for await면 충분합니다. AuthenticationLevel.none은 타입 이름까지 쓰세요. 값이 옵셔널인 곳(예: 저장해 둔 마지막 수준)에서 그냥 .none이라고 쓰면 nil을 뜻합니다. Swift에서 공개 모델 VehicleStatus의 이름은 VehicleStatus_입니다. 생성된 VCSEC 메시지가 원래 이름을 쓰기 때문이며, 그래서 s.status는 VehicleStatus_입니다.

// 별도 Task에서. 링크가 끊기거나 disconnect()가 불리면 루프가 스스로 끝남
for await event in vehicle.events {
    switch onEnum(of: event) {
    case .status(let s):
        render(s.status)                                         // 반복은 변화가 아님
    case .authenticationRequest(let a):
        if a.requestedLevel != AuthenticationLevel.none {
            print("인증 요청: \(a.requestedLevel), 이유 \(a.reasons)")
        }
    case .unrecognized(let u):
        let raw = u.raw                                          // 읽을 때마다 바이트를 복사하므로 한 번만 읽음
        keep(raw, u.unknownFields)                               // 저장하기 전에 raw의 VIN을 가림
    }
}
// 루프가 끝남: vehicle.connection을 확인한 뒤 vehicle.disconnect()를 호출

다음 단계

  • 키 등록과 페어링 이벤트: 13. 키와 페어링. vehicleStatus(), keySummary(), listKeys()는 여전히 connect(vin, key = null)만으로 충분합니다.
  • 링크는 vehicle.connection으로, 세션은 vehicle.sessions로 관찰하세요. 둘 다 StateFlow입니다. 링크가 Disconnected를 알려도 disconnect()는 직접 호출하세요.
  • 차량 브로드캐스트로 보는 실시간 상태: vehicle.events(위의 브로드캐스트 이벤트, 14. 차량 상태 조회, B2).
