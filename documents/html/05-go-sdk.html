모듈과 패키지 지도

모듈 경로는 github.com/teslamotors/vehicle-command이고 go.mod는 Go 1.23을 요구합니다. v0.x 릴리스는 API 안정성을 보장하지 않으므로 go.mod에 버전을 고정하세요.

go get github.com/teslamotors/vehicle-command@v0.4.1
패키지역할주요 심볼
pkg/protocol키 로드, 도메인 상수, 오류 타입. 하위 디렉터리 protobuf/*에 생성된 protobuf 바인딩.LoadPrivateKey, LoadPublicKey, ECDHPrivateKey, DomainVCSEC, DomainInfotainment, Error, MayHaveSucceeded, ShouldRetry
pkg/connector전송 계층 인터페이스 정의.Connector, FleetAPIConnector, AuthMethodNone/GCM/HMAC, BufferSize, MaxResponseLength
pkg/connector/bleBLE 전송 구현 (go-ble 기반). macOS, Linux 지원. Windows는 빌드는 되지만 런타임 오류.InitAdapterWithID, ScanVehicleBeacon, NewConnection, NewConnectionFromScanResult, VehicleLocalName, CloseAdapter
pkg/connector/inetFleet API(HTTPS) 전송 구현.NewConnection, SendFleetAPICommand, HTTPError, ErrVehicleNotAwake, MaxLatency
pkg/vehicle차량 명령 API. 도메인 라우팅, 세션, 재시도를 감싼 고수준 메서드.Vehicle, NewVehicle, StateCategory*, SeatPosition, Level, ChargingPolicy

pkg/cli공통 플래그/환경 변수/키링 처리. CLI 도구를 만들 때 사용.Config, NewConfig, Flag*, DomainList, Env* 상수
pkg/accountTesla 계정(OAuth 토큰) 래퍼. Fleet API 도메인 결정, GetVehicle.Account, New, GetVehicle, Get, Post, UpdateKey
pkg/proxyREST → 종단 간 인증 명령 변환 서버. http.Handler 구현.Proxy, New, ExtractCommandAction, ErrCommandUseRESTAPI
pkg/signFleet Telemetry 설정 등에 쓰는 JWS(Schnorr/P256) 서명.SignMessageForVehicle, SignMessageForFleet
internal/ 패키지는 임포트할 수 없습니다

internal/authentication(ECDH, 서명, 검증), internal/dispatcher(세션/라우팅), internal/log, internal/schnorr는 Go의 internal 규칙에 따라 외부 모듈에서 임포트할 수 없습니다. 필요한 기능은 pkg/protocol(키 타입 재노출), pkg/vehicle(세션 관리), pkg/cache(캐시 엔트리)를 통해 사용합니다.

기본 흐름: BLE로 잠금 해제

저장소의 examples/ble/main.go를 요약한 최소 프로그램입니다. 호출 순서와 defer 순서가 중요합니다.

package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/teslamotors/vehicle-command/pkg/connector/ble"
    "github.com/teslamotors/vehicle-command/pkg/protocol"
    "github.com/teslamotors/vehicle-command/pkg/vehicle"
)

func main() {
    vin := "5YJ30123456789ABC"

    // 1. BLE 어댑터 초기화. 빈 문자열이면 기본 어댑터. Linux에서만 "hci0" 같은 ID 지정 가능.
    if err := ble.InitAdapterWithID(""); err != nil {
        if ble.IsAdapterError(err) {
            log.Fatal(ble.AdapterErrorHelpMessage(err)) // Linux: setcap 안내 출력
        }
        log.Fatalf("BLE 어댑터 초기화 실패: %s", err)
    }

    // 2. 개인 키 로드 (PEM, NIST P-256). nil이어도 되지만 인증 명령은 실패한다.
    privateKey, err := protocol.LoadPrivateKey("private.pem")
    if err != nil {
        log.Fatalf("개인 키 로드 실패: %s", err)
    }

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    // 3. 광고 스캔. VIN에서 계산한 Local Name("S...C")과 일치하는 비콘을 찾는다.
    scan, err := ble.ScanVehicleBeacon(ctx, vin)
    if err != nil {
        log.Fatalf("스캔 실패: %s", err)
    }
    fmt.Printf("발견: %s (%s) %ddBm\n", scan.LocalName, scan.Address, scan.RSSI)

    // 4. GATT 연결. target이 nil이면 내부에서 다시 스캔한다.
    conn, err := ble.NewConnectionFromScanResult(ctx, vin, scan)
    if err != nil {
        log.Fatalf("연결 실패: %s", err)
    }
    defer conn.Close() // (b) 두 번째로 실행

    // 5. Vehicle 객체 생성. 세 번째 인자는 세션 캐시(없으면 nil).
    car, err := vehicle.NewVehicle(conn, privateKey, nil)
    if err != nil {
        log.Fatal(err)
    }

    // 6. 수신 고루틴 시작.
    if err := car.Connect(ctx); err != nil {
        log.Fatalf("Connect 실패: %s", err)
    }
    defer car.Disconnect() // (a) 첫 번째로 실행. 반드시 conn.Close()보다 먼저.

    // 7. 도메인별 핸드셰이크. nil이면 VCSEC와 INFOTAINMENT 둘 다.
    if err := car.StartSession(ctx, nil); err != nil {
        log.Fatalf("핸드셰이크 실패: %s", err)
    }

    // 8. 명령 전송. 각 명령은 컨텍스트 만료까지 자동 재시도한다.
    if err := car.Unlock(ctx); err != nil {
        log.Fatalf("잠금 해제 실패: %s", err)
    }
    if err := car.ClimateOn(ctx); err != nil {
        log.Fatalf("공조 켜기 실패: %s", err)
    }
    fmt.Println("완료")
}
  1. 어댑터 초기화는 프로세스당 한 번. ble.InitAdapterWithID는 전역 ble.Device를 만들고 이후 ScanVehicleBeacon/NewConnection이 재사용합니다. 명시적으로 부르지 않으면 첫 스캔/연결 때 기본 어댑터로 자동 초기화됩니다. Linux에서 newDevice()를 여러 번 부르면 실패하므로 내부 뮤텍스로 보호됩니다. 어댑터를 바꾸려면 ble.CloseAdapter() 후 다시 초기화합니다.
  2. defer 순서. Vehicle.Disconnect()는 디스패처 고루틴을 멈춘 뒤 내부적으로 conn.Close()를 호출합니다. Connector.Close()는 멱등이어야 하므로 둘 다 defer해도 되지만, Disconnect가 먼저 실행되어야 합니다(defer는 역순이므로 defer conn.Close()를 먼저, defer car.Disconnect()를 나중에 씁니다).
  3. 컨텍스트는 명령마다 새로 만드는 것이 좋습니다. 예제는 단순화를 위해 30초 하나를 공유하지만, tesla-control은 연결에 20초, 명령마다 5초를 따로 줍니다. 세션의 명령 만료 시간(expires_at)도 컨텍스트 데드라인에서 계산됩니다(데드라인이 없으면 5초).
  4. 재시도는 SDK가 합니다. Vehicle.Send, StartSession, VCSEC 명령 루프는 protocol.ShouldRetry(err)가 참인 오류(일시적이고, 성공했을 가능성이 없는 오류)를 RetryInterval()(BLE 1초) 간격으로 컨텍스트가 끝날 때까지 재시도합니다.

개인 키와 공개 키 다루기

함수설명
protocol.LoadPrivateKey(filename) (ECDHPrivateKey, error)P-256 EC 개인 키 파일을 로드합니다. PEM 형식(EC PRIVATE KEY, PKCS#8 PRIVATE KEY)을 지원합니다. 다른 곡선이나 RSA 키는 거부됩니다.
protocol.SavePrivateKey(skey, filename) error네이티브 키를 SEC1 PEM(EC PRIVATE KEY)으로 0600 권한으로 저장합니다. HSM 기반 키처럼 내보낼 수 없는 구현이면 key is not exportable 오류.
protocol.LoadPublicKey(filename) (*ecdh.PublicKey, error)공개 키를 유연하게 로드합니다. 지원 형식: PKIX PEM(PUBLIC KEY), 비암호화 PKCS#8 PEM(PRIVATE KEY, 개인 키 파일에서 공개 키 추출), SEC1 PEM(EC PRIVATE KEY), 바이너리 비압축 곡선 점(65바이트, 0x04 시작), 16진수 문자열 비압축 곡선 점(130자, 끝의 개행 허용). 곡선이 P-256이 아니면 ErrInvalidPublicKey.
protocol.PublicKeyBytesFromHex(h) (*ecdh.PublicKey, error)16진수 문자열을 검증해 ecdh.PublicKey로 변환합니다.
protocol.UnmarshalECDHPrivateKey(keyBytes) ECDHPrivateKey32바이트 스칼라(빅엔디언)에서 개인 키를 복원합니다. 키링에 저장된 형식이 이것입니다. 실패하면 nil.
ECDHPrivateKey.PublicBytes() []byte비압축 인코딩 공개 키(65바이트). 핸드셰이크와 signer_identity.public_key에 그대로 들어갑니다.

OpenSSL로 키 쌍을 만드는 방법(tesla-keygen 대신 파일 기반 키를 쓰고 싶을 때):

openssl ecparam -genkey -name prime256v1 -noout > private.pem
openssl ec -in private.pem -pubout > public.pem
protocol.md의 테스트 키를 실제 차량에 등록하지 마세요

pkg/protocol/protocol.md에 있는 client.key/vehicle.key는 테스트 벡터 검증용으로 공개된 키입니다. 차량에 등록하면 누구나 명령을 보낼 수 있습니다.

Vehicle 타입 핵심 메서드

메서드설명
vehicle.NewVehicle(conn connector.Connector, privateKey ECDHPrivateKey, sessionCache *cache.SessionCache) (*Vehicle, error)Vehicle을 만듭니다. privateKey와 sessionCache는 nil 가능. 캐시에 이 VIN의 엔트리가 있으면 즉시 로드합니다. 인증 방식은 conn.PreferredAuthMethod()로 결정(BLE: AES-GCM, inet: HMAC). Flags는 DefaultFlags(FLAG_ENCRYPT_RESPONSE 비트)로 초기화됩니다.
Connect(ctx) error디스패처의 수신 고루틴을 시작합니다. 준비되기 전에 ctx가 만료되면 오류.
StartSession(ctx, domains []universal.Domain) error지정한 도메인과 핸드셰이크합니다. nil이면 VCSEC와 INFOTAINMENT 모두, 병렬로 수행. 키가 페어링되지 않았으면 protocol.ErrKeyNotPaired. 일시적 오류는 자동 재시도. 캐시에서 이미 로드된 도메인은 핸드셰이크를 생략합니다.
Disconnect()디스패처를 멈추고 conn.Close()를 호출합니다.
Wakeup(ctx) error커넥터가 FleetAPIConnector면 Fleet API wake_up 엔드포인트를 state == "online"이 될 때까지 10초 간격으로 폴링합니다. BLE면 VCSEC에 RKE_ACTION_WAKE_VEHICLE을 보냅니다(인증 필요).
Send(ctx, domain, payload []byte, auth connector.AuthMethod) ([]byte, error)저수준: 임의 페이로드를 도메인에 보내고 응답 페이로드를 돌려줍니다. 재시도 포함. 새 명령을 실험할 때 사용.
SendMessage(ctx, message *universal.RoutableMessage) (protocol.Receiver, error)더 저수준: 이미 구성된 RoutableMessage를 인증 없이 전송합니다. 다른 주체가 서명한 메시지를 중계할 때(카드 없는 키 페어링 등) 사용. 반환된 Receiver는 사용 후 Close().
SessionInfo(ctx, publicKey *ecdh.PublicKey, domain) (*signatures.SessionInfo, error)임의 공개 키로 핸드셰이크 요청을 보내 SessionInfo를 받습니다. 인증 불필요. 키가 등록됐는지 확인하는 용도(tesla-control session-info).
SetMaxLatency(d time.Duration)세션 정보 응답이 요청 후 이 시간보다 늦게 도착하면 시계 동기화에 쓰지 않고 버립니다. 기본은 커넥터의 AllowedLatency()(BLE 4초, inet 10초).
Flags uint32 (필드)모든 요청의 RoutableMessage.flags. 기본 1 << FLAG_ENCRYPT_RESPONSE. 2024.38+ 펌웨어는 응답을 암호화하고, 구형 펌웨어는 무시합니다.
PrivateKeyAvailable() bool, VIN() string상태 조회.
UpdateCachedSessions(c *cache.SessionCache) error / LoadCachedSessions(c) error현재 세션 상태를 캐시에 쓰거나 캐시에서 읽습니다.

도메인 선택과 Infotainment 깨우지 않기

VCSEC 명령(잠금, 트렁크, 웨이크, 키 관리, BodyControllerState)만 쓸 때는 INFOTAINMENT와 핸드셰이크할 필요가 없습니다. INFOTAINMENT 핸드셰이크는 잠들어 있는 인포테인먼트를 깨우고 시간이 걸립니다.

import universal "github.com/teslamotors/vehicle-command/pkg/protocol/protobuf/universalmessage"

// VCSEC만 핸드셰이크
if err := car.StartSession(ctx, []universal.Domain{protocol.DomainVCSEC}); err != nil { ... }
if err := car.Lock(ctx); err != nil { ... }

tesla-control은 -domain vcsec 플래그(반복 가능)와, body-controller-state 명령의 domain: protocol.DomainVCSEC 지정, 그리고 -ble wake일 때 VCSEC만 핸드셰이크하는 특별 처리를 통해 같은 일을 합니다.

INFOTAINMENT 세션 없이 Infotainment 명령을 보내면

protocol.ErrNoSession(cannot send authenticated command before establishing a vehicle session)이 즉시 반환됩니다. tesla-control은 이 오류를 "You must provide a private key…"로 안내합니다.

세션 캐시

핸드셰이크는 왕복 한 번을 추가하고, Fleet API에서는 요청 수를 늘립니다. pkg/cache로 세션 상태(도메인별 SessionInfo와 생성 시각)를 디스크에 저장하면 다음 실행 때 첫 명령을 바로 보낼 수 있습니다. 캐시가 낡았으면 첫 명령이 실패하면서 차량이 최신 세션 정보를 함께 보내주므로 SDK가 자동으로 갱신하고 재시도합니다. 즉 낡은 캐시를 써도 손해가 없습니다.

const cacheFile = "/var/lib/myapp/tesla-cache.json"

myCache, err := cache.ImportFromFile(cacheFile)
if err != nil {
    myCache = cache.New(5) // 최대 5대분. 0이면 무제한. LRU 축출.
}

car, err := vehicle.NewVehicle(conn, privateKey, myCache) // 생성 시 캐시에서 로드
...
defer func() {
    if err := car.UpdateCachedSessions(myCache); err != nil { log.Println(err) }
    if err := myCache.ExportToFile(cacheFile); err != nil { log.Println(err) }
}()
  • 캐시는 클라이언트 개인 키에 묶입니다. 다른 키로 캐시를 쓰면 첫 인증이 실패하고 차량이 새 세션 정보를 보내 정상 복구됩니다.
  • 여러 VIN을 한 캐시에 넣어도 됩니다. SessionCache.Vehicles는 VIN → 도메인별 엔트리 맵입니다.
  • 파일 접근 제어를 하세요. 캐시에는 차량 공개 키, epoch, 카운터, 시계 오프셋이 들어 있습니다. 개인 키는 없지만 제3자가 읽거나 변조하지 못하게 해야 합니다. ExportToFile은 0644로 만들므로 필요하면 권한을 좁히세요.
  • tesla-control과 프록시는 각각 TESLA_CACHE_FILE(기본 ~/.tesla-cache.json)과 메모리 내 캐시(최대 10000대)를 사용합니다.
  • SessionCache.Update/GetEntry는 내부 디스패처용이므로 Vehicle.UpdateCachedSessions를 쓰는 편이 좋습니다.

pkg/cli로 CLI 애플리케이션 만들기

pkg/cli.Config는 다섯 CLI 도구가 공유하는 플래그/환경 변수/키링 로직을 제공합니다. 자체 CLI를 만들 때 그대로 재사용할 수 있습니다.

import (
    "flag"
    "github.com/teslamotors/vehicle-command/pkg/cli"
)

config, err := cli.NewConfig(cli.FlagAll) // FlagVIN | FlagOAuth | FlagPrivateKey | FlagBLE
if err != nil { panic(err) }
config.RegisterCommandLineFlags()   // -vin, -key-name, -key-file, -token-name, -token-file, -session-cache, -domain, -keyring-type ...
flag.Parse()
config.ReadFromEnvironment()        // 비어 있는 값만 TESLA_* 환경 변수로 채움
if err := config.LoadCredentials(); err != nil { ... } // 키링 비밀번호 프롬프트를 타임아웃 전에 처리

ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
defer cancel()
acct, car, err := config.Connect(ctx) // OAuth가 있으면 인터넷, 없으면 BLE. Connect + StartSession(config.Domains)까지 수행
if err != nil { ... }
if car != nil {
    defer car.Disconnect()
    defer config.UpdateCachedSessions(car) // 캐시 파일 갱신
}
Flag 마스크등록되는 옵션
FlagVIN-vin / TESLA_VIN

  • config.PrivateKey()는 파일이 우선, 없으면 키링. 처음 로드 때 캐시 파일도 함께 읽습니다.

오류 처리 패턴

모든 SDK 오류는 가능하면 protocol.Error 인터페이스를 구현합니다. 두 메서드가 재시도와 사용자 안내를 결정합니다.

err := car.Unlock(ctx)
switch {
case err == nil:
    // 성공
case protocol.MayHaveSucceeded(err):
    // 명령이 도착했을 수 있지만 확인을 못 받음 (예: 타임아웃). 재전송하면 두 번 실행될 수 있으니 상태를 조회해 판단.
case errors.Is(err, protocol.ErrKeyNotPaired):
    // 공개 키가 차량에 등록되지 않음. 페어링 안내.
case errors.Is(err, protocol.ErrNoSession):
    // StartSession을 안 했거나 해당 도메인을 빼고 했음.
case protocol.IsNominalError(err):
    // 차량이 명령을 인증했지만 실행할 수 없음 (예: 주차 상태 아님, 이미 켜져 있음). 사용자에게 사유 표시.
case protocol.Temporary(err):
    // 일시적 오류. SDK가 이미 컨텍스트 만료까지 재시도했으므로 컨텍스트를 늘려 다시 시도.
default:
    // 그 외
}
도우미의미
protocol.MayHaveSucceeded(err)차량이 명령을 실행했을 가능성이 있음. 컨텍스트 타임아웃, 응답 파싱 실패, HTTP 5xx(503 제외) 등.
protocol.Temporary(err)사용자 개입 없이 재시도로 해결될 수 있음. ErrBusy, MESSAGEFAULT_ERROR_BUSY/TIMEOUT/INVALID_SIGNATURE/INVALID_TOKEN_OR_COUNTER/INTERNAL/INCORRECT_EPOCH/TIME_EXPIRED/TIME_TO_LIVE_TOO_LONG, HTTP 503/504/408/421.
protocol.ShouldRetry(err)Temporary이면서 MayHaveSucceeded가 아닌 경우만 참. SDK 내부 재시도 루프의 기준.
protocol.IsNominalError(err)애플리케이션 계층 거부(NominalError). 프록시는 이를 HTTP 200 + reason으로 돌려줍니다.
errors.As(err, &*protocol.RoutableMessageError)프로토콜 계층 오류. .Code로 MessageFault_E 확인.
errors.As(err, &*protocol.KeychainError)키 추가/삭제 실패. .Code는 WhitelistOperation_information_E.

전체 오류 코드 표와 시나리오별 대처는 9. 오류와 문제 해결을 보세요.

커스텀 Connector 구현

다른 BLE 스택(예: TinyGo, 모바일 브리지, 시리얼 게이트웨이)이나 테스트용 모의 전송을 붙이려면 connector.Connector를 구현해 vehicle.NewVehicle에 넘기면 됩니다. 디스패처는 커넥터를 순수한 데이터그램 통로로만 취급합니다.

type Connector interface {
    Receive() <-chan []byte                     // 차량이 보낸 RoutableMessage 바이트. 스레드 안전.
    Send(ctx context.Context, buffer []byte) error // RoutableMessage 바이트 전송. 스레드 안전.
    VIN() string
    Close()                                     // 여러 번 호출해도 안전해야 함
    PreferredAuthMethod() AuthMethod            // BLE: AuthMethodGCM, HTTP: AuthMethodHMAC
    RetryInterval() time.Duration               // 재전송 간격 (BLE/inet 모두 1초)
    AllowedLatency() time.Duration              // 세션 정보 응답의 최대 허용 지연 (BLE 4초, inet 10초)
}

type FleetAPIConnector interface {             // 인터넷 커넥터만 추가 구현
    Connector
    SendFleetAPICommand(ctx context.Context, endpoint string, command interface{}) ([]byte, error)
    Wakeup(ctx context.Context) error
}
  • Receive() 채널의 버퍼는 connector.BufferSize(5) 정도를 권장합니다. BLE 구현은 5, inet도 5를 씁니다. 가득 차면 BLE는 청크를 버리고, inet은 dropped response because inbox is full 오류를 냅니다.
  • Send가 반환하는 오류가 protocol.Error를 구현하면 디스패처가 ShouldRetry로 재전송을 판단합니다. 일반 오류는 종단 오류로 취급됩니다.
  • 응답은 connector.MaxResponseLength(100000바이트)까지 지원해야 합니다. BLE 구현은 메시지당 1024바이트(maxBLEMessageSize)로 제한합니다.
  • BLE라면 2바이트 빅엔디언 길이 프레이밍과 MTU 분할을 커넥터 안에서 처리해야 합니다. 디스패처는 프레이밍을 모릅니다.
  • 세션 정보 응답이 AllowedLatency보다 늦게 오면 시계 동기화용으로 버려지므로, 지연이 큰 전송은 값을 늘리거나 Vehicle.SetMaxLatency로 조정하세요.
  • FleetAPIConnector를 구현하면 Vehicle.Wakeup이 그것을 쓰고, SetPINToDrive가 허용되며, SendAddKeyRequest는 거부됩니다.

HSM/TEE 통합 시 주의

protocol.ECDHPrivateKey는 인터페이스이고 protocol.Session이 재노출되어 있어 외부 모듈에서도 구현할 수 있습니다(pkg/protocol/external_impl_test.go가 예). 개인 키를 Nitro Enclave, KMS, 하드웨어 HSM에 두려면 Exchange(remotePublicBytes) (Session, error), PublicBytes(), SchnorrSignature(message)를 TEE 호출로 프록시하는 타입을 만듭니다. pkg/protocol/key.go의 주석이 요구하는 조건:

  • TEE는 ECDH 공유 비밀을 내보내는 API를 노출하면 안 됩니다.
  • TEE는 ECDH 유도 키로 동작하는 범용 AES 인터페이스를 노출하면 안 됩니다(호스트가 무결성 키를 계산할 수 있음).
  • TEE는 호스트가 nonce를 지정하는 AES-GCM 암호화 인터페이스를 노출하면 안 됩니다.
  • Session 객체에는 유도된 비밀을 넣지 말고 TEE 핸들만 넣습니다.

이 조건을 만족하지 못해도, 호스트가 침해되었을 때 이미 알려진 차량 공개 키에 대한 장기 공유 비밀만 유출된다는 점에서 여전히 가치가 있을 수 있습니다. 파일 기반 저장을 쓸 때는 SavePrivateKey가 0600으로 저장한다는 점과 키링 옵션(키링)을 활용하세요.

로깅, 빌드, 테스트

  • 로깅. SDK는 internal/log로 stderr에 [debug]/[info ]/[warn ]/[error]를 찍습니다. 외부 모듈은 레벨을 직접 바꿀 수 없으므로, CLI 도구의 -debug/-verbose 또는 환경 변수 TESLA_VERBOSE(tesla-control, tesla-http-proxy)를 씁니다. 자체 애플리케이션에서 디버그 로그가 필요하면 저장소를 포크하거나 examples/ble처럼 저장소 안의 프로그램으로 빌드해야 합니다(examples/ble/main.go는 internal/log를 임포트할 수 있는 저장소 내부 코드입니다).
  • 디버그 출력 해석. TX: 32020802…/RX: …는 RoutableMessage의 16진수입니다. protoc --decode=UniversalMessage.RoutableMessage -I pkg/protocol/protobuf pkg/protocol/protobuf/*.proto로 디코드합니다(절차).
