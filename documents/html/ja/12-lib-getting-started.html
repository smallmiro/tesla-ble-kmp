12. ライブラリ入門

ライブラリの作成、キーの取得、車両の検索、接続、状態の読み取り、切断までの全体の流れを説明します。最後の節では、新しいキーのペアリングと最初のコマンドの送信 (M4) を示します。

このページの内容
  1. 全体の流れ
  2. 5 つのルール
  3. Kotlin (Android)
  4. Swift (iOS)
  5. ペアリングしてからロック
  6. 次のステップ

全体の流れ

  1. ライブラリを作成します。 TeslaBle.create(platform, config) をアプリごとに 1 回呼びます。
  2. キーを取得します。 ble.keys.getOrCreate() はスマートフォンの P-256 キーを返し、初回はセキュアハードウェア内に作成します。
  3. 車両を見つけます。 ble.scan(vin) は車両のアドバタイズを流します。最初の 1 件を使います。
  4. 接続します。 ble.connect(vin, key, advertisement) は Vehicle を返します。
  5. 読み取ります。 vehicleStatus()、keySummary()、listKeys() を使います。
  6. 後片付けをします。 vehicle.disconnect() を呼び、アプリの終了時に ble.close() を呼びます。

5 つのルール

  • 結果は値です。 車両やキーストアへの呼び出しはすべて VehicleResult (Success、Uncertain、Failure) を返します。自分のコルーチンがキャンセルされた場合を除き、例外は投げられません。
  • TeslaBle はアプリに 1 つです。 使い終わったら close() を呼びます。まだ接続中の車両があれば、それも切断されます。
  • 必ず切断します。 リンクがすでに切れていても vehicle.disconnect() を呼びます。セッションキャッシュを保存し、セッションキーを消去し、車両の BLE スロットを解放します。2 回呼んでも問題ありません。
  • 読み取りにキーは必須ではありません。 3 つのクエリには connect(vin, key = null) で十分です。セッションの開始にはキーが必要です。
  • デバッグログは開発時のみ使います。 DebugLogger() はプラットフォームのログに出力します。リリースビルドには含めないでください。

Kotlin (Android)

import dev.mirolab.teslable.*
import dev.mirolab.teslable.model.*
import dev.mirolab.teslable.port.*
import kotlinx.coroutines.flow.first

suspend fun demo(context: android.content.Context, vinText: String) {
    val vin = Vin.parseOrNull(vinText) ?: return              // 17 文字の形式チェック
    val ble = TeslaBle.create(
        PlatformContext(context),
        TeslaBleConfig.default(logger = DebugLogger()),         // 開発用ロガー、リリースビルドでは使わない
    )
    try {
        val key = when (val r = ble.keys.getOrCreate()) {       // デフォルトのエイリアス、ハードウェア優先
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: KeyStoreError
        }

        // 最初のアドバタイズを使う。制限時間は呼び出し側で設定する (例: withTimeoutOrNull)。
        val event = ble.scan(vin).first()
        val target = (event as? ScanEvent.Found)?.advertisement ?: return   // Failed の場合は event.error を参照

        val vehicle = when (val r = ble.connect(vin, key, target)) {
            is VehicleResult.Success -> r.value
            is VehicleResult.Uncertain -> return
            is VehicleResult.Failure -> return                  // r.error: TransportError など
        }
        try {
            println(vehicle.vehicleStatus())                    // println ではなく UI に表示する
            println(vehicle.listKeys())
        } finally {
            vehicle.disconnect()                                // スロットを解放する。リンクが切れた後でも呼ぶ
        }
    } finally {
        ble.close()                                             // suspend。まだ接続中の車両があれば切断する
    }
}

これらの呼び出しの前に、実行時に BLUETOOTH_SCAN と BLUETOOTH_CONNECT を要求してください。プラットフォームノート を参照してください。

Swift (iOS)

SKIE は suspend 関数を async throws に、Flow を AsyncSequence に変換し、switch onEnum(of:) で結果のすべてのケースを網羅できるようにします。コードは samples/ios/Sources/SampleModel.swift と同じ形です。

import Teslable

let ble = TeslaBle.companion.create(
    platform: PlatformContext(),
    config: TeslaBleConfig.companion.default(logger: DebugLogger())
)

func run(vinText: String) async {
    guard let vin = Vin.companion.parseOrNull(value: vinText) else { return }   // 形式が不正

    // 1) キー
    var key: VehicleKey?
    do {
        let result = try await ble.keys.getOrCreate(alias: VehicleKeyStoreCompanion.shared.DEFAULT_ALIAS, policy: .preferHardware)
        switch onEnum(of: result) {
        case .success(let s): key = s.value as? VehicleKey
        case .uncertain(let u): print("不確実: \(u.error.message)")
        case .failure(let f): print("失敗: \(f.error.message)")
        }
    } catch { print("エラー: \(error)") }

    // 2) スキャン (最初のアドバタイズで止める。制限時間は Task のキャンセルで設定する)
    for await event in ble.scan(vin: vin) {
        switch onEnum(of: event) {
        case .found(let f): print("\(f.advertisement.localName.value) rssi=\(f.advertisement.rssi)")
        case .failed(let e): print("スキャン失敗: \(e.error.message)")
        }
        break
    }

    // 3) 接続とクエリ
    do {
        let connected = try await ble.connect(vin: vin, key: key, target: nil, options: ConnectOptions(timeout: nil))
        switch onEnum(of: connected) {
        case .success(let s):
            guard let vehicle = s.value as? Vehicle else { return }
            let status = try await vehicle.vehicleStatus(timeout: nil)
            switch onEnum(of: status) {
            case .success(let v): print("状態: \(String(describing: v.value))")
            case .uncertain(let u): print("不確実: \(u.error.message)")   // 再送せず、もう一度クエリする
            case .failure(let f): print("失敗: \(f.error.message)")
            }
            try await vehicle.disconnect()
        case .uncertain(let u): print("不確実: \(u.error.message)")
        case .failure(let f): print("失敗: \(f.error.message)")
        }
    } catch { print("エラー: \(error)") }
}

target: nil の場合、connect は自分でスキャンします。Info.plist に NSBluetoothAlwaysUsageDescription を追加してください。プラットフォームノート を参照してください。

ペアリングしてからロック

新しいスマートフォンのキーを初めて使うときは、キーカードで登録し、車両の一覧に載るまで待ってから、VCSEC セッションを開始してコマンドを送ります。イベントの扱いは 13. キーとペアリング、コマンドは 15. コマンド で説明します。

Kotlin

// vehicle was connected with `key` (see above)
vehicle.addKeyRequest(key.publicKey).collect { event -> render(event) }      // user taps the key card, confirms on screen
if (waitUntilEnrolled(vehicle, key)) {                                       // polls sessionInfo(…, INFOTAINMENT), see chapter 13
    vehicle.startSession(setOf(VehicleDomain.VCSEC))
    val result = vehicle.lock()                                              // VehicleResult<Unit>; Uncertain: vehicleStatus(), do not resend
}

Swift

for await event in vehicle.addKeyRequest(publicKey: key.publicKey, role: .owner, formFactor: .iosDevice, timeout: nil) {
    render(event)                                                            // user taps the key card, confirms on screen
}
// poll vehicle.sessionInfo(publicKey:domain:timeout:) until success (chapter 13), then:
_ = try await vehicle.startSession(domains: [.vcsec], timeout: nil)
let result = try await vehicle.lock(timeout: nil)

Kotlin のデフォルト引数は Swift のオーバーロードにならないため、Swift ではすべての引数を明示的に渡します。

次のステップ

  • キーの登録とペアリングイベント: 13. キーとペアリング。vehicleStatus()、keySummary()、listKeys() は引き続き connect(vin, key = null) だけで使えます。
  • リンクは vehicle.connection、セッションは vehicle.sessions で監視します。どちらも StateFlow です。リンクが Disconnected を報告した場合でも、disconnect() は自分で呼んでください。
