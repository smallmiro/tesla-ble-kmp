오류 모델

SDK가 반환하는 오류는 가능한 한 protocol.Error 인터페이스를 구현합니다. 두 메서드가 호출자가 해야 할 일을 결정합니다.

type Error interface {
    error
    MayHaveSucceeded() bool // 차량이 명령을 받아 실행했을 수 있음 (확인 불가)
    Temporary() bool        // 사용자 개입 없이 재시도로 해결될 수 있음
}
타입계층MayHaveSucceededTemporary설명
*protocol.CommandError범용필드 PossibleSuccess필드 PossibleTemporaryprotocol.NewError(msg, mayHaveSucceeded, temporary)로 생성. 컨텍스트 만료 시 {ctx.Err(), true, true}로 감싸짐. Unwrap() 지원
*protocol.RoutableMessageError프로토콜ERROR_NONE, RESPONSE_MTU_EXCEEDED만 true표의 재시도 가능 코드만 true차량의 signedMessageStatus.signed_message_fault. .Code는 universal.MessageFault_E. Error()는 enum 이름
*protocol.NominalError애플리케이션Details에 위임Details에 위임차량이 명령을 인증했지만 실행 불가. Infotainment는 car could not execute command: <사유>, VCSEC는 NominalVCSECError를 감쌈. 프록시는 HTTP 200 + reason으로 변환
*protocol.NominalVCSECError애플리케이션falsefalseFromVCSECMessage.nominalError. .Details.GetGenericError()가 GenericError_E
*protocol.KeychainError애플리케이션falsefalse키 추가/삭제 실패. .Code는 WhitelistOperation_information_E. 메시지 keychain operation failed: <코드>
*inet.HTTPError전송(HTTP)4xx와 503은 false, 그 외 true503, 504, 408, 421Fleet API가 200 이외를 돌려줌. .Code, .Message(본문)

도우미 함수 protocol.MayHaveSucceeded(err), protocol.Temporary(err), protocol.ShouldRetry(err), protocol.IsNominalError(err)는 errors.As로 래핑을 뚫고 검사합니다. 커밋 a4b43c1에서 래핑된 프로토콜 오류의 분류가 수정되었으므로 fmt.Errorf("%w")로 감싼 오류도 올바르게 분류됩니다.

재시도 정책

func ShouldRetry(err error) bool {
    // Error 인터페이스를 구현하고, MayHaveSucceeded()가 false이며, Temporary()가 true일 때만 true
}

SDK는 다음 지점에서 ShouldRetry가 참인 동안 커넥터의 RetryInterval()(BLE, inet 모두 1초) 간격으로 컨텍스트가 만료될 때까지 재시도합니다.

지점재시도 대상비고
Vehicle.StartSession핸드셰이크 전체디스패처는 응답이 RetryInterval 안에 오지 않으면 요청을 다시 보냄
Vehicle.Send (Infotainment 명령)전송 + 응답 대기재시도 시 카운터가 새로 증가한 새 메시지를 만듦
getVCSECResult (VCSEC 명령)전송 + 종단 응답 대기OPERATIONSTATUS_WAIT는 ErrBusy로 변환되어 재시도
Dispatcher.Send커넥터 Send 자체동일 바이트 재전송(카운터 불변). 커넥터가 protocol.Error를 반환할 때만
inet.Connection.Wakeupwake_up 폴링10초 간격, state == "online"까지. Temporary 오류만 계속
ble.NewConnectionFromScanResult스캔/다이얼/서비스 탐색어댑터 오류(IsAdapterError)와 잘못된 Local Name, 연결 불가 비콘은 즉시 실패. 그 외는 컨텍스트 만료까지 반복
MayHaveSucceeded가 참인 오류는 자동 재시도하지 않습니다

컨텍스트 타임아웃, 응답 파싱 실패 등은 차량이 이미 명령을 실행했을 수 있으므로 SDK가 재전송하지 않습니다. 잠금 해제나 트렁크 열기처럼 두 번 실행되면 곤란한 명령은 BodyControllerState나 GetState로 상태를 확인한 뒤 결정하세요. tesla-control은 이 경우 Couldn't verify success: …를 출력합니다.

Infotainment 애플리케이션 계층 오류

Infotainment 응답 carserver.Response.actionStatus.result가 OPERATIONSTATUS_ERROR이면 result_reason.plain_text가 NominalError의 메시지가 됩니다: car could not execute command: <plain_text>. 텍스트가 비어 있으면 unspecified error. 코드에 언급된 예: already off(발렛 해제 시 성공으로 처리), low_power_mode_enforced, parental_controls_active. 프록시는 이 문자열을 reason으로 돌려줍니다.

디버깅 도구

TX/RX 덤프 디코딩

tesla-control -debug(또는 TESLA_VERBOSE=1)는 송수신한 RoutableMessage를 16진수로 출력합니다.

2023-12-13T14:41:13-08:00 [debug] TX: 320208023a1212100a7962c10d38b61dd2a7722780a4f0969a031005514f57616bcc81a8ce0f9d7b48322952040a020805

protoc로 디코드합니다(저장소 루트에서 실행).

cd vehicle-command/pkg/protocol
echo 320208023a1212100a7962c10d38b61dd2a7722780a4f0969a031005514f57616bcc81a8ce0f9d7b48322952040a020805 \
    | xxd -r -p \
    | protoc --decode=UniversalMessage.RoutableMessage -I protobuf protobuf/*.proto

# 출력의 protobuf_message_as_bytes 를 도메인에 맞는 타입으로 다시 디코드
printf "\n\002\010\005" | protoc --decode=VCSEC.UnsignedMessage -I protobuf protobuf/*.proto      # VCSEC 요청
printf "..." | protoc --decode=VCSEC.FromVCSECMessage -I protobuf protobuf/*.proto              # VCSEC 응답
printf "..." | protoc --decode=CarServer.Action -I protobuf protobuf/*.proto                    # Infotainment 요청
printf "..." | protoc --decode=CarServer.Response -I protobuf protobuf/*.proto                  # Infotainment 응답

BLE에서는 AES-GCM으로 암호화되므로 protobuf_message_as_bytes가 암호문입니다. 평문을 보려면 -debug 로그의 요청 구성 시점 로그나 세션 키를 알아야 합니다. 핸드셰이크 메시지와 응답의 오류 필드(signedMessageStatus)는 평문입니다.

보안 주의

  • 테스트 키를 실제 차량에 등록하지 마세요. pkg/protocol/protocol.md와 internal/authentication/test_data/, pkg/protocol/test/의 키는 공개되어 있습니다.
  • 세션 캐시 파일 권한. ~/.tesla-cache.json은 개인 키를 담지 않지만 세션 상태를 담습니다. 제3자가 읽거나 변조하지 못하게 하세요. 변조된 캐시는 첫 명령 실패 후 자동 복구되지만 불필요한 실패를 만듭니다.
  • 개인 키 내보내기. tesla-keygen export 출력과 -key-file 파일은 등록된 모든 차량에 대한 명령 권한입니다. 0600 권한, 버전 관리 제외, 백업 암호화.
  • 디버그 로그. -debug 출력에는 공개 키, epoch, 카운터, 암호문이 포함됩니다. 개인 키나 세션 키는 출력되지 않지만 로그를 공개 이슈에 올릴 때는 VIN을 가리세요.
