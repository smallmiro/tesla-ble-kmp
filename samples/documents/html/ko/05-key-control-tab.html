5. 키·제어 탭

처음 쓰는 사용자의 일상 경로를 위해 모니터 앱에 더한 다섯 번째 탭입니다. 키를 만들고, 차에 등록하고, 버튼으로 차를 제어합니다. Control 탭은 호출마다 버튼이 따로 있는 진단 화면으로 그대로 두고, 이 탭은 호출 순서를 네 단계와 버튼 그리드 뒤에 감춥니다.

Android와 iOS 구현 완료, 실기기 확인 대기

Android 빌드 0.3.0 (3), iOS 빌드 0.5.0 (18). 단계 규칙과 명령 실행기는 단위 테스트로 확인했고, 화면과 차는 이 페이지 끝의 체크리스트로 확인합니다.

요구사항

ID앱이 하는 일
SFR-018Control 다음에 키·제어 탭. 네 단계를 각각 완료, 해야 함, 한 줄 힌트가 있는 막힘으로 표시합니다. (1) 키: 모니터 키를 만들거나 불러옵니다. (2) 연결: 저장된 VIN과 모니터의 연결을 씁니다. (3) 등록: 등록을 요청하고(콘솔에 키 카드), 진행 줄을 보여 주며, 자동으로 확인합니다. (4) 제어: 사용 가능한 VCSEC 명령의 버튼 그리드. 모든 명령은 먼저 VCSEC 세션이 있는지 확인한 뒤 한 번만 보내며, Uncertain 결과는 다시 보내지 않고 vehicleStatus() 재조회가 이어집니다. 상태 카드는 마지막 vehicleStatus()의 잠금, 트렁크, 프렁크, 절전 상태를 보여 줍니다.

단계와 버튼이 켜지는 조건

규칙은 순수 함수 하나(KeyControlSteps)이므로 차 없이 테스트합니다. 입력은 키 준비 여부, 휴대폰 잠금으로 키가 잠겼는지, VIN 저장 여부, 키를 가진 연결 여부(Connected이고 vehicle.hasKey. 연결할 때 키 저장소 오류가 나면 키 없이 연결됩니다. 이때 2단계는 "해야 함"으로 남고 버튼이 연결 끊고 다시 연결로 바뀌어, 모니터 연결을 멈춘 뒤 키를 가지고 다시 연결합니다), 등록 상태, 이 탭의 호출이 실행 중인지입니다.

3 등록등록 상태가 enrolled키가 준비되지 않았거나 연결되지 않음(1, 2단계를 먼저 끝내세요)키 준비됨, 연결됨, 등록 상태가 enrolled 또는 checking이 아님, 실행 중인 것이 없음
4 제어–등록 상태가 enrolled가 아님(키가 등록되면 버튼이 켜집니다)키 준비됨, 연결됨, 등록 상태가 enrolled, 실행 중인 것이 없음

버튼 두 개가 더 있습니다. 등록 상태 확인은 키가 준비되고, 연결되어 있고, 등록 상태가 checking이 아니며, 실행 중인 호출이 없을 때 켜집니다(enrolled여도 켜져 있어 차에서 지운 키를 다시 확인할 수 있습니다). 상태 새로고침은 연결되어 있고 실행 중인 호출이 없을 때 켜집니다(vehicleStatus()는 키가 필요 없습니다).

등록 상태

등록 상태는 unknown, checking, notEnrolled, enrolled 중 하나입니다.

  • 탭은 listKeys()로 확인합니다. 차의 항목 중 공개 키가 로컬 키와 같은 것을 찾습니다(매뉴얼 13장). 확인하는 동안은 checking이고, 끝나면 enrolled 또는 notEnrolled이며, 결과가 Uncertain 또는 Failure이면 unknown입니다. 확인은 키가 준비된 상태에서 탭이 새 연결을 볼 때마다 한 번(unknown으로 끝나면 약 5초 뒤 한 번 다시 시도합니다. 모니터의 첫 조회와 경합에서 질 수 있기 때문입니다), 탭이 보일 때마다, 그리고 등록 상태 확인을 누를 때 실행됩니다. 자동 확인은 "먼저 연결하세요" 줄을 남기지 않습니다.
  • 페어링 확인이 성공하면 enrolled가 됩니다. sessionInfo(publicKey, INFOTAINMENT)를 3초마다 최대 2분 동안 호출합니다. 매뉴얼의 waitUntilEnrolled처럼 KeyNotPaired와 Uncertain에서는 계속 폴링하고, 그 밖의 실패(예: 링크가 끊긴 뒤의 NotConnected)에서는 즉시 멈춥니다.
  • Control 탭이 등록을 확인하거나 이 기기의 키를 제거하면 다시 확인합니다.
  • 명령 전의 세션, 또는 명령 자체(세션이 이미 Ready였으므로 그 명령은 아무것도 보내지 않았습니다)가 KeyNotPaired로 실패하면 notEnrolled가 됩니다.
  • 연결이 끊기거나 키가 바뀌면 unknown으로 돌아갑니다.

등록 진행 팝업

키 등록 요청(3단계)을 누르면 막는 시트가 바로 열리고 흐름이 끝날 때까지 유지됩니다. 기존 흐름(addKeyRequest, 이어서 매뉴얼 13장 "Enrolling a key"의 확인)을 세 줄과 메시지 하나로 보여 줍니다. iOS 구현 완료, Android: 예정, 같은 스펙. Control 탭의 키 등록 요청은 결과 줄만 남기고 팝업이 없습니다.

키 삭제 후 다시 만들기

1단계에는 두 번째 버튼 키 삭제 후 다시 만들기가 있어 모니터 키 teslable-monitor를 새 키로 바꿉니다(예: 차에서 키를 완전히 지웠거나 저장된 키가 손상된 경우). iOS 구현 완료, Android: 예정, 같은 스펙. 라이브러리 매뉴얼: 13장 "Deleting or replacing a key locally"와 "Key accessibility", 17장 "Session cache".

규칙내용
활성 조건다른 호출이 없고(이 탭의 호출, 또는 Control 탭의 페어링·명령. 있으면 결과가 "사용 중, 나중에 다시 누르세요"라고 알리고 아무것도 바뀌지 않음), 그리고 키가 준비되어 잠겨 있지 않거나 저장된 키가 손상되었을 때(다음 줄). 그 밖의 키 오류(아직 읽지 않음, 다른 keys.get 실패)에서는 꺼 둡니다. 연결은 필요 없습니다.
확인무엇이든 바꾸기 전에 항상 묻습니다. 문구: 옛 키는 이 폰에서 영구히 지워지며 복구할 수 없다, 차량에는 차량에서 지우기 전까지(차량 화면, 또는 이미 등록된 다른 키의 removeKey) 옛 공개키가 그대로 남는다, 새 키는 등록되어 있지 않으므로 키카드로 다시 등록해야 한다(3단계), 연결을 끊고 다시 연결한다.
잠금먼저 키 저장소를 읽습니다(keys.get(alias)). KeyStoreError.Locked이면 연결도 포함해 아무것도 바꾸지 않고 폰 잠금을 풀라고 알립니다(매뉴얼: Locked에서는 지우거나 다시 만들지 않는다). 지우는 중의 Locked는 옛 키를 되돌리고 다시 연결하며, 만드는 중의 Locked는 만들기 실패로 봅니다(다시 시도하지 않음).
손상된 키cause가 정확히 stored key is corrupted인 KeyStoreError.PlatformFailure(정확히 같을 때만 손상이며 부분 일치는 쓰지 않습니다: 라이브러리는 message 앞에 "key store failure: "를 붙이고, 오탐이면 건강한 등록 키를 확인 뒤 지우게 됩니다)(매뉴얼 13장 "Deleting or replacing a key locally", 16장, 17장 "Key storage")가 문서에 적힌 유일한 손상 경우입니다. 키 상태가 corrupted가 되고, 1단계가 그렇게 알리고, 버튼이 켜지고, 읽기 관문이 이를 받아들입니다(키를 읽을 수 없는 것이 요점): 지운 뒤 만듭니다. 확인 창은 손상된 옛 키를 복구할 수 없다는 말도 합니다. 라이브러리는 손상된 키를 스스로 바꾸지 않으며, 앱은 이 확인 뒤에만 바꿉니다.
다른 탭과 겹친 연결엔진 수준의 문(KeyOperationGate)이 모든 탭을 덮습니다. Control 탭의 호출이 도는 동안 교체는 거부되고(busy), 교체 중에는 Control 탭의 호출이 거부되며, connectNow, 자동 연결, 잠금 해제 뒤 재시도, ensureKey()는 교체 중에 아무것도 하지 않으므로 Live나 Control 탭에서 누른 연결이 옛 핸들을 잡을 수 없습니다. 사용자가 마지막에 누른 것이 이깁니다(SFR-012): 교체 중에 누른 연결은 기억해 두었다가, 교체가 쓸 수 있는 키로 끝나면(성공, 또는 옛 키 그대로) 따르며 쓰던 연결이 없었어도 마찬가지입니다. 그 사이에 누른 연결 끊기나 VIN 지우기는 다시 연결을 취소하므로 멈춤이 되돌려지지 않습니다. 쓸 수 있는 키 상태 없이 끝나면(만들기 실패, lost, unverified, unknownLocked) 아무것도 연결하지 않고 결과가 그렇게 알립니다. 키 핸들 캐시에는 세대가 있어, 핸들을 버린 뒤에 끝난 읽기는 캐시에 오르지 않으므로 지워진 키가 캐시에 남지 않습니다. 연결을 끊은 뒤 교체기가 연결이 남지 않았는지 확인하고, 남아 있으면 아무것도 지우지 않습니다. 그러므로 replaced는 옛 키 연결과 함께 보고되지 않습니다.
순서(KeyReplacer, 순수)키 저장소 읽기, 연결 끊기(모니터 연결이 동작 중이었을 때만: 연결 중, 연결됨, 재시도 대기. 사용자가 멈춰 둔 연결은 멈춘 채로), 키 핸들 버리기, keys.delete(alias), 1단계와 같은 설정의 keys.getOrCreate(alias, PREFER_HARDWARE, AFTER_FIRST_UNLOCK), 새 키로 다시 연결(연결이 동작 중이었거나 그 사이에 연결을 눌렀고 그 뒤에 연결 끊기를 누르지 않았을 때).
연결을 먼저 끊는 이유살아 있는 Vehicle과 그 세션, 세션 캐시는 옛 키의 것입니다(캐시는 공개키 SHA-1로 구분). 키가 바뀐 뒤 다음 connect는 옛 캐시를 버리고 핸드셰이크를 다시 하므로 옛 연결은 두지 않습니다.
지우기 실패새 키를 만들지 않습니다. 옛 키를 다시 읽고(keys.get, getOrCreate는 쓰지 않음) 결과는 읽은 내용을 따릅니다: 키가 있으면 옛 키가 그대로이고 연결이 동작 중이었으면 다시 연결합니다. 그래도 키가 없으면(lost) 아무것도 만들지 않고 다시 연결도 하지 않습니다(연결하면 키가 조용히 만들어짐). 상태를 읽지 못하면(unverified) 마찬가지로 다시 연결하지 않고 1단계 "다시 불러오기"를 누르라고 알립니다. 지우기가 실패한 뒤 키 저장소가 잠겨 있으면 키가 지워졌는지 아무도 모르므로(unknownLocked) 다시 연결도 하지 않고(잠금 해제 뒤 연결하면 키가 조용히 만들어짐), 폰을 잠금 해제하고 1단계 "다시 불러오기"를 누르기 전까지 상태를 알 수 없다고 알립니다.
만들기 실패옛 키는 없어졌고 새 키도 없습니다. 조용한 재시도도 재연결도 없으며, 결과가 1단계를 누르라고 알립니다.
성공한 뒤3단계는 "등록되지 않음"으로 돌아갑니다(새 키는 차량에 없고, 다시 연결한 뒤의 확인이 그것을 확인합니다). 상태 카드와 등록 진행 줄은 옛 키의 연결에서 온 것이라 지웁니다. Control 탭의 키 목록과 키 정보도 지웁니다.
별명키 별명(SFR-019)은 옛 키 ID에 속하며 거기 남습니다. 새 키로 옮기지 않습니다.

명령 실행

KeyControlRunner.run(ensureSession, command, requery)는 순수 함수이며 페이크로 테스트합니다.

  1. ensureSession은 startSession(setOf(VCSEC))입니다. 이미 Ready인 도메인은 요청 없이 성공합니다. Failure(또는 Uncertain)이면 명령을 보내지 않고 재조회도 하지 않으며, 결과 줄에 이유를 보여 줍니다. KeyNotPaired는 등록 상태를 notEnrolled로 바꾸고, KeyStoreError.Locked는 휴대폰 잠금 해제를 요청합니다.
  2. command는 정확히 한 번 호출합니다.
  3. Success는 "성공"을, Failure는 메시지와 함께 "실패"를, Uncertain은 메시지와 함께 "불확실"을 보여 주며 다시 보내지 않습니다.
  4. requery(vehicleStatus())는 명령 뒤에 항상 실행됩니다. Success 뒤에는 상태 카드를 갱신하고, Uncertain 뒤에는 매뉴얼이 요구하는 재조회입니다. 재조회가 실패하면 같은 결과 줄에 덧붙입니다.

대화상자를 확인하면 4단계 규칙을 다시 검사합니다. 더 이상 맞지 않거나 다른 호출이 실행 중이면 아무것도 보내지 않고 이유를 결과 줄에 남깁니다. Model X와 Cybertruck 버튼은 접혀 있는 "다른 차종" 섹션에 있습니다. 인포테인먼트 명령(공조, 충전, 경적, 조명)은 M5를 기다리므로 보이지 않습니다. 탭에는 상태 새로고침 버튼이 있는 상태 카드(잠금, 트렁크, 프렁크, 절전, 마지막으로 읽은 시각)와, 최신 줄이 맨 위에 오고 시각이 붙으며 VIN이 없는 결과 목록도 있습니다. 상태 카드는 한 연결에 속합니다. 연결이 바뀌면 지워지고, 연결이 바뀐 뒤에 끝난 재조회는 카드를 바꾸지 않습니다.

이 탭의 모든 라이브러리 호출은 탭 자체의 exclusive { }로 한 번에 하나씩 실행되며, 호출이 실행되는 동안 버튼은 꺼집니다. Android에서는 뷰 모델의 스코프에서 실행되므로 탭을 바꾸거나 휴대폰을 회전해도 취소되지 않습니다. Control 탭에는 별도의 가드가 있고, 라이브러리가 연결마다 VCSEC 명령을 직렬화하므로 두 탭에서 누른 것이 전송 중에 뒤섞이지 않습니다.

실차 체크리스트

  1. 새로 설치: 1단계가 "해야 함"으로 보입니다. 누르면 키가 만들어지고 1단계가 완료됩니다.
  2. VIN이 저장되어 있고 차가 근처에 있음: 연결하면 2단계가 완료되고, 등록 확인이 실행됩니다(checking, 새 키라면 이어서 notEnrolled).
  3. 3단계: 누르고, 콘솔에 키 카드를 올리고, 차 화면에서 승인합니다. 진행 줄이 나타나고 enrolled가 되며 4단계 버튼이 켜집니다.
  4. 잠금, 잠금 해제, 깨우기: 결과가 "성공"이고 상태 카드가 따라 바뀝니다.
  5. 트렁크 토글과 닫기, 확인 대화상자가 뜨는 프렁크.
  6. 키가 아직 등록된 상태에서 다시 설치: 연결 뒤 확인 결과가 다시 페어링하지 않고도 enrolled입니다.
  7. 차 화면에서 키를 삭제하고 명령을 누릅니다: 세션이 KeyNotPaired로 실패하고 3단계가 "해야 함"으로 돌아갑니다.

SFR-020, 키 삭제 후 다시 만들기(iOS 절차는 samples/ios/README.md):

  1. 키 삭제 후 다시 만들기를 누릅니다: 대화상자가 네 가지(이 폰에서 영구 삭제, 차량에 옛 공개키가 남음, 키카드로 다시 등록, 연결을 끊음)를 말합니다. 취소하면 아무것도 바뀌지 않습니다.
  2. 연결되어 있고 등록된 상태에서 확인합니다: 연결이 끊겼다가 돌아오고, 1단계는 완료로 남고, 확인 뒤 3단계는 "등록되지 않음"이 되고, 상태 카드에는 옛 연결의 값이 없고, Control 탭 키 목록은 비어 있습니다. 이어서 키 목록을 누르면 차량에 옛 공개키가 보이고 "이 기기" 표시 행은 없습니다.
  3. 새 키를 등록합니다(3단계). 옛 키 ID에 붙인 별명은 새 키에 나타나지 않습니다.
  4. 재시작 뒤 첫 잠금 해제 전: 버튼이 꺼져 있거나, 결과가 키 저장소가 잠겨 있고 아무것도 바뀌지 않았다고 알립니다(키를 지우지 않았고 연결도 그대로).
  5. VIN은 저장되어 있지만 연결을 끊은 상태(연결 끊기를 누름): 새 키가 만들어지고 연결은 시작되지 않습니다.

SFR-020, 손상된 키와 다른 탭(iOS 절차: samples/ios/README.md):

  1. 손상된 키(재현할 수 있을 때만. 예: 래핑 키 없이 복원한 Android, iOS에서는 어려움): 1단계가 키가 손상되었다고 알리고 버튼이 켜지며, 확인 창에 옛 키를 복구할 수 없다는 말이 더해지고, 확인하면 새 키가 생깁니다. stored key is corrupted가 아닌 키 오류에서는 버튼이 꺼진 채입니다.
  2. 겹친 누름: Control 탭에서 키 등록 요청을 시작하고 교체 버튼을 누릅니다: 결과가 사용 중이라고 알립니다. 교체를 누르고 도는 동안 Live 탭의 연결을 누릅니다: 새 키가 생길 때까지 연결이 시작되지 않고, 그 뒤 앱이 새 키로 다시 연결합니다(누른 연결을 기억해 두었기 때문이며, 그 전에 아무것도 동작하지 않았어도 마찬가지). 도는 동안 Live 탭의 연결 끊기를 누르면 교체 뒤에도 끊긴 채로 남습니다.

SFR-021, 등록 진행 팝업(iOS 절차는 samples/ios/README.md):

  1. 키 등록 요청을 누릅니다: 시트가 바로 열리고, 요청을 보냈으니 중앙 콘솔에 키카드를 대고 차 화면에서 승인하라고 알립니다.
  2. 카드를 대고 승인합니다: 시트가 확인 중으로 바뀌며 시도 번호, 경과·남은 시간을 보이고, 이어서 "완료"와 닫기가 나옵니다. 3단계가 완료되고 4단계 버튼이 켜집니다.
  3. 2분 동안 승인하지 않습니다: 안내와 함께 "2분 안에 확인되지 않았습니다", 닫기, 등록 상태 확인이 동작합니다.
  4. 기다리는 중에 취소를 누릅니다: 시트가 멈추는 중이라고 알린 뒤 요청은 되돌릴 수 없다는 안내와 함께 취소됨을 보이고, 이후 sessionInfo 요청이 없습니다(Log 탭). 그 뒤 카드를 대고 등록 상태 확인을 누르면 enrolled가 나올 수 있습니다.
  5. 시트가 열린 채 블루투스를 끄거나 멀어집니다: 시트가 바로 닫히고 결과 줄이 기다리기를 중단했다고 알립니다.
  6. 흐름이 도는 동안 시트를 아래로 끌어 봅니다: 그대로 남습니다.
