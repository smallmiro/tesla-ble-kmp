6. CLI Tools

Usage, options, environment variables and keyring behavior of the five tools under cmd/ (tesla-keygen, tesla-control, tesla-auth-token, tesla-jws, tesla-http-proxy).

Installation

cd vehicle-command
go get ./...
go build ./...
go install ./...          # Installs the five tools into $GOBIN (default ~/go/bin). Same as make install (which installs only ./cmd/...)

The Docker image tesla/vehicle-command also contains all five tools, and its default entrypoint is tesla-http-proxy. Select other tools with --entrypoint. However, the host BLE adapter is not accessible from inside the container, so run BLE commands with a local build.

docker run --entrypoint tesla-keygen tesla/vehicle-command:latest -h
Platforms

macOS and Linux are supported. On Windows, everything except BLE builds, but newAdapter in pkg/connector/ble returns not supported on Windows, so tesla-control -ble does not work. On Linux, initializing the BLE adapter requires CAP_NET_ADMIN (troubleshooting).

A typical initial setup:

export TESLA_KEY_NAME=$(whoami)

export TESLA_VIN=5YJ30123456789ABC
export TESLA_CACHE_FILE=~/.tesla-cache.json

Keyring behavior

Private keys and OAuth tokens are kept in the OS credential store via 99designs/keyring.

Service name
com.tesla.auth (items appear under this name in the macOS Keychain)
Private key item
vehicleCommandKey.<TESLA_KEY_NAME>. The data is a 32-byte P-256 scalar (big-endian)
OAuth token item
oauthtoken.<TESLA_TOKEN_NAME>. The data is the token string as-is
Default backend
The OS default. On macOS the login keychain (KeychainTrustApplication: true), on Linux whichever of secret-service/kwallet/keyctl etc. is available, and for the file backend ~/.tesla_keys
Password
If the file backend or keychain unlock needs a password, a prompt is shown in the terminal. If neither stdout nor stderr is a terminal, you get a no terminal output available for password prompt error. For unattended runs, set TESLA_KEYRING_PASSWORD.
KeyCtl scope
The Linux keyctl backend uses the user scope.

tesla-control calls config.LoadCredentials() before the connection timeout starts so that the password prompt does not eat into the timeout. Follow the same order when building your own tools.

tesla-keygen

Creates, deletes, exports and migrates P-256 private keys for command authentication, and prints the public key as PEM.

usage: tesla-keygen [OPTION...] create|delete|export|migrate
SubcommandBehavior
createIf a key already exists (keyring name or file), it does not create one and only prints the existing key's public key. With -f, it overwrites with a new key. The key is stored in the keyring if -key-name is given, otherwise in -key-file (SEC1 PEM, 0600). If neither is given, private key location not provided.
deleteDeletes vehicleCommandKey.<name> from the keyring. File keys are not deleted.
exportPrints the private key to stdout as EC PRIVATE KEY PEM. Errors if the key implementation is not exportable.
migrateReads the PEM private key from -key-file and stores it in the keyring under the -key-name name. Both are required. The original file is left in place.
OptionDescription
-fOverwrite even if a key already exists (create)
-output fileSave the public key to a file instead of stdout
-key-name name, -key-file fileKey location. Defaults $TESLA_KEY_NAME, $TESLA_KEY_FILE
-keyring-type type, -keyring-file-dir directory, -keyring-debugKeyring settings
-token-name, -token-file, -session-cache, -disable-session-cache, -domainRegistered via cli.FlagOAuth | cli.FlagPrivateKey, so the flags exist but have no effect on keygen's behavior
 
# Create in the keyring and save the public key
export TESLA_KEY_NAME=$(whoami)
tesla-keygen create > public_key.pem

# Create a file-based key (no keyring)
tesla-keygen -key-file ~/.tesla/private.pem create > public_key.pem

# Migrate a key created with OpenSSL into the keyring
tesla-keygen -key-file private.pem -key-name $(whoami) migrate

# Export for backup (the output is secret; store it securely)
tesla-keygen export > private_backup.pem

# Force the file backend + unattended run
TESLA_KEYRING_TYPE=file TESLA_KEYRING_PASSWORD=... tesla-keygen create

The public key printed is PKIX PEM (-----BEGIN PUBLIC KEY-----). It can be used as-is both for Fleet API partner registration (/.well-known/appspecific/com.tesla.3p.public-key.pem) and for tesla-control add-key-request.

tesla-control

A general-purpose CLI that sends vehicle commands over BLE or the internet. It does not work on Windows.

Usage: tesla-control [OPTION...] COMMAND [ARG...]
       tesla-control help            # Full list of commands
       tesla-control help COMMAND    # Argument description for a command
       tesla-control                 # Running without COMMAND starts an interactive shell

Options

OptionDefaultDescription
-blefalseForces a BLE connection even when OAuth environment variables are set. Combined with a Fleet API-only command, yields command requires a FleetAPI OAuth token
-debugfalseDebug logging, including TX/RX hex dumps. Can also be enabled with TESLA_VERBOSE
-command-timeout duration5sTimeout for a single command. The SDK keeps retrying within it
-connect-timeout duration20sTimeout for scan + connect + handshake
-vin VIN$TESLA_VINTarget vehicle
-key-name name / -key-file file$TESLA_KEY_NAME / $TESLA_KEY_FILECommand-authentication private key
-token-name name / -token-file file$TESLA_TOKEN_NAME / $TESLA_TOKEN_FILEOAuth token (internet path)
-session-cache file$TESLA_CACHE_FILE → ~/.tesla-cache.jsonSession cache file. Updated automatically on exit
-disable-session-cachefalseDo not use the cache
-domain vcsec|infotainment(all)Domain(s) to handshake with. Can be repeated. Example: -domain vcsec avoids waking infotainment
-keyring-type, -keyring-file-dir, -keyring-debugOS default / ~/.tesla_keys / falseKeyring settings
-bt-adapter id (Linux only)hci0Bluetooth adapter to use (hci0–hci15)

Credential selection rules

In cmd/tesla-control/commands.go, each command is classified by requiresAuth (needs a private key) and requiresFleetAPI (needs an OAuth token). Before execution, configureFlags and checkReadiness apply the following rules.

Command typeRequiresTransportExamples
Vehicle command, authentication required (requiresAuth)VIN + private keyInternet if OAuth is available; BLE if -ble is given or there is no OAuthlock, climate-on, state charge
Vehicle command, no authentication requiredVINSame as abovelist-keys, session-info, body-controller-state, add-key-request, wake (internet)
Account command (requiresFleetAPI)OAuth tokenInternet only. Error if combined with -bleproduct-info, rename-key, get, post
-ble wakeVIN + private keyBLE. Handshakes with VCSEC only (because infotainment is asleep)tesla-control -ble wake

body-controller-state has domain: protocol.DomainVCSEC specified, so it handshakes with VCSEC only. Other commands can be restricted with the -domain flag.

Interactive shell

Running without COMMAND establishes the connection once and lets you send multiple commands in a row at the > prompt. Because the handshake is not repeated each time, this is useful when trying out several commands. Arguments are parsed with shlex, so quotes can be used; exit with exit. -command-timeout applies to each command.

$ tesla-control -ble
> body-controller-state
{ "vehicleLockState": "VEHICLELOCKSTATE_LOCKED", ... }
> unlock
> climate-set-temp 21C
> exit

Output and exit codes

  • Success: exit code 0. Most commands print nothing. state, body-controller-state, session-info, list-keys, product-info, get/post, charging-schedule-add (the generated ID) and others print their result to stdout.
  • Couldn't verify success: …: the command may have arrived but was not confirmed (protocol.MayHaveSucceeded). Exit code 1.
  • You must provide a private key with -key-name or -key-file to execute this command: protocol.ErrNoSession. Exit code 1.
  • Failed to execute command: …: any other error. Exit code 1.
  • On Linux, an adapter permission error prints setcap guidance.

Examples

# Key pairing (inside the car, with an NFC card ready)
tesla-control -ble add-key-request public_key.pem owner cloud_key

# Confirm enrollment
tesla-control -ble list-keys
tesla-control -ble session-info public_key.pem infotainment

# Basic commands
tesla-control -ble lock
tesla-control -ble -domain vcsec unlock           # Does not wake infotainment
tesla-control -ble climate-set-temp 72F
tesla-control -ble seat-heater front-left high
tesla-control -ble charging-set-limit 80
tesla-control -ble state climate
tesla-control -ble -debug ping                    # Inspect the TX/RX dump

# Internet path (when an OAuth token is in the keyring)
tesla-control wake
tesla-control lock
tesla-control product-info
tesla-control get "api/1/vehicles/$TESLA_VIN/vehicle_data"

# Charging schedules
tesla-control -ble charging-schedule-add weekdays 22:00-06:00 37.4 -122.1
tesla-control -ble charging-schedule-remove home

For all commands and their arguments, see 7. Command Reference.

tesla-auth-token

Reads an OAuth token from stdin or a file and stores it in the keyring as the oauthtoken.<name> item. It does not issue tokens. Follow the Fleet API documentation for the issuance procedure.

usage: tesla-auth-token [-token-name token_name] [file]
OptionDescription
-token-name nameKeyring item name. Default $TESLA_TOKEN_NAME. This is the only flag. The keyring type/path/password can be specified only through the TESLA_KEYRING_TYPE, TESLA_KEYRING_PATH and TESLA_KEYRING_PASSWORD environment variables.
file (positional argument)File containing the token. If omitted, reads stdin until EOF. Passing more than one is an error.
 
export TESLA_TOKEN_NAME=$(whoami)
echo -n "$ACCESS_TOKEN" | tesla-auth-token
tesla-auth-token token.txt
# After saving, tesla-control uses the internet path by default because OAuth is available. Use -ble for BLE.
The token string is stored as-is

The bytes read are stored without processing, so a trailing newline may be included. account.New cleans it up with strings.TrimSpace, so this causes no problems in practice. An expired token must be refreshed and stored again.

tesla-jws

Signs or verifies JWS (JSON Web Signature) objects, used for Fleet Telemetry configuration and similar, with the command-authentication private key. The signing algorithm is Tesla.SS256 (Schnorr/P-256 + SHA-256), which is not part of the JWS standard; it exists so that the existing ECDH/P-256 key can be safely reused as a signing key.

usage: tesla-jws [OPTION...] sign APP [JSON_FILE]
       tesla-jws verify [JWS_FILE]
Subcommand / optionDescription
sign APP [JSON_FILE]Signs the JSON object in JSON_FILE (stdin if omitted) as the claims. iss is overwritten with the base64 public key and aud with the context string. Prints the resulting JWS to stdout.
-fleetSignature for the whole fleet. aud = com.tesla.fleet.<APP>. Without it, -vin is required and aud = com.tesla.vehicle.<VIN>.<APP>, so only that vehicle accepts it.
verify [JWS_FILE]Only checks that the signature is valid for the public key in iss, and prints the claims as JSON. It does not check whether the issuer is trustworthy or whether aud is correct.
-vin, -key-name, -key-file, -keyring-*, -session-cache, -domainCommon flags from cli.FlagPrivateKey | cli.FlagVIN
 
# Sign a Fleet Telemetry config → POST to Fleet API /api/1/vehicles/fleet_telemetry_config_jws
tesla-jws -fleet sign TelemetryClient telemetry_config.json > signed-config.jws
tesla-jws verify signed-config.jws

# Signature for a specific vehicle only
tesla-jws -vin $TESLA_VIN sign TelemetryClient telemetry_config.json

The generated .jws file is not secret (it uses the same syntax as a JWT, but it is not a bearer token). The proxy's /api/1/vehicles/fleet_telemetry_config endpoint performs the same signing automatically on the server side (8. HTTP Proxy).
