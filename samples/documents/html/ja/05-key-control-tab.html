5. キー＆コントロールタブ

初めて使う人の日常の流れのために、モニターアプリへ加えた 5 つ目のタブです。キーを作り、車に登録し、ボタンで車を操作します。Control タブは、呼び出しごとにボタンが分かれた診断画面としてそのまま残します。このタブは呼び出しの順序を、4 つのステップとボタンのグリッドの裏に隠します。

Android と iOS でビルド済み、実機確認待ち

Android ビルド 0.3.0 (3)、iOS ビルド 0.5.0 (12)。ステップの規則とコマンド実行器は単体テストで確認し、画面と車はこのページの末尾のチェックリストで確認します。

要件

IDアプリの動作
SFR-018Control の次にキー＆コントロールタブ。4 つのステップを、それぞれ完了、未実施、1 行のヒント付きのブロックで示します。(1) キー: モニターのキーを作成または読み込みます。(2) 接続: 保存した VIN とモニターの接続を使います。(3) 登録: 登録を要求し（コンソールにキーカード）、進捗行を表示し、自動で確認します。(4) 操作: 使える VCSEC コマンドのボタンのグリッド。すべてのコマンドは、まず VCSEC セッションがあることを確認してから 1 回だけ送られ、Uncertain の結果は再送されず、vehicleStatus() の再問い合わせが続きます。状態カードは、直近の vehicleStatus() による施錠、トランク、フランク、スリープの状態を表示します。

ステップとボタンが有効になる条件

規則は 1 つの純粋関数（KeyControlSteps）なので、車なしでテストできます。入力は、キーの準備状況、スマートフォンのロックでキーが使えないか、VIN の保存有無、接続状況、登録状態、このタブの呼び出しが実行中かどうかです。

ステップ完了の条件ブロックされる条件（ヒント）ボタンが有効になる条件
1 キーキーが準備できているキーがロックされている（スマートフォンのロックを解除してもう一度押してください）実行中のものがない
2 接続接続済みVIN が保存されていない（Live タブで VIN を保存してください）VIN が保存済みで、未接続で、実行中のものがない
3 登録登録状態が enrolledキーが未準備、または未接続（先にステップ 1 と 2 を終えてください）キー準備済み、接続済み、登録状態が enrolled でも checking でもない、実行中のものがない
4 操作–登録状態が enrolled ではない（キーが登録されるとボタンが有効になります）キー準備済み、接続済み、登録状態が enrolled、実行中のものがない

登録状態

登録状態は unknown、checking、notEnrolled、enrolled のいずれかです。

  • タブは listKeys() で確認します。車のエントリのうち、公開鍵がローカルのキーと等しいものを探します（マニュアル 13 章）。確認中の状態は checking で、終わると enrolled または notEnrolled になり、結果が Uncertain または Failure のときは unknown です。確認は、キーが準備できた状態でタブが新しい接続を見るたびに 1 回、そして登録状態の確認を押したときに実行されます。
  • ペアリングの確認に成功すると enrolled になります。sessionInfo(publicKey, INFOTAINMENT) を 3 秒ごとに最大 2 分間呼びます。
  • コマンド前のセッションが KeyNotPaired で失敗すると notEnrolled になります。
  • 接続が切れるかキーが変わると unknown に戻ります。

コマンドの実行

KeyControlRunner.run(ensureSession, command, requery) は純粋関数で、フェイクでテストします。

  1. ensureSession は startSession(setOf(VCSEC)) です。すでに Ready のドメインは、要求なしで成功します。Failure のときはコマンドを送らず、結果行に理由を表示します。KeyNotPaired は登録状態を notEnrolled にし、KeyStoreError.Locked はスマートフォンのロック解除を求めます。
  2. command はちょうど 1 回呼ばれます。
  3. Success は「成功」、Failure はメッセージ付きで「失敗」、Uncertain はメッセージ付きで「不確実」と表示し、再送はしません。
  4. requery（vehicleStatus()）は、コマンドの後に必ず実行されます。Success の後は状態カードを更新し、Uncertain の後はマニュアルが求める再問い合わせになります。

Model X と Cybertruck のボタンは、折りたたまれた「他の車種」セクションにあります。インフォテインメントのコマンド（空調、充電、ホーン、ライト）は M5 を待つため表示しません。タブには、状態を更新ボタン付きの状態カード（施錠、トランク、フランク、スリープ、最後に読んだ時刻）と、新しい行が一番上に来て、時刻が付き、VIN を含まない結果リストもあります。

このタブのすべてのライブラリ呼び出しは、タブ自身の exclusive { } で 1 つずつ実行され、呼び出しの実行中はボタンが無効になります。Control タブには別のガードがあり、ライブラリが接続ごとに VCSEC コマンドを直列化するため、両方のタブでの押下が通信上で混ざることはありません。

実車チェックリスト

  1. 新規インストール: ステップ 1 は「未実施」と表示されます。押すとキーが作られ、ステップ 1 が完了します。
  2. VIN が保存済みで車が近くにある: 接続するとステップ 2 が完了し、登録の確認が実行されます（checking、新しいキーなら続いて notEnrolled）。
  3. ステップ 3: 押し、コンソールにキーカードを置き、車の画面で承認します。進捗行が表示され、enrolled になり、ステップ 4 のボタンが有効になります。
  4. 施錠、解錠、ウェイクアップ: 結果は「成功」で、状態カードがそれに続きます。
  5. トランクのトグルと閉める操作、確認ダイアログが出るフランク。
  6. キーが登録されたままで再インストール: 接続後の確認が、再度ペアリングしなくても enrolled になります。
  7. 車の画面でキーを削除してコマンドを押す: セッションが KeyNotPaired で失敗し、ステップ 3 が「未実施」に戻ります。
