Tesla vehicle-command BLE 開発マニュアル

Tesla 車両と Bluetooth Low Energy(BLE) またはインターネットで接続し、エンドツーエンド認証(end-to-end authenticated)されたコマンドを送信する vehicle-command SDK の開発者マニュアルです。

このドキュメントの基準バージョン

リポジトリ vehicle-command/ のタグ v0.4.1 以降のコミット a4b43c1(Fix wrapped protocol error classification)を基準に作成しました。Go モジュールパスは github.com/teslamotors/vehicle-command、必要な Go バージョンは 1.23 です。コードが更新されたら、このマニュアルの API シグネチャとコマンド一覧も再確認してください。

30 秒でわかる要約

  1. 鍵を作る。 tesla-keygen create > public_key.pem。NIST P-256 秘密鍵が OS のキーリングに保存され、公開鍵が出力されます。
  2. 車両に鍵を登録する。 車内で tesla-control -ble add-key-request public_key.pem owner cloud_key を実行し、NFC カードをセンターコンソールにかざして承認します。
  3. コマンドを送る。 tesla-control -ble lock。SDK がアドバタイズのスキャン → GATT 接続 → ドメインごとのハンドシェイク → AES-GCM で暗号化したコマンドの送信を処理します。
export TESLA_KEY_NAME=$(whoami)
export TESLA_VIN=5YJ30123456789ABC
export TESLA_CACHE_FILE=~/.tesla-cache.json

tesla-keygen create > public_key.pem
tesla-control -ble add-key-request public_key.pem owner cloud_key   # 車内で、NFC カードを用意
tesla-control -ble lock
tesla-control -ble -debug body-controller-state                     # ロック/ドア/スリープ状態 (Infotainment がスリープ中でも動作)

主要概念のまとめ

ドメイン(Domain)
VCSEC ロック、トランク、鍵管理、ウェイクアップを担当するセキュリティコントローラー。Infotainment がスリープしていても BLE で応答します。INFOTAINMENT 空調、充電、メディア、状態照会など残りのコマンドを担当します。ドメインごとに別々の鍵ペアとセッションがあります。
セッション(Session)
クライアントの公開鍵で SessionInfoRequest を送ると、ドメインが自身の公開鍵、epoch、カウンター、時計を含む SessionInfo を返します。ECDH で 128 ビットの AES-GCM 鍵 K を合意します。
認証方式
BLE では AES-GCM(暗号化 + 認証)、Fleet API では HMAC-SHA256(平文 + 認証)を使用します。どちらの方式も、VIN、epoch、有効期限、カウンターを含むメタデータを認証に結合します。
ロール(Role)
Owner、Driver、Fleet Manager、Vehicle Monitor、Charging Manager、Guest、Service。ロールによって許可されるコマンドが異なります。
セッションキャッシュ
セッション状態をディスクに保存すると、次回の実行時にハンドシェイクなしですぐにコマンドを送れます。キャッシュが古い場合は車両が新しいセッション情報をエラーと一緒に返すため、自動的に復旧します。
