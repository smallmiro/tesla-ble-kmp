2. 制約

サンプルへのすべての変更は、これらのルールに従います。ルールは AGENTS.md のリポジトリルールに上乗せするものであり、緩めることはありません。

サンプルが呼び出してよいもの

  • ライブラリマニュアル（第 11 章から第 19 章）が「使用可能」としている :sdk の公開 API だけです。どの章を開けばよいかは、第 11 章の「どのページを読むか」の表で分かります。
  • 次のものは使いません。:application や :adapter-* の型、@InternalTeslableApi が付いたもの、マニュアルで予定とされている API、ライブラリのログ文字列をデータとして読むこと。
  • 呼び出し順序、エラー処理（Success、Uncertain、Failure）、タイムアウト、プラットフォーム設定はマニュアルに従います。VCSEC コマンドの結果が Uncertain だった場合は、vehicleStatus() で状態を再取得します。コマンドを再送してはいけません。
  • Swift: Kotlin のデフォルト引数は Swift のオーバーロードにならないため、すべての引数を渡します。
  • サンプルのコードとマニュアルのコード例は一致させます。マニュアルの例が間違っていた場合は、同じプルリクエストで直します。
サンプルでの回避策は禁止

マニュアルに書かれていないものがサンプルに必要な場合、またはライブラリの動作がマニュアルと違う場合は、まずマニュアルを直します（Markdown と 3 言語の HTML）。または library-api-request スキルでライブラリへの要望を書き、計画に加えます。サンプルの要件はそれまで待ちます。

プラットフォーム設定

AndroidiOS
Bluetooth 権限BLUETOOTH_SCAN（neverForLocation）と BLUETOOTH_CONNECT。実行時に要求しますproject.yml の info: ブロックにある NSBluetoothAlwaysUsageDescription
ネットワークINTERNET 権限なし（PRD NFR-014）ネットワーク呼び出しなし
バックアップandroid:allowBackup="false"：ラッピングキーなしで復元されたソフトウェアキーは使えなくなるためキーは端末の外に出ない Keychain の項目
生成ファイル–TeslableSample.xcodeproj と Sources/Info.plist は xcodegen generate で作られます。コミットしないでください
署名–Local.xcconfig に DEVELOPMENT_TEAM を書きます。コミットしないでください

ライブラリマニュアルは、バックグラウンドでの利用をまだ扱っていません（第 17 章）。それが必要なサンプルは、使うプラットフォーム設定をこれらのページと第 17 章に、同じプルリクエストで書き残します。

ログ、秘密情報、車両データ

  • 秘密鍵、セッションキー、実際の VIN は、ログに出さない、フィクスチャに入れない、コミットしない。VIN は、スマートフォンの外に出る前にマスクします（先頭 3 文字と末尾 4 文字を残す）。
  • 画面に表示したりコピーしたりするログには、ライブラリの observe 行とサンプル自身の結果行だけを含めます。DebugLogger が出す BLE の生の TX:/RX: 16 進ダンプはシステムログにだけ残し、共有しません。
  • スマートフォンから取り出したログは、git が無視する samples/logs/ に置きます。分析レポートは docs/analysis/ に置きます。
  • アプリの画面は今のところ韓国語です。ライブラリのエラーメッセージは英語で、そのまま表示します。

ビルドとテスト

目的コマンド
Android サンプルをビルドする./gradlew :samples:android:assembleDebug
シミュレータ用の iOS フレームワーク./gradlew :sdk:linkDebugFrameworkIosSimulatorArm64
実機用の iOS フレームワーク./gradlew :sdk:linkDebugFrameworkIosArm64
iOS プロジェクトを生成するcd samples/ios && xcodegen generate
iOS のビルドと Swift 単体テスト（シミュレータ）xcodebuild -project TeslableSample.xcodeproj -scheme TeslableSample -destination 'platform=iOS Simulator,name=<device>' CODE_SIGNING_ALLOWED=NO test
ローカルゲート全体（両方のサンプルを含む）tools/ci/verify.sh
  • 車がなくてもテストできるロジック（パース、マスク、タイマー、状態変化）は、先に単体テストを書きます。Swift のテストは samples/ios/Tests/、Kotlin のテストは samples/android/src/test/ に置きます（このフォルダはまだないので、最初のテストと一緒に作ります）。
  • 画面と実車での動作は、書面のチェックリストを使って実機で確認します。シミュレータには Bluetooth がありません。

ドキュメントの同期

  • サンプルの動作を変更するときは、同じプルリクエストで 1. 要件、3. 現在のアプリ（またはアプリ専用のページ）、およびそれらの韓国語・英語・日本語の HTML 版を更新します。
  • サンプルのプルリクエストには、参照したライブラリマニュアルの章と節を記載します。
