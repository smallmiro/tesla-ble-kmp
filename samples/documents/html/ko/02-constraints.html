2. 제약

샘플 앱을 바꿀 때는 항상 이 규칙을 따릅니다. 이 규칙은 AGENTS.md의 저장소 규칙에 더해지는 것이며, 저장소 규칙을 완화하지 않습니다.

이 페이지의 내용
  1. 샘플 앱이 호출할 수 있는 것
  2. 플랫폼 설정
  3. 로그, 비밀, 차량 데이터

샘플 앱이 호출할 수 있는 것

  • 라이브러리 매뉴얼(11장부터 19장)이 사용 가능으로 적은 :sdk의 공개 API만 씁니다. 11장의 "어떤 페이지를 읽을지" 표가 어느 장을 열어야 하는지 알려 줍니다.
  • 쓰지 않는 것: :application이나 :adapter-*의 타입, @InternalTeslableApi가 붙은 모든 것, 매뉴얼이 예정이라고 적은 API, 라이브러리 로그 텍스트를 데이터처럼 읽는 것.
  • 호출 순서, 오류 처리(Success, Uncertain, Failure), 시간 제한, 플랫폼 설정은 매뉴얼을 따릅니다. VCSEC 명령이 Uncertain이면 vehicleStatus()로 상태를 다시 읽습니다. 명령을 다시 보내지 않습니다.
  • Swift: Kotlin 기본 인자는 Swift 오버로드로 바뀌지 않으므로 모든 인자를 넘깁니다.
  • 샘플 앱 코드와 매뉴얼의 코드 예제는 서로 맞아야 합니다. 매뉴얼 예제가 틀렸으면 같은 풀 리퀘스트에서 고칩니다.
샘플 앱에서 우회하지 않습니다

샘플 앱에 매뉴얼에 없는 내용이 필요하거나 라이브러리가 매뉴얼과 다르게 동작하면, 먼저 매뉴얼(Markdown과 3개 언어 HTML)을 고치거나 library-api-request 스킬로 라이브러리 요청을 작성해 계획에 추가합니다. 그때까지 해당 샘플 앱 요구사항은 대기합니다.

플랫폼 설정

AndroidiOS
Bluetooth 권한BLUETOOTH_SCAN(neverForLocation)과 BLUETOOTH_CONNECT, 런타임에 요청project.yml의 info: 블록에 있는 NSBluetoothAlwaysUsageDescription
백그라운드(모니터 앱)connectedDevice 유형의 포그라운드 서비스: FOREGROUND_SERVICE, FOREGROUND_SERVICE_CONNECTED_DEVICE, POST_NOTIFICATIONS(런타임에 요청). 서비스는 BLUETOOTH_CONNECT가 허용된 뒤에만 시작합니다UIBackgroundModes: [bluetooth-central]. UIFileSharingEnabled와 LSSupportsOpeningDocumentsInPlace는 로그 폴더 Documents/logs/를 위한 것
네트워크INTERNET 권한 없음(PRD NFR-014)네트워크 호출 없음
백업android:allowBackup="false": 감싸는 키 없이 복원된 소프트웨어 키는 쓸 수 없기 때문입니다키는 기기를 떠나지 않는 Keychain 항목입니다
생성 파일–TeslableSample.xcodeproj와 Sources/Info.plist는 xcodegen generate로 만듭니다. 커밋하지 않습니다
서명–Local.xcconfig에 DEVELOPMENT_TEAM이 들어 있습니다. 커밋하지 않습니다

라이브러리 매뉴얼은 아직 백그라운드 사용을 다루지 않습니다(17장). 백그라운드 사용이 필요한 샘플 앱은 같은 풀 리퀘스트에서 사용하는 플랫폼 설정을 이 페이지들과 17장에 적습니다. Android 모니터 앱이 이를 따랐습니다(위 표, 17장 "샘플 앱의 Android 백그라운드 사용"). 실기기 확인은 대기 중입니다. iOS 모니터 앱은 bluetooth-central을 유지하고 같은 재연결 루프를 실행합니다. iOS가 백그라운드에서 스캔하고 재연결하는지는 실차에서 계획 Task 2 스파이크를 실행하기 전까지 확인되지 않았습니다(17장 "샘플 앱의 iOS 백그라운드 사용").

로그, 비밀, 차량 데이터

  • 개인키, 세션키, 실제 VIN은 로그에 남기거나 픽스처에 넣거나 커밋하지 않습니다. 기기 밖으로 나가기 전에 VIN을 마스킹합니다(앞 3자와 뒤 4자만 남김).
  • 화면에 보이거나 복사되는 로그에는 라이브러리의 observe 줄과 샘플 앱 자체의 결과 줄만 들어갑니다. DebugLogger의 원시 BLE TX:/RX: 16진수는 시스템 로그에만 남고 공유하지 않습니다.
  • 휴대폰에서 가져온 로그는 git이 무시하는 samples/logs/에 둡니다. 분석 보고서는 docs/analysis/에 둡니다.
  • 앱 화면은 당분간 한국어입니다. 라이브러리 오류 메시지는 영어이며 그대로 표시합니다.

목적명령
Android 샘플 앱 빌드./gradlew :samples:android:assembleDebug
시뮬레이터용 iOS 프레임워크./gradlew :sdk:linkDebugFrameworkIosSimulatorArm64
실기기용 iOS 프레임워크./gradlew :sdk:linkDebugFrameworkIosArm64
iOS 프로젝트 생성cd samples/ios && xcodegen generate
iOS 빌드와 Swift 단위 테스트(시뮬레이터)xcodebuild -project TeslableSample.xcodeproj -scheme TeslableSample -destination 'platform=iOS Simulator,name=<device>' CODE_SIGNING_ALLOWED=NO test
전체 로컬 게이트(두 샘플 앱 포함)tools/ci/verify.sh
  • 차 없이 테스트할 수 있는 로직(파싱, 마스킹, 타이머, 상태 변화)은 단위 테스트를 먼저 씁니다. Swift 테스트는 samples/ios/Tests/에, Kotlin 테스트는 samples/android/src/test/에 둡니다(./gradlew :samples:android:testDebugUnitTest).
  • 화면과 실차 동작은 작성된 체크리스트에 따라 실제 휴대폰에서 확인합니다. 시뮬레이터에는 Bluetooth가 없습니다.

문서를 함께 맞추기

  • 샘플 앱의 동작이 바뀌면 같은 풀 리퀘스트에서 1. 요구사항, 3. 현재 앱(또는 해당 앱의 별도 페이지)과 이들의 한국어, 영어, 일본어 HTML 버전을 갱신합니다.
  • 샘플 앱 풀 리퀘스트에는 참고한 라이브러리 매뉴얼의 장과 절을 적습니다.
