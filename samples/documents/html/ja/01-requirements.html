1. 要件

サンプルの要件には独自の ID SFR-xxx を使い、ライブラリの FR-xxx や NFR-xxx と混ざらないようにしています。これらの要件は 2026-10-24 にライブラリの PRD からここへ移しました。PRD が扱うのは今後ライブラリだけです。

要件一覧

ID要件プラットフォーム状態出典
SFR-001ライブラリを一通り試せる Android サンプル（Compose）。VIN 入力、スキャン、接続、進捗イベント付きペアリング、キー一覧と削除、ロック、アンロック、トランク、フランク、vehicleStatus()、ウェイクアップ、不確定な結果の表示と再取得、デバッグログ画面を含みます。エアコンのオン/オフ、充電の開始/停止、少なくとも 1 つの getState は、ライブラリが提供された時点（M5）で追加します。AndroidVCSEC 完了 M4。デバッグログ画面は未完了です（DebugLogger は Logcat にだけ出力し、画面には表示されません）。インフォテインメント関連の項目は M5 待ちです。PRD FR-110
SFR-002SKIE が生成する Swift API を使い、SFR-001 と同じフローを備えた iOS サンプル（SwiftUI）。加えて、observe のログ行を収集する観察モード、マークボタン、全件コピーを備えます。iOSVCSEC 完了 M4。観察モードを含みます。インフォテインメント関連の項目は M5 待ちです。PRD FR-111
SFR-010 to SFR-017モニターアプリ。タブ、VIN の保存と自動接続、バックグラウンドでの再接続、画面の点灯維持、Vehicle.events によるライブ状態、定期的な問い合わせ、マーク付きの JSON Lines ログ、ログを取り出すスクリプト。4. モニターアプリを参照してください。Android, iOS予定 すぐに作り始められます (issue #91)。必要なライブラリ API である Vehicle.events と iOS のキーアクセシビリティ (FR-037) が使えます。設計 2026-10-24

要件を追加するときのルール

  • 新しい要件には、次に空いている SFR- 番号を付けます。docs/superpowers/specs/2026-10-24-vehicle-events-monitor-design.md で計画している監視アプリは SFR-010 から始まります。
  • ライブラリマニュアルに「使用可能」と書かれていないライブラリ機能が必要な要件は、状態を「ライブラリ待ち」にしてここに書き、library-api-request スキルで要望を出します（2. 制約を参照）。
  • 状態を表す言葉は、予定、進行中、完了、ライブラリ待ち、M5 待ちです。
