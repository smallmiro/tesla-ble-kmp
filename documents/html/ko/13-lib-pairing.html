13. 키와 페어링

휴대폰은 자신만의 키 쌍이 필요하고, 차량은 그 공개키가 목록에 있어야 해당 키의 명령을 받아 줍니다. 라이브러리는 키를 만들어 저장하고, 차량의 키 목록을 읽고, 차량에 키를 등록합니다. 사용자가 NFC 키카드를 태그하고 화면에서 승인합니다.

키 보관소

TeslaBle.keys는 VehicleKeyStore입니다. 키는 별칭으로 찾으며, 대부분의 앱은 기본 별칭 하나만 있으면 됩니다.

호출반환동작
getOrCreate(alias, policy)VehicleResult<VehicleKey>저장된 키를 반환하거나, 별칭으로 NIST P-256 키 쌍을 생성
get(alias)VehicleResult<VehicleKey?>키가 없으면 Success(null)
delete(alias)VehicleResult<Unit>키가 없어도 성공
  • 기본 별칭은 "teslable-default"입니다(VehicleKeyStore.DEFAULT_ALIAS, Swift에서는 VehicleKeyStoreCompanion.shared.DEFAULT_ALIAS).
  • 별칭에는 영문자, 숫자, ., _, -를 최대 64자까지 쓸 수 있으며, .이나 ..은 쓸 수 없습니다.
  • VehicleKey는 핸들입니다. alias, protection, publicKey(65바이트, 0x04 ‖ X ‖ Y)를 제공합니다. 개인키는 플랫폼 키 보관소를 벗어나지 않으며, 내보내기 API는 없습니다.

키가 저장되는 위치

policy 인자는 소프트웨어 키를 허용할지 정합니다. 키가 실제로 어디에 저장되었는지는 VehicleKey.protection으로 알 수 있습니다.

KeyPolicy동작
PREFER_HARDWARE(기본값)하드웨어 우선, 하드웨어가 실패하면 소프트웨어
REQUIRE_HARDWARE하드웨어만, 아니면 KeyStoreError.HardwareUnavailable
SOFTWARE_ONLY소프트웨어만, 테스트와 에뮬레이터용
KeyProtection하드웨어위치
SECURE_ENCLAVE예iOS Secure Enclave
STRONGBOX예Android StrongBox
TEE예Android Trusted Execution Environment
SOFTWARE아니요Android Keystore로 래핑되거나 iOS 키체인에 보관, JVM에서는 메모리

실제 기기에서 SOFTWARE가 나오면 사용자에게 알리는 것을 고려하세요. 하드웨어 키보다 보안이 약합니다.

내 키가 등록되어 있나요?

vehicle.listKeys()는 키 없이, 차량을 깨우지 않고 동작합니다. 차량의 목록과 내 공개키를 비교하세요.

val mine = key.publicKey.toByteArray()
val enrolled = when (val r = vehicle.listKeys()) {
    is VehicleResult.Success -> r.value.firstOrNull { it.publicKey?.toByteArray()?.contentEquals(mine) == true }
    else -> null                                   // Uncertain 또는 Failure: 알 수 없음, 나중에 다시 조회
}
// enrolled?.role은 KeyRole, enrolled?.slot은 화이트리스트 슬롯

등록되지 않은 키로도 연결과 읽기는 할 수 있습니다. 그 키로 세션을 시작하면 KeyNotPaired로 실패합니다.

키 삭제와 교체

  • keys.delete(alias)는 휴대폰에서만 키를 지웁니다. 차량에서 제거하기 전까지 차량은 그 공개키를 계속 목록에 둡니다.
  • 저장된 세션은 키 하나에 속합니다. 키가 바뀌면 다음 연결에서 이전 세션을 버리고 새 핸드셰이크를 시작합니다.
  • 손상된 저장 키(KeyStoreError.PlatformFailure, stored key is corrupted)는 자동으로 교체되지 않습니다. 사용자에게 알리고, delete 후 getOrCreate를 호출한 다음, 새 키를 차량에 다시 등록하세요. 플랫폼 노트를 참고하세요.

키 등록

Go 원본은 키 등록 요청을 보내기만 하고 응답을 읽지 않습니다. 응답을 PairingEvent 값으로 읽는 것은 이 라이브러리에서 새로 추가한 동작이며, 아직 실차에서 확인하지 않았습니다.

호출반환동작
addKeyRequest(publicKey, role, formFactor, timeout)Flow<PairingEvent>차량에 키 추가를 요청합니다(FR-022, FR-023). 콜드 플로우로, 수집할 때마다 요청을 한 번 보냅니다. 서명하지 않으므로 세션이 필요 없습니다. timeout = null이면 pairingTimeout(60초)을 씁니다. 요청은 한 번에 하나씩 실행됩니다
sessionInfo(publicKey, domain, timeout)VehicleResult<SessionInfoSummary>도메인별로 등록 여부를 확인합니다(FR-024). 연결에 키가 필요 없습니다. Failure(KeyNotPaired)는 차량 목록에 키가 없다는 뜻입니다. 연결 자신의 키로 물으면 그 도메인의 세션도 만들어져 sessions에 Ready(fromCache = false)로 표시됩니다
addKey(publicKey, role, formFactor, timeout)VehicleResult<Unit>충분한 권한이 있는 등록된 키가 NFC 카드 없이 다른 키를 추가합니다(FR-027). 인증된 VCSEC 명령이며 VCSEC 세션이 필요합니다
removeKey(publicKey, timeout)VehicleResult<Unit>차량에서 키를 제거합니다(FR-026). 인증된 VCSEC 명령이며 VCSEC 세션이 필요합니다
  • role의 기본값은 KeyRole.OWNER, formFactor의 기본값은 platformKeyFormFactor()입니다. Android는 ANDROID_DEVICE, iOS는 IOS_DEVICE, JVM(테스트)은 CLOUD_KEY입니다.
  • Swift에서는 Kotlin의 기본 인자를 쓸 수 없습니다. 모든 인자(role:, formFactor:, timeout:)를 직접 넘기세요. 예: formFactor: .iosDevice.
  • addKey와 removeKey는 InsufficientPrivileges(연결의 키가 키 관리 권한이 없는 경우, 예: Driver 키), KeychainRejected(code)(예: WHITELIST_FULL), NoSession, InvalidArgument(role = UNKNOWN)로 실패할 수 있습니다. Uncertain은 차량의 키 목록이 바뀌었을 수 있다는 뜻입니다. listKeys()로 확인하고 다시 보내지 마세요.

페어링 이벤트

PairingEvent의미마지막 이벤트
Sent요청을 전송했습니다. 사용자가 센터 콘솔에 NFC 키카드를 태그하고 화면에서 승인해야 합니다아니요
WaitingForTap차량이 대기 중(WAIT)이라고 알립니다아니요
Accepted차량이 키를 받아들였습니다. 인포테인먼트가 키를 알게 되기까지 수십 초가 더 걸릴 수 있습니다예
Rejected(error)차량이 거부했습니다: KeychainRejected, UnknownKeychainCode, VcsecRejected, UnknownVcsecError예
Unknown(raw)해석하지 못한 프레임입니다. raw는 바이트의 사본입니다아니요
Failed(error)전송하지 못했거나(NotConnected, 쓰기 실패, InvalidArgument) 기다리는 동안 링크가 끊겼습니다예
TimedOuttimeout 안에 마지막 응답이 오지 않았습니다. 키가 등록되었을 수도 있으니 sessionInfo로 확인하세요예

마지막 이벤트 뒤에는 플로우가 끝납니다(isTerminal이 true). 상태도 오류도 없는 프레임, 중간 OK 상태, 요청을 보내기 전에 받은 프레임은 무시합니다.

실차에서 확인하지 않았습니다

키 등록 요청의 응답 형식은 아직 실차에서 관찰하지 못했습니다(ADR-0009). Unknown(raw)를 받으면 raw를 16진수로(VIN 제외) 차량이 한 동작과 함께 알려 주세요.

페어링 절차

  1. 키를 만들고(keys.getOrCreate()) 그 키로 연결합니다.
  2. vehicle.addKeyRequest(key.publicKey)를 수집합니다. 사용자에게 센터 콘솔에 키카드를 태그하고 화면에서 승인하도록 안내합니다.
  3. Accepted(또는 TimedOut) 뒤에 sessionInfo(key.publicKey, VehicleDomain.INFOTAINMENT)를 3초마다 최대 2분 동안 호출합니다. KeyNotPaired는 "아직"이라는 뜻이니 계속 호출하세요. Success면 키가 등록되고 동기화된 것입니다.
  4. startSession(setOf(VehicleDomain.VCSEC))를 실행한 다음 명령을 보냅니다(15. 명령).

Kotlin

val key = (ble.keys.getOrCreate() as VehicleResult.Success).value
val vehicle = (ble.connect(vin, key) as VehicleResult.Success).value

vehicle.addKeyRequest(key.publicKey).collect { event ->
    when (event) {
        PairingEvent.Sent -> show("Tap the key card on the center console, then confirm on the screen")
        PairingEvent.WaitingForTap -> show("Waiting for the card")
        PairingEvent.Accepted -> show("Accepted, waiting for the car to sync")
        is PairingEvent.Rejected -> show("Rejected: ${event.error.message}")
        is PairingEvent.Unknown -> report(event.raw.joinToString("") { it.toUByte().toString(16).padStart(2, '0') })      // see the warning below
        is PairingEvent.Failed -> show("Failed: ${event.error.message}")
        PairingEvent.TimedOut -> show("No answer, checking enrollment")
    }
}

suspend fun waitUntilEnrolled(vehicle: Vehicle, key: VehicleKey): Boolean {
    val deadline = TimeSource.Monotonic.markNow() + 2.minutes
    while (deadline.hasNotPassedNow()) {
        when (val r = vehicle.sessionInfo(key.publicKey, VehicleDomain.INFOTAINMENT)) {
            is VehicleResult.Success -> return true
            is VehicleResult.Failure -> if (r.error != VehicleError.KeyNotPaired) return false
            is VehicleResult.Uncertain -> Unit                  // reply lost: ask again
        }
        delay(3.seconds)
    }
    return false
}

Swift

for await event in vehicle.addKeyRequest(publicKey: key.publicKey, role: .owner, formFactor: .iosDevice, timeout: nil) {
    switch onEnum(of: event) {
    case .sent: print("Tap the key card on the center console, then confirm on the screen")
    case .waitingForTap: print("Waiting for the card")
    case .accepted: print("Accepted, waiting for the car to sync")
    case .rejected(let r): print("Rejected: \(r.error.message)")
    case .unknown(let u): print("Unknown frame, \(u.raw.size) bytes")
    case .failed(let f): print("Failed: \(f.error.message)")
    case .timedOut: print("No answer, checking enrollment")
    }
}

// then, every 3 s for up to 2 minutes:
let r = try await vehicle.sessionInfo(publicKey: key.publicKey, domain: .infotainment, timeout: nil)
switch onEnum(of: r) {
case .success: print("enrolled")
case .failure(let f): print("not yet or failed: \(f.error.message)")   // KeyNotPaired: keep polling
case .uncertain: print("reply lost, ask again")
}

역할(KeyRole)은 OWNER, DRIVER, FLEET_MANAGER, VEHICLE_MONITOR, CHARGING_MANAGER, GUEST, SERVICE입니다. 역할별로 보낼 수 있는 명령은 7. 명령 레퍼런스에 정리되어 있습니다. 확장된 프로토콜 정의에만 있는 역할과 키 형태(예: ROLE_RIDER, KEY_FORM_FACTOR_APPLE_WATCH)는 UNKNOWN으로 읽힙니다.
