1. 요구사항

샘플 앱 요구사항은 라이브러리의 FR-xxx, NFR-xxx와 섞이지 않도록 별도의 ID SFR-xxx를 씁니다. 2026-10-24에 라이브러리 PRD에서 이곳으로 옮겼습니다. 이제 PRD는 라이브러리만 다룹니다.

SFR-022Live 탭을 자동차 클러스터로 구성합니다: 기어 줄 P/R/N/D, 큰 속도(km/h), 잠금 상태, 위에서 본 차량 사진. 닫히지 않은 문·프렁크·트렁크·충전 포트에는 빨간 아이콘을 붙이고(문이 돌아가는 애니메이션도, 부위 그림 겹치기도 없음) 열린 곳의 이름도 글자로 보여 줍니다. 상태를 모르는 부위는 아이콘이 없습니다. 속도는 언제나 —입니다. 아직 이 값을 알려 주는 문서화된 API가 없습니다(getState, M5, 단위 #118). 받지 못한 값은 —로 둡니다. 아이콘은 왼쪽이 운전석입니다(좌핸들 기준). 사진의 검은 바탕은 어두운 둥근 판 위에 놓입니다. 연결되지 않았거나 현재 연결이 아직 차량의 상태를 받지 못했다면 화면을 어둡게 하고 연결 상태와 마지막 수신 시각을 보여 줍니다. 현재 연결의 첫 방송 또는 첫 성공한 vehicleStatus()를 받으면 받은 것으로 칩니다(조회는 약 0.1초, 방송은 4.7~43.1초). 이전 연결의 결과, Failure, Uncertain은 세지 않습니다. VIN을 지우면 값도 지웁니다. VIN과 연결은 설정 시트로 옮기며, VIN이 없으면 시트가 저절로 열립니다. SFR-014의 항목별 시각, 트렁크 안내, 최근 이벤트는 상세 시트로 옮깁니다.iOS구현 완료, 실기기 확인 대기 iOS 0.5.0 (26), 단위 테스트 통과. Android: SFR-014 목록 유지.요청 2026-11-01
SFR-023Query 탭의 상태 진단: Drive, Media, MediaDetail 버튼이 누를 때마다 getState()를 한 번 호출해 차량이 돌려주는 값을 사람이 볼 수 있게 합니다. 버튼은 연결, 키, 등록된 키, 그리고 vehicleStatus()의 최근 sleepStatus == AWAKE가 모두 있을 때만 켜집니다(UNKNOWN이면 꺼집니다). 한 번 누를 때마다 먼저 vehicleStatus()를 다시 읽고, Infotainment 세션이 없으면 시작한 뒤, getState를 한 번 보냅니다. Uncertain과 Failure는 그대로 보여 주고 자동으로 다시 보내지 않으며, wakeUp()은 절대 호출하지 않습니다. 별도의 잠든 차에 보내기(실험) 버튼은 확인 대화상자(차가 깨어날 수 있음)를 거친 뒤 수면 확인만 건너뜁니다. 값(원시 숫자로 보이고 단위 미확인으로 표시한 속도, 기어, 출력, 주행거리, 재생 상태, 볼륨, 곡 제목)은 화면에만 나오고, 로그에는 범주, 결과, 소요 시간, 오류 종류만 남습니다. 연결이 바뀐 뒤에 도착한 결과는 버리고, 키를 교체하는 중이거나 다른 탭이 키 동작을 하는 동안에는 조회를 시작하지 않습니다. 자세한 내용은 4. 모니터 앱.iOS구현 완료, 실기기 확인 대기 iOS 0.5.0 (26), 단위 테스트 통과. Android: 예정, 같은 스펙.계획 2026-11-01 (#118), PRD FR-033
SFR-024넓은 화면과 접는 화면(iPhone Duo): 가로 크기 클래스가 regular 이고 쓸 수 있는 너비가 540pt 이상이면(Duo 안쪽 화면) 공식 Tesla 앱의 큰 화면 배치를 따릅니다. 왼쪽: 제목(키 별명 또는 "Tesla")과 상태 한 줄, 채워진 카드 둘(Live 상세, 키·제어), 카드 없는 상태 줄(잠금, 문·트렁크, 수면, 재실, 주행), 앱 빌드 바닥 줄. 고른 페이지는 그 자리에 열림. 오른쪽: 공식 Tesla 앱처럼 말풍선이 붙은 비스듬한 차량 사진(지붕 위 잠금 아이콘, 왼쪽 위 "열기 전면", 오른쪽 위 "열기/닫기 트렁크"가 각각 가는 선으로 차에 이어짐, 차 뒤 옆의 충전구 번개는 열리면 빨강이고 누를 수 없음, 열린 문마다 짧은 선이 붙은 빨간 문 아이콘), 기어 줄과 마지막 수동 Drive 조회의 속도(단위 미확인, 나이 표시), 아래 동작 줄(깨우기, 트렁크 닫기). 모든 버튼은 키·제어 탭에 있는 버튼을 같은 모델로 움직이므로 켜지는 조건, 안내 문구, 한 번만 보내기, vehicleStatus() 재조회가 같습니다. 탭 다섯 개는 기본 탭 막대로 두고, 시스템이 도크 아래 세로 막대로 그립니다. 좁은 너비(Duo 바깥 화면, 일반 iPhone)는 탭 다섯 개를 그대로 씁니다. 앱은 폰의 라이트/다크 설정과 상관없이 항상 다크 모드입니다(모든 탭, 두 영역, 시트, 알림). 고른 항목, 열린 Live 시트, Log 메모는 접거나 펼쳐도 이어집니다. 내용은 안전 영역(오른쪽 도크) 안에 둡니다. 크기 클래스와 쓸 수 있는 너비만 보고, 기기 모델, UIScreen, 방향, 힌지 API는 쓰지 않습니다. 자세한 내용은 4. 모니터 앱.iOS구현 완료, 실기기 확인 대기 iOS 0.5.0 (26), 단위 테스트 통과. Android: 지금은 해당 없음(접는 기기 대상 없음).iPhone Duo (Xcode 27.2), Tesla 앱 4.62 배치
SFR-025키·제어 탭의 Infotainment 제어(4단계, VCSEC 그리드 아래): 공조 켜기 / 끄기, 충전 시작 / 중지, 카테고리별 읽기 버튼(getState(CLIMATE), getState(CHARGE), Uncertain 뒤의 재조회에도 씀). 4단계 규칙으로 켜집니다. 한 번 누르면 vehicleStatus()(AWAKE일 때만 계속), 그다음 startSession(setOf(INFOTAINMENT)), 그다음 호출 한 번입니다. wakeUp()은 절대 부르지 않고, 아무것도 다시 보내지 않으며, getState가 저절로 실행되지 않습니다. Uncertain은 있는 그대로 보여 주고, 읽기나 이후의 성공으로 확정될 때까지 그 카테고리를 미확인으로 표시합니다. 연결이 바뀐 뒤에 도착한 결과는 버립니다. 로그에는 명령, 결과, 소요 시간, 오류 유형만 남기고 값이나 차 자체의 문구는 남기지 않습니다(FR-112). 자세한 내용은 5. 키·제어 탭.Android, iOSAndroid 구현 완료, 실기기 확인 대기 0.4.0 (4), 단위 테스트 통과(#118). iOS: 구현 완료, 실기기 확인 대기 0.5.0 (26), 단위 테스트 통과(#118).계획 M5 PR C (docs/superpowers/plans/2026-11-08-m5-infotainment.md), PRD FR-060, FR-070, FR-033

요구사항을 추가하는 규칙

  • 새 요구사항은 비어 있는 다음 SFR- 번호를 씁니다. docs/superpowers/specs/2026-10-24-vehicle-events-monitor-design.md에서 계획한 모니터링 앱은 SFR-010부터 시작합니다.
  • 요구사항에 라이브러리 매뉴얼이 사용 가능으로 적지 않은 라이브러리 기능이 필요하면, 여기에 상태를 "라이브러리 대기"로 적고 library-api-request 스킬로 요청을 올립니다(2. 제약 참고).
  • 상태 용어: 예정, 진행 중, 완료, 라이브러리 대기, M5 대기.
