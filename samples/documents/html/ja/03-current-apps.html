3. 現在のアプリ

Android

モニターアプリです（4. モニターアプリ、SFR-010～SFR-018）。5 つのタブとフォアグラウンドサービスでできています。ビルド 0.3.0 (3)、単体テストは通過し、実機確認は待機中です。

Gradle モジュールは :samples:android、パッケージ名とアプリケーション ID は dev.mirolab.teslable.sample、minSdk は 31 です。MainActivity.kt がタブと権限の要求を担当し、画面が表示されている間は画面を点灯させたままにします。MonitorService.kt と MonitorEngine.kt がサービス、接続、イベント、問い合わせ、ログを動かします。SampleState.kt は Control タブの状態を保持し、すべての操作を exclusive { } 経由で実行するため、ライブラリの呼び出しは同時に 1 つしか動きません。KeyControl.kt（純粋なステップ規則とコマンド実行部）、KeyControlState.kt（タブの状態）、Enrollment.kt（ペアリングと確認、両タブで共有）がキー＆コントロールタブを構成します。タブの画面は ui/ にあります。単体テスト（KeyControlTest を含む）は src/test/ にあり、./gradlew :samples:android:testDebugUnitTest で実行します。

タブ内容
Live接続バナー、VIN の保存と消去、接続と切断、項目ごとの最新のブロードキャスト状態と最後に変わった時刻、最近のイベント
QueryvehicleStatus()、keySummary()、listKeys() を 30 秒ごと（変更可）に問い合わせ、結果と時刻、セッション、「今すぐ問い合わせ」
Log行数、認識できないイベントの数、最後の行、ファイルのパス、メモと Mark、新しいファイル
Control以前の 1 画面（下）。モニターの接続とキーを使います
キー＆コントロール4 つのステップ（キー、接続、登録、操作）、VCSEC コマンドボタンのグリッド、状態カード、結果（5. キー＆コントロールタブ）

iOS

モニターアプリです（4. モニターアプリ、SFR-010～SFR-018）。5 つのタブと、アプリの存続期間中ずっと存在する 1 つのモニターオブジェクトでできています。ビルド 0.5.0 (12)、単体テストは通過し、実機確認は待機中です。

XcodeGen プロジェクト（project.yml）で、スキームは TeslableSample（シミュレータ用）と TeslableSampleDevice（実機用）です。project.yml は Info.plist に UIBackgroundModes: [bluetooth-central]、UIFileSharingEnabled、LSSupportsOpeningDocumentsInPlace を設定します。MonitorModel.swift と MonitorEngine.swift が接続、イベント、問い合わせ、ログを動かします。ConnectionLoop.swift、LogLine.swift、LogWriter.swift、VinMask.swift、LiveState.swift、VehicleMapping.swift はその裏にある部品です（iOS の実装を参照）。SampleModel.swift は Control タブの状態と BleClient を保持し、すべての操作を exclusive { } 経由で実行するため、ライブラリの呼び出しは同時に 1 つしか動きません。KeyControl.swift（純粋なステップ規則とコマンド実行部）と KeyControlModel.swift（タブの状態）がキー＆コントロールタブを構成します。タブは ContentView.swift と Views/ にあります。Swift の単体テストは Tests/ にあります（VinMaskTests、LogWriterTests、ConnectionLoopTests、LiveStateTests、TimeoutsTests、KeyControlTests）。
