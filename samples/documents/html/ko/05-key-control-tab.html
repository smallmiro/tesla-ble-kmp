5. 키·제어 탭

처음 쓰는 사용자의 일상 경로를 위해 모니터 앱에 더한 다섯 번째 탭입니다. 키를 만들고, 차에 등록하고, 버튼으로 차를 제어합니다. Control 탭은 호출마다 버튼이 따로 있는 진단 화면으로 그대로 두고, 이 탭은 호출 순서를 네 단계와 버튼 그리드 뒤에 감춥니다.

Android와 iOS 구현 완료, 실기기 확인 대기

Android 빌드 0.3.0 (3), iOS 빌드 0.5.0 (12). 단계 규칙과 명령 실행기는 단위 테스트로 확인했고, 화면과 차는 이 페이지 끝의 체크리스트로 확인합니다.

요구사항

ID앱이 하는 일
SFR-018Control 다음에 키·제어 탭. 네 단계를 각각 완료, 해야 함, 한 줄 힌트가 있는 막힘으로 표시합니다. (1) 키: 모니터 키를 만들거나 불러옵니다. (2) 연결: 저장된 VIN과 모니터의 연결을 씁니다. (3) 등록: 등록을 요청하고(콘솔에 키 카드), 진행 줄을 보여 주며, 자동으로 확인합니다. (4) 제어: 사용 가능한 VCSEC 명령의 버튼 그리드. 모든 명령은 먼저 VCSEC 세션이 있는지 확인한 뒤 한 번만 보내며, Uncertain 결과는 다시 보내지 않고 vehicleStatus() 재조회가 이어집니다. 상태 카드는 마지막 vehicleStatus()의 잠금, 트렁크, 프렁크, 절전 상태를 보여 줍니다.

단계와 버튼이 켜지는 조건

규칙은 순수 함수 하나(KeyControlSteps)이므로 차 없이 테스트합니다. 입력은 키 준비 여부, 휴대폰 잠금으로 키가 잠겼는지, VIN 저장 여부, 키를 가진 연결 여부(Connected이고 vehicle.hasKey. 연결할 때 키 저장소 오류가 나면 키 없이 연결되며, 힌트가 연결을 끊고 다시 연결하라고 안내합니다), 등록 상태, 이 탭의 호출이 실행 중인지입니다.

단계완료 조건막히는 조건(힌트)버튼이 켜지는 조건
1 키키가 준비됨키가 잠겨 있음(휴대폰 잠금을 풀고 다시 누르세요)실행 중인 것이 없음
2 연결연결됨저장된 VIN 없음(Live 탭에서 VIN을 저장하세요)VIN이 저장되어 있고, 연결되지 않았고, 실행 중인 것이 없음
3 등록등록 상태가 enrolled키가 준비되지 않았거나 연결되지 않음(1, 2단계를 먼저 끝내세요)키 준비됨, 연결됨, 등록 상태가 enrolled 또는 checking이 아님, 실행 중인 것이 없음
4 제어–등록 상태가 enrolled가 아님(키가 등록되면 버튼이 켜집니다)키 준비됨, 연결됨, 등록 상태가 enrolled, 실행 중인 것이 없음

버튼 두 개가 더 있습니다. 등록 상태 확인은 키가 준비되고, 연결되어 있고, 등록 상태가 checking이 아니며, 실행 중인 호출이 없을 때 켜집니다(enrolled여도 켜져 있어 차에서 지운 키를 다시 확인할 수 있습니다). 상태 새로고침은 연결되어 있고 실행 중인 호출이 없을 때 켜집니다(vehicleStatus()는 키가 필요 없습니다).

등록 상태

등록 상태는 unknown, checking, notEnrolled, enrolled 중 하나입니다.

  • 탭은 listKeys()로 확인합니다. 차의 항목 중 공개 키가 로컬 키와 같은 것을 찾습니다(매뉴얼 13장). 확인하는 동안은 checking이고, 끝나면 enrolled 또는 notEnrolled이며, 결과가 Uncertain 또는 Failure이면 unknown입니다. 확인은 키가 준비된 상태에서 탭이 새 연결을 볼 때마다 한 번(unknown으로 끝나면 약 5초 뒤 한 번 다시 시도합니다. 모니터의 첫 조회와 경합에서 질 수 있기 때문입니다), 탭이 보일 때마다, 그리고 등록 상태 확인을 누를 때 실행됩니다. 자동 확인은 "먼저 연결하세요" 줄을 남기지 않습니다.
  • 페어링 확인이 성공하면 enrolled가 됩니다. sessionInfo(publicKey, INFOTAINMENT)를 3초마다 최대 2분 동안 호출합니다. 매뉴얼의 waitUntilEnrolled처럼 KeyNotPaired와 Uncertain에서는 계속 폴링하고, 그 밖의 실패(예: 링크가 끊긴 뒤의 NotConnected)에서는 즉시 멈춥니다.
  • Control 탭이 등록을 확인하거나 이 기기의 키를 제거하면 다시 확인합니다.
  • 명령 전의 세션, 또는 명령 자체(세션이 이미 Ready였으므로 그 명령은 아무것도 보내지 않았습니다)가 KeyNotPaired로 실패하면 notEnrolled가 됩니다.
  • 연결이 끊기거나 키가 바뀌면 unknown으로 돌아갑니다.

명령 실행

KeyControlRunner.run(ensureSession, command, requery)는 순수 함수이며 페이크로 테스트합니다.

  1. ensureSession은 startSession(setOf(VCSEC))입니다. 이미 Ready인 도메인은 요청 없이 성공합니다. Failure(또는 Uncertain)이면 명령을 보내지 않고 재조회도 하지 않으며, 결과 줄에 이유를 보여 줍니다. KeyNotPaired는 등록 상태를 notEnrolled로 바꾸고, KeyStoreError.Locked는 휴대폰 잠금 해제를 요청합니다.
  2. command는 정확히 한 번 호출합니다.
  3. Success는 "성공"을, Failure는 메시지와 함께 "실패"를, Uncertain은 메시지와 함께 "불확실"을 보여 주며 다시 보내지 않습니다.
  4. requery(vehicleStatus())는 명령 뒤에 항상 실행됩니다. Success 뒤에는 상태 카드를 갱신하고, Uncertain 뒤에는 매뉴얼이 요구하는 재조회입니다. 재조회가 실패하면 같은 결과 줄에 덧붙입니다.

대화상자를 확인하면 4단계 규칙을 다시 검사합니다. 더 이상 맞지 않거나 다른 호출이 실행 중이면 아무것도 보내지 않고 이유를 결과 줄에 남깁니다. Model X와 Cybertruck 버튼은 접혀 있는 "다른 차종" 섹션에 있습니다. 인포테인먼트 명령(공조, 충전, 경적, 조명)은 M5를 기다리므로 보이지 않습니다. 탭에는 상태 새로고침 버튼이 있는 상태 카드(잠금, 트렁크, 프렁크, 절전, 마지막으로 읽은 시각)와, 최신 줄이 맨 위에 오고 시각이 붙으며 VIN이 없는 결과 목록도 있습니다.

이 탭의 모든 라이브러리 호출은 탭 자체의 exclusive { }로 한 번에 하나씩 실행되며, 호출이 실행되는 동안 버튼은 꺼집니다. Android에서는 뷰 모델의 스코프에서 실행되므로 탭을 바꾸거나 휴대폰을 회전해도 취소되지 않습니다. Control 탭에는 별도의 가드가 있고, 라이브러리가 연결마다 VCSEC 명령을 직렬화하므로 두 탭에서 누른 것이 전송 중에 뒤섞이지 않습니다.

실차 체크리스트

  1. 새로 설치: 1단계가 "해야 함"으로 보입니다. 누르면 키가 만들어지고 1단계가 완료됩니다.
  2. VIN이 저장되어 있고 차가 근처에 있음: 연결하면 2단계가 완료되고, 등록 확인이 실행됩니다(checking, 새 키라면 이어서 notEnrolled).
  3. 3단계: 누르고, 콘솔에 키 카드를 올리고, 차 화면에서 승인합니다. 진행 줄이 나타나고 enrolled가 되며 4단계 버튼이 켜집니다.
  4. 잠금, 잠금 해제, 깨우기: 결과가 "성공"이고 상태 카드가 따라 바뀝니다.
  5. 트렁크 토글과 닫기, 확인 대화상자가 뜨는 프렁크.
  6. 키가 아직 등록된 상태에서 다시 설치: 연결 뒤 확인 결과가 다시 페어링하지 않고도 enrolled입니다.
  7. 차 화면에서 키를 삭제하고 명령을 누릅니다: 세션이 KeyNotPaired로 실패하고 3단계가 "해야 함"으로 돌아갑니다.
