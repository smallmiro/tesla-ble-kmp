## 공통 규칙 (모든 상세 계획에 적용)

- 각 작업은 브랜치 → Red → Green → Refactor → 커밋 → PR(CI Green + AI 리뷰) → rebase merge. `{{WORKFLOW_FILE}}` §5.
- 각 작업에 참고한 `{{MANUAL_DIR}}` 문서와 대응 Go 원본 경로를 표기한다(PR 템플릿 "원본 대응").
- 포팅한 파일 헤더: `// Ported from vehicle-command@a4b43c1 <원본 경로> (Apache-2.0)`.
- 골든 픽스처 비교는 **필드 단위**다. Go의 protobuf 인코더는 oneof 필드를 뒤에 놓는 등 필드 순서가 Wire와 달라 바이트 단위로는 같지 않다(`protocol.md`의 TX 예시에서 `uuid`(51)가 `payload`(10)보다 앞에 온다). 디코딩 후 필드를 비교하거나, 우리 인코딩을 다시 디코딩해 비교한다.
- 마일스톤이 끝나면 `{{HANDOFF_DIR}}`에 인계 노트를 쓰고 다음 상세 계획을 작성해 승인받는다.
