17. プラットフォームノート

Android や iOS のアプリで設定すべきこと、ライブラリがキーとセッションを保存する場所、知っておくべきいくつかのプラットフォーム固有の動作をまとめます。実機でまだ確認していない項目はその旨を記載しています。

サポート範囲

  • Android 12 (API 31) 以降、iOS 16 以降で、アプリが フォアグラウンド にある場合に対応します。バックグラウンドでの Bluetooth は対象外です。
  • JVM ターゲットはテストと実験用です。キーはメモリ上にあり、プロセスの終了とともに消えます。

Android

2 つの Bluetooth 権限を宣言し、実行時に要求してください。権限がないと、スキャンと接続は PermissionDenied を返します。ライブラリはサーバーを呼び出さないため、インターネット権限は不要です。

<uses-permission android:name="android.permission.BLUETOOTH_SCAN" android:usesPermissionFlags="neverForLocation" />
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
<uses-feature android:name="android.hardware.bluetooth_le" android:required="true" />
  • ライブラリは PlatformContext(context) で作成します。アプリケーションコンテキストを保持します。
  • 接続時、ライブラリは 517 の MTU を要求し、失敗した場合は 20 バイトのブロックにフォールバックします。
  • Keystore のエントリ名は teslable.key:<alias> と teslable.wrap:<alias> なので、アプリ自身のエントリと衝突しません。
キーファイルを自動バックアップから除外してください

ソフトウェアキーは files/teslable/keys/<alias>.enc として保存され、バックアップされることのない Keystore キーでラップされています。自動バックアップがラップ用のキーなしでこのファイルを復元すると、キーは破損していると判定されます。dataExtractionRules または fullBackupContent で files/teslable/keys/ を除外してください。サンプルアプリは単に android:allowBackup="false" を設定しています。files/teslable/sessions の保存済みセッションは失われても害はありませんが、除外しておく方がすっきりします。

iOS

  • Info.plist に NSBluetoothAlwaysUsageDescription を追加します。最初のスキャンで権限ダイアログが表示されます。ユーザーが拒否すると、呼び出しは PermissionDenied を返します。
  • ライブラリは PlatformContext() で作成します。
  • シミュレーターには Bluetooth がありません。スキャンと接続は実機の iPhone でのみ試せます。
  • iOS には MTU ネゴシエーションの API がないため、ライブラリはシステムが選んだ書き込み長を使います。応答キャラクタリスティックが通知 (notification) と指示 (indication) のどちらを使うかは、実車で確認中です (ADR-0003)。
  • Swift は SKIE を通して Kotlin を呼び出します。suspend 関数は async throws に、Flow は AsyncSequence になり、sealed 型は switch onEnum(of:) で扱えます。companion メンバーには .companion を通してアクセスします。

キーの保存

protection意味
SECURE_ENCLAVEiOS Secure Enclave。秘密鍵がチップの外に出ることはありません
STRONGBOXAndroid StrongBox セキュリティチップ
TEEAndroid Trusted Execution Environment
SOFTWAREエミュレーター、シミュレーター、またはハードウェアの試行がすべて失敗したデバイス
  • ソフトウェアキーは Android Keystore の AES キーでラップされるか、デバイスのロック解除中のみ読み取り可能でデバイスの外に出ない iOS キーチェーン項目として保存されます。
  • iOS では、Secure Enclave の検索失敗は「キーなし」ではなくエラーとして報告されるため、正常なキーが誤って上書きされることはありません。
  • 秘密鍵をエクスポートする API はありません。
破損したキーが自動で置き換えられることはありません

getOrCreate または get が stored key is corrupted 付きの PlatformFailure を返した場合は、ユーザーに知らせてから delete と getOrCreate を呼んでください。新しいキーは公開鍵が異なるため、車両に登録し直す 必要があります。黙って置き換えると、ユーザーは理由もわからないまま車両を制御できなくなります。

セッションキャッシュ

  • 保存済みセッションを使うと、次の接続でハンドシェイクを省略できます。保存先は Android では files/teslable/sessions/、iOS ではキーチェーン、JVM ではメモリです。TeslaBleConfig.sessionCache で独自の実装を渡すこともできます。
  • 名前は VIN のハッシュなので、VIN そのものは保存されません。
  • セッションは 1 つのキーに属します。キーが変わった後や、車両側の状態が進んでいる場合、古いセッションは次の接続で破棄されます。
  • キャッシュがない、または古くなっていてもエラーではありません。ライブラリは単に新しいセッションを開始します。

クロック

セッションの時間管理には単調クロックを使いますが、一部のプラットフォームではスマートフォンのスリープ中にこのクロックが止まります。長いスリープの後、保存済みセッションからの最初のコマンドが有効期限のフォールトで失敗することがあります。その場合、ライブラリは車両が返す新しいセッション情報を取り込んでリトライするため、アプリ側には何も見えません。

接続スロットとリンク切断

  • 車両が受け付ける Bluetooth 接続は 最大 3 つ です。スロットを空けるため、使い終わったら disconnect() を呼んでください。3 つすべてが使われていると、接続は MaxConnectionsExceeded を返します。
  • リンクが切れて connection が Disconnected になった場合でも、セッションキーを消去するため 必ず disconnect() を呼んでください。もう一度呼んでも害はありません。
  • 切断された Vehicle は再利用できません。TeslaBle.connect で接続し直してください。
