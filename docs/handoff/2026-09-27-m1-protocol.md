## 결정
- 시간은 `kotlin.time.TimeSource` 주입으로만 흐른다(`Reassembler`, `Signer`, `TestVerifier` 공통). 벽시계(`kotlin.time.Clock`, `System.currentTimeMillis`)는 어디서도 쓰지 않는다. M2 `:adapter-storage`의 세션 캐시만 `createdAt`(저장 시각)을 벽시계로 남기고, 불러올 때 `age: Duration = now - createdAt`으로 바꿔 `Signer.importSessionInfo`에 넘긴다. `age`가 음수면(벽시계가 뒤로 감) 캐시가 0으로 자르거나 항목을 버려야 한다 — `Signer.importSessionInfo`는 `age >= 0`을 요구해서 Go(미래의 `generatedAt`도 허용)보다 엄격하다.
- `Signer`/`TestVerifier` 연산 결과는 `SignerResult<T>`(`Ok<T>` / `Fault(fault: MessageFault_E, detail: String)`, Go `authentication.Error` 대응)다. 로그·재시도 판단용이며 앱에는 노출하지 않는다 — M2 Dispatcher가 `VehicleError`로 바꾼다.
- `TestVerifier`는 `:testing`에 있고 `personalization: ByteArray`를 받는다(`Vin`이 아니라 원시 바이트). Go `Verifier`가 운영 세션정보 검증(VIN 17자)과 Go 자체 테스트 벡터(`verifier_test.go TestGCMKnown`의 `testvin` 같은 임의 바이트) 양쪽에 쓰이므로, 타입을 `Vin`으로 좁히지 않고 원본처럼 바이트로 받는다. M2 `FakeVehicle`이 실제 VIN으로 감싼다.
- HMAC 인가(`AuthorizeHMAC`)는 포팅하지 않는다(D6, BLE 경로는 GCM 전용). `TestInvalidExpirationTime`은 그래서 `AuthorizeHMAC` 대신 `Signer.encrypt`로 같은 만료 경계를 검증한다.

## 막힌 점
없음(진행을 막는 것 기준). 다음은 M2 이후로 미룬 항목:
- 응답 counter 윈도우는 M2 `PendingRequest`(요청별 `SlidingWindow`)가 검사한다(`Signer.decrypt`는 counter만 돌려주고 재사용 검사는 하지 않는다).
- 세션정보 수신 시 4초 `AllowedLatency` 규칙과 challenge(uuid) 대응은 M2 Dispatcher 몫.
- 세션 캐시 `age` 계산과 음수 클램프(위 "결정" 참조) — M2 `:adapter-storage` 구현.
- Wire의 모르는 enum 값 처리(`unknownFields`)가 Go `default:` 분기가 있는 다른 곳(VCSEC `operationStatus`, Infotainment `actionStatus`)에도 필요 — M2/M4 계획에 테스트로 넣을 것. 같은 이유로, 모르는 fault·도메인을 실은 **암호화 응답**은 응답 AAD가 달라져 `INVALID_SIGNATURE`로 드롭된다(SDD §12) — M2에서 응답 메타데이터를 만들 때 `unknownFields`의 원시 값을 쓰도록 보완한다.
- `TestVerifier` 정리 항목(최종 리뷰에서 처리되지 않았으면): `copy()`가 payload oneof의 다른 멤버를 비우지 않음, `forceCounter`는 `UInt.MAX_VALUE`에서만 Go와 동일, 일부 테스트가 자기 일관성만 확인.
- `errors.md`의 "SKIE가 enum으로 노출" 문장은 `onEnum(of:)` 기반으로 M3에서 교정.
- `VcsecRejected` 문구는 Go의 GenericError≠NONE 분기(프로토 전체 문자열)를 재현하지 않음 — M4에서 VCSEC 응답을 해석할 때 재검토.
