3. Current Apps

What the two apps do as of 2026-10-24 (milestone M4). Both are the monitor app (4. Monitor App); the former single screen of each is its Control tab. The Key & Control tab (5. Key & Control Tab, SFR-018) is the short path: get a key, enroll it, press the control buttons.

Android

The monitor app (4. Monitor App, SFR-010 to SFR-018): five tabs and a foreground service. Build 0.3.0 (3); the unit tests pass and the real-device check is pending.

Gradle module :samples:android, package and application id dev.mirolab.teslable.sample, minSdk 31. MainActivity.kt holds the tabs and the permission requests and keeps the screen on while it is visible. MonitorService.kt and MonitorEngine.kt run the service, the connection, the events, the queries and the logs. SampleState.kt holds the Control tab state and runs every action through exclusive { }, so only one library call runs at a time. KeyControl.kt (pure step rules and command runner), KeyControlState.kt (tab state) and Enrollment.kt (pair and confirm, shared by both tabs) make up the Key & Control tab. The tabs are in ui/. Unit tests (including KeyControlTest) are in src/test/ and run with ./gradlew :samples:android:testDebugUnitTest.

iOS

The monitor app (4. Monitor App, SFR-010 to SFR-018): five tabs and one monitor object for the app's lifetime. Build 0.5.0 (12); the unit tests pass and the real-device check is pending.

XcodeGen project (project.yml) with the schemes TeslableSample (simulator) and TeslableSampleDevice (phone). project.yml sets UIBackgroundModes: [bluetooth-central], UIFileSharingEnabled and LSSupportsOpeningDocumentsInPlace in Info.plist. MonitorModel.swift and MonitorEngine.swift run the connection, the events, the queries and the logs; ConnectionLoop.swift, LogLine.swift, LogWriter.swift, VinMask.swift, LiveState.swift and VehicleMapping.swift are the pieces behind them (see iOS implementation). SampleModel.swift holds the Control tab state and BleClient, and runs every action through exclusive { }, so only one library call runs at a time. KeyControl.swift (pure step rules and command runner) and KeyControlModel.swift (tab state) make up the Key & Control tab. The tabs are in ContentView.swift and Views/. Swift unit tests are in Tests/ (VinMaskTests, LogWriterTests, ConnectionLoopTests, LiveStateTests, TimeoutsTests, KeyControlTests).
